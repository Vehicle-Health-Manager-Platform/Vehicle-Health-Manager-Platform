# R6b2 ASR/图文任务HTTP证据（2026-10-28）

承接PR255/6d0cc3b，分支codex/recognition-job-http-evidence。按用户授权规划后实施，本批完成六个任务接口四类HTTP证据并回归上批VIN/行驶证两项。最后两类里程仍按计划待补，不合并或部署。

## 实现

现场记录器保持原POST调用兼容，新增显式method、规范操作与幂等键参数，真实发送GET查询、POST创建/取消。ASR和图文各20次具名请求：创建正常/同键重放/无同意/非法查询/匿名/错误角色/跨车主；查询正常/不存在边界/非法查询/匿名/错误角色/跨车主；取消正常/同键重放/多余正文/非法查询/匿名/错误角色/跨车主。

从真实创建响应提取job_id，SQL复查owner/vehicle/material和CANCELLED，取消后result为空，任务流程不产生车辆/档案新增。证据仅保存摘要、状态、角色、操作与有界绑定，不保存JWT/音频/文档正文。审计逐例核对方法/路径与绑定，要求六接口分别四类齐全，拒绝未知/不安全job_id、缺少接口、错误方法、SQL不符、失败/错误/跳过JUnit和旧源码。

独立运行器默认执行四类，正常构建/清旧证据，测试结束后核查四个现场MySQL容器均已移除；check-only仅复核已有当前源码证据。8项审计测试沿用现有CI发现，不增加正式服务凭据。

## 已定位并修复的测试问题

首轮新增场景误将创建回执当作任务详情，断言创建响应必须包含state=QUEUED；实际创建契约只含标识与归属。断言提前失败留下合成材料93的排队任务，随后两个既有单次worker旅程取到该任务，产生连带失败。改为核验创建回执的vehicle/material绑定，经GET断言QUEUED；增加AfterEach仅清理材料93的遗留QUEUED夹具，防止失败污染其他场景。正常取消后还核对该材料恰好一个任务。未修改业务接口或放松既有成功/权限断言。

首轮失败不计通过，最终四类全部重新执行；默认回归也按修复后源码重新运行。该问题是新增测试对契约的误用及夹具隔离缺陷，不表述为产品业务缺陷。

最终四个新库场景共22执行项零失败/错误/跳过，53次显式清单请求覆盖八接口；四库移除、源码稳定。ASR/图文各20次，共40次覆盖新增六接口，其余13次回归VIN/行驶证。8项审计测试及修复后默认12组全部通过：Python595、小程序1237、OCR80通过/1平台跳过、ASR40、图文26、嵌入27与构建/契约/交接门禁。未重跑全部后端。
