# R7c3 第一步执行：诊断本机草稿与原键恢复

状态：本地完成，整个 R7 尚未完成，无 GitHub 上传。本步设计见[设计与顺序](R7C3_RECOVERY_DESIGN.md)。

## 已实现

- 车主和独立运营内存会话保留服务器登录响应账号 ID；同令牌手机号绑定保留 ID，切号或退出清理，不保存令牌到设备。
- 车主新建/追加、当前获派运营人员答复及双方关闭，按角色、账号、业务范围保存未决请求。写请求先落盘再发出；原动作、正文、来源版本和 UUID 不可变。恢复后不自动重发。
- 草稿需用户主动保存或恢复，最长七天；只含输入文字、车辆选择。恢复不沿用用途同意，车辆须重新出现在本人当前车辆列表中才能选中。未决请求不随草稿期限过期；保存未决请求不延长草稿期限。
- 重启或页面重建后，先从服务器读取本页当前权限，再提示原键重试或草稿恢复。账号、角色、会话业务隔离；迟到响应不能填回旧页面。
- 401 隐藏本地内容并要求重新登录，保留未知请求以便同账号重新认证后恢复；403/404 清理当前失权范围。权限读取网络失败不能沿用先前读取授权。
- 同步存储经过现有 api-runtime 显式透传，正确传播配额/能力失败。发出请求前存储失败阻止提交；服务器成功但本机清理失败明确提示并保留原键，阻止新建变更。
- 同账号多个页面不能覆盖别页未决请求；迟到成功清理不能删除另一条后续请求。本机严格校验结构、动作与业务 ID，损坏数据拒绝恢复/发送。

## 范围和限制

恢复数据只在当前设备；清理应用存储会删除本机恢复信息，仍须从服务器本人记录核对实际结果。草稿/输入正文属于本机明文存储，页面明确提示共享设备使用后清除，且不自动保存草稿。存储损坏时保留数据并阻止发送，需先核对服务器实际记录，再通过设备应用存储清理恢复；不自动丢弃未知请求。

不自动持久化服务器档案、照片或私有签名地址。运营政策配置、管理分配、订单档案授权、已读目前仍采用各自已有流程，不宣称都已具备跨重启恢复；整 R7 销项时逐项核对必要性。已有后端永久创建意图、原键回执及版本 CAS 仍是去重事实来源，本机记录不授予业务权限。
