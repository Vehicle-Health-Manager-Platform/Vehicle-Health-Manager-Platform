# R5a 券库存与领取设计

## 范围和授权

依据 R5 启动规划和用户“规划好下一步，然后开始实施”的授权，本次完成 R5a 后将代码、迁移、测试、文档一起上传。订单抵扣、预约冻结、服务核销及佣金规则属于 R5b；供应商、正式身份/资金、真机及发布属于 R9。

## 方案与规则

直接复用旧 coupon 表无法证明历史权益来源；全部替换又会破坏旧订单引用。采用增量来源表和发布版本快照：保留 coupon/user_coupon，只有带新发行记录的券具有可验证来源，历史记录显示来源未知。

- 商户店长创建草稿，提供券名称、DISCOUNT 或 SERVICE 类型、精确标准项目、金额/门槛、有限库存、生效和截止 UTC 时间。SERVICE 金额与门槛均为零；DISCOUNT 金额为正且门槛不小于金额。库存不预填生产数值。
- 仅发行门店和指定在售标准项目适用；发行成本由该门店承担。草稿允许按版本更新；发布后权益、库存总量、有效期冻结，需改变条件则创建新券。发布状态 PUBLISHED 可停止为 STOPPED，不能重新开放。停止阻止新领取，已领权益保留快照。
- 每位车主每个模板终身只能领取一次；唯一约束兜底，换幂等键不能多领。领取必须在有效期内、发行门店和项目有效且在售、库存充足。单券锁串行化库存扣减，发行记录、user_coupon、库存流水、审计和幂等回执同事务提交。
- 运营池仅为曝光选择，不改变权益、库存或承担主体。独立 can_coupon 权限默认关闭；目录/审核权限不能代替。运营上下架按版本控制，商户券发布不等于自动进入运营池。车主既可查看指定门店可领券，也可查看运营已选券。
- 重放先检查当前身份、权限、所属资源和领取来源有效性；不得把旧回执当作当前页面状态，前端成功后重新读取。领取本身已经发生的库存耗尽/个人已领不能否定同键成功重试。
- 我的券返回冻结权益、实际状态、到期时间和来源资格。到期由服务器时间判定，不后台随意改历史状态；未开始、到期、发行方失效、未知来源均明确展示。首页显示已有券的实际截止时间，不虚构临期天数。

## 接口与页面

商户：分页列表、创建草稿、按版本修改、发布/停止；运营：分页管理列表和版本化选入/移出；车主：分页可领券（指定门店或运营池）、领取、我的券。

页面沿用现有角色会话和样式：商户管理券、运营池、领券和我的券，增加个人中心/首页/门店入口。所有列表有空态、加载失败和翻页；未实现抵扣/核销前没有操作按钮。隐藏、账户切换、筛选切换清除私有数据及过期响应。失败重试保留原请求与幂等键。

## 验证和交付

真实 MySQL：最后一张争抢、同人并发、不同键限领、同键重试与不同正文拒绝、失效来源/跨店/权限撤销、版本竞争、历史来源未知、审计失败整体回滚。HTTP：角色、查询和严格正文、UUID、no-store、未配置数据库拒绝。前端：协议校验、失败重试、账户/隐藏后响应丢弃。迁移重复执行；完整现有测试、微信/H5 构建及 GitHub 六项 CI。

## 自检

发布冻结与停止后的既领权益语义一致；只在新领取时检查库存，成功重试不重复扣减。运营选择不授予商户管理权限。无缺省生产发券政策，无待实现交易按钮。R5b 的优惠交易/佣金决策未混入 R5a。
