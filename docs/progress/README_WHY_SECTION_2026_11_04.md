# 门面补「为什么做这个项目」

日期：2026-11-04｜分支：`docs/readme-why-section`｜基线：`main` `b216578`

## 背景

用户要求在英文与中文 README 里各自加一节「Why this project」/「为什么做这个项目」。

改之前两份 README 的开头已经有一句问题陈述（"今天车辆历史散落在纸质单据、聊天记录和各家门店的系统里……
这个项目把它收进一套数据模型"）。直接再叠一节就等于同一件事说两遍，因此把原来那两行**整段挪进新章节**并
展开，开场只留"这是什么 + 八步链路"，其余不动。

## 结构

新章节插在泳道图说明之后、`## 能做什么 / What it does` 之前。第一屏仍然是"定位 + 两张图"，
往下滚动一格是"为什么"，再往下才是功能表。

内容是一张**问题 → 本仓库的做法**对照表（6 行），加一段收束：

| 今天的问题 | 本仓库的做法 | 证据 |
| --- | --- | --- |
| 记录归写它的人所有，换一家门店就从零开始 | 订单与档案一套模型，三角色都往里写，记录跟着车走 | 订单 / 档案单一模型（`docs/STRUCTURE.md`） |
| 交接靠口头 | 每次交接是可追人的记录：车主确认或异议、技师本人签质检、商家凭车主六位码核销 | `OWNER.md:18`、`TECHNICIAN.md:10`、`ORDER_REDEMPTION.md:7` |
| 争议没有可比基线 | 接车 / 防护 / 过程 / 故障件 / 完工五类照片按阶段留证，取车页对比接车与完工，缺证据显示缺失不回填 | `MERCHANT.md:9,12`、`TECHNICIAN.md:10`、`OWNER.md:18` |
| 「共享历史」全有或全无 | 档案授权逐条授予、可逐条撤销；未授权的门店读不到 | `SERVICE_WORKSPACE.md:14-16`、`OrderArchiveGrants.java:54`（无 ACTIVE 授权时抛 404） |
| 车可能在车主不知情下被放行 | 核销必须用到车主手里的六位码 | `ORDER_REDEMPTION.md:7,23`（错码 422/42200） |
| 假数据的桩掩盖真实缺口 | 可选能力开关控制、默认关闭，关闭返回 `503` 而非编造数据 | `docs/operations/AI_CHAT_RUNBOOK.md:12,72` |

表里没有写"提升效率""降低成本"这类无法验证的话，也没有把尚未验证的能力写进"为什么"。
