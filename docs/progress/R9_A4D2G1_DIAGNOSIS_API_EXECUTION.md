# R9 A4d-2g1 人工诊断、处理队列与通知验收

## 设计与执行顺序

沿用已授权的独立功能优先顺序。本阶段以已有生产接口为入口，接入真实 Spring HTTP、全迁移 MySQL 和真实定时通知投递；采用合成身份和月度资格夹具，不连接微信或 AI。

1. 核对服务政策、月度资格、队列和正文的独立权限。
2. 生成可重复执行的 20 个诊断接口用例：政策创建/修改/发布/停用，车主提交/补充/关闭，运营分派/转派/答复/关闭，通知查询/已读。
3. 在全新数据库运行正常、边界、错误、越权四类场景，审计实际请求正文、角色、版本和幂等键；检查事件、消息、通知与审计的一致性。
4. 增加证据防伪回归和 CI 门禁，整理脱敏报告并上传依赖 PR179 的草稿 PR。

## 验收要求

- 不可用、暂停、无资格、错误车辆或未同意均不能提交；停用政策和关闭工单不能被旧回执恢复。
- 管理者能读队列但不能读正文；处理者必须是当前指派者，转派立即撤销旧处理者正文和消息权限。
- 重复写入不增加事件、正文或通知；站内通知只暴露元数据，已读时间稳定且跨车主不可访问。
- 原始响应和 JWT 仅在忽略的 `.cache`；公开报告不包含身份凭证和诊断正文。

已完成本阶段本地实现与验证。完整 API 业务验收、性能延迟达标、真实外部供应商和真机仍未完成。
