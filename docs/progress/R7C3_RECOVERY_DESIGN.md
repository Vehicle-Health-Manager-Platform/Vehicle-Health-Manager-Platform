# R7c3 第一步：诊断草稿与原键恢复

沿用已授权的 R7 账号与业务隔离、持久草稿、不可变请求同键恢复方案。本步先完成车主新建、车主追加与当前获派运营人员答复/关闭；运营政策创建不套用长期重试，其他业务消息留作下一步。

## 实现顺序

1. 登录响应保留经现有协议校验的账号 ID，仅在内存中保存会话。手机号绑定更新保留同令牌账号 ID。
2. 本机存储按身份、账号 ID、业务范围隔离。草稿需主动保存；恢复前完成本页服务器读取与权限复核。仅保存文字和车辆选择，不保存用途同意，恢复后重新确认用途。存储不含令牌、密码、私有图片地址或服务器档案。
3. 确认提交后，在发网络请求前持久化原始动作、业务 ID、正文及 UUID。存储失败则阻止发送。重新进入只提示原键重试，不自动提交，不产生新键。原请求与可编辑草稿独立，不能以编辑后的正文覆盖未知请求。
4. 权限失败不展示或恢复本地内容；清除已失权业务的本地条目。网络失败保留原请求。成功后删除；若清理失败，阻止新提交并允许重试原键，服务器长期新建意图和版本 CAS 仍防重复。客户端存储属于当前设备，清理设备数据会丢失恢复信息，不能充当业务事实。
5. 草稿最长保留七天；未知请求不因时间自动删除。当前请求成功或明确拒绝后才清除，除非用户主动清除本机草稿。跨账号、角色、会话业务与迟到响应均隔离。

## 验收

覆盖重新创建页面/流程后恢复、换账号不读取、权限读取失败不恢复、不可变正文与键、持久化失败不发出请求、成功清理失败不重复新建、草稿过期/损坏/无效结构。运行全套前端与微信/H5构建。本步无新增接口/迁移，不表示 R7c3 或整个 R7 完成。

## 后续
