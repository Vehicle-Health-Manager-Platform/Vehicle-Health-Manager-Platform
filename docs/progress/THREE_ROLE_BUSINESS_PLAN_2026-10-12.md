## 1. 当前起点与原则

业务起点为 GitHub `main` 的 `bd10ae4`：R1 入驻/员工/门店/标准目录、R2 交易恢复/双方同意全额退款/佣金账单、R3a1 录车手动回退、R3c1 接车扫码八图、R3c2 本人档案 PDF 已实现并合并。README 演示图集 PR #120 是独立文档改动，不阻塞本规划。

继续只做车主、门店、技师微信小程序及必要后端。必要管理能力用已有的小程序运营受限入口；PC 运营后台不做。沿用 R3–R9 编号，避免重排历史阶段。优先完成可独立实施的 P0 主流程，外部 OCR/VIN、正式短信/身份/资金最终接入；外部服务未开通时保留缺项并推进下一可实施单元。

每个业务单元先冻结中文规格和接口/权限/状态，再实施后端与微信页面，补数据库/HTTP/原生流程证据，更新文档并上传独立 GitHub PR。上传不自动代表合并、生产发布或真机验收。阶段中的数值、资格和授权规则在具体规格中确定，不把 UI 示例当作业务政策。

## 3. R3c3 已冻结范围与分段记录

用户已确认登录车主持链接只读查看，无逐人审批；有效期1/24/168小时，固定快照不含私有文本、标识、图片、签字或PDF。规格独立提交并上传后，与后端一并交付#122；微信#123，收口文档独立上传。以下保留最初拆分要求，具体字段与事务以已确认规格/API为准，不再重复请求相同授权。

### 3.1 规格阶段

先核对 R3c2 报告投影及现有身份/文件访问服务，形成独立共享授权契约：

1. 选择一辆本人车辆及日期范围；明确可共享字段、是否含私有照片/标识、是否允许接收人下载。
2. 确定接收方式和身份要求，优先采用小程序内受控查看，分享入口不能直接暴露本人 PDF 下载地址或鉴权令牌。
3. 确定有效期上限、接收资格、授权状态和撤销/过期/车辆归属变化处理。
4. 确定访问审计与最小投影；区分查看权和导出权，不把报告分享当作门店/技师自动读全档案授权。
5. 明确撤销语义：后续服务器访问立即拒绝；已经下载至设备的副本无法保证远程删除。

以上为下一阶段需冻结的具体设计项，本次规划没有预设匿名访问、永久有效、公开图片或固定奖励政策。

### 3.2 后端阶段

独立迁移和授权记录，建立创建/本人列表/撤销/受控读取契约；随机分享凭据避免可枚举 ID，服务端每次复核有效期、授权状态和车辆归属。验证越权、撤销与访问竞争、重复创建/撤销、事务失败及审计一致性。复用现有报告快照，不把授权映射保存成公开文件直链。

### 3.3 微信小程序阶段

车主档案页新增分享配置、明确授权、授权列表/撤销；接收页处理登录、权限、过期、撤销及加载失败。切换账号/车辆或页面隐藏后忽略迟到结果；原生分享失败/取消给出正确状态。普通 HTTPS 与云托管请求都按已有传输边界实现。

### 3.4 验收与 GitHub 阶段

验证创建→接收→查看→撤销→再次访问被拒绝，覆盖过期、他人车辆、链接猜测、账号切换、资源归属变化及下载限制。记录实际数据库/HTTP 与原生流程证据，补中文契约、迁移、验收和进度文档；按规格、后端、微信页面、收口分别上传 PR。真机分享接收与生产身份最终另验。
