# A4d43 隔离OCR共享网关与微信旅程

2026-10-25，基线430ba21 / 草稿PR233，分支codex/r9-a4d43-isolated-mileage。仅微信小程序及共享后端验收接线，生产网关默认关闭，未合并部署。

## 实现

原运行器的预检及ObservedEngine直接在父进程初始化模型，不能证明A4d42硬截止路径。现改用isolated_check进行单独两次私有HTTP模型预检并关闭，再为业务旅程创建生产ProcessRecognizer。父进程ObservedWorker原样委托请求、原样返回结果，仅记录请求/完成/失败次数、独立进程身份与预热进程复用；不解析JSON或解码图片，不返回替身识别结果。

网关模式恰好1次worker请求，微信模式恰好3次（基础1+原生2），拒绝请求不得到达worker。计数代表worker请求，并非直接观测模型内部调用。严格检查READY、8秒推理/30秒启动截止、资源profile及零失败；关闭时核对worker CLOSED/无PID、监督线程终止、HTTP服务停止、私有配置与自有Maven容器移除。

复用原12项共享网关、80项材料/工作台，以及可选9项微信开发者工具和候选/取消/带入三个SQL检查点；没有新增产品页面、契约或客户端密钥。

微信原生最终整轮通过：9项页面检查、候选/取消/带入三个SQL节点零档案，最终原保存按钮仅产生1条里程123456且引用本人图片的档案，登记里程仍100，签名下载内容相同。UI上传1/识别2/保存1，基础1+原生2合计worker3次，零失败且复用同一独立预热进程；每次预检真实模型私有HTTP两次另计。80项材料/工作台与12项网关仍全部通过，来源稳定、本人会话及系统mock清除、页面引用释放、代理/服务/worker/监督线程关闭和数据库/存储/容器清理通过。仅关闭自有隔离微信项目并删除测试网络私有配置，系统临时下载由微信管理，不声称物理删除。

非原生入口也已按最终源码完整复验通过：80+12项HTTP、worker1次、零失败且复用独立预热进程、来源稳定和全部资源清理。两种模式报告均核对同一最终源码摘要；最终JUnit均1项、0失败/错误/跳过。见[脱敏报告](../testing/reports/R9_A4D43_ISOLATED_MILEAGE_2026_10_25.json)。实际核对无运行容器、OCR自有worker为0，两轮均无私有控制JSON/curl配置/头文件残留。

前两轮原生在首个业务操作前出现App.callWxMethod错误，上传/识别/保存均0，失败轮次不计通过且资源已清理。独立探针确认下载及身份安装成功，reLaunch实际返回pageNotFound属性读取错误；仅重开项目不能修复。同一包/同一路由在SDK3.17.4失败，隔离项目固定3.17.2后reLaunch:ok，故增加运行时SDK证据及缺失/版本变化拒绝。未改变普通包SDK配置，也不将本机对照推断为所有3.17.4环境必然失败。官方接口依据见[微信自动化文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/miniprogram.html)。

所有身份/图片/ClamAV签名为合成，微信选图及picker/switch/input事件有工具辅助。不将其扩大成真实仪表准确率、手机相机/权限、正式微信身份、网关在途worker故障交互或Linux产品容器验收；A4d42故障回归仍只证明明确替身引擎的真实进程/HTTP行为。317/353历史证据、36套/36结论与全API验收false保持。
