## 已完成操作计划：本地车辆与档案真实业务联调

1. 从最新 `main` 建立独立分支，确认健康接口 200/UP、匿名车辆接口 401/40100及 V001–V005 结构；记录源码提交和本机容器版本。
2. 在隔离测试库准备标识清楚的最小四级车型和两辆测试车。种子限定测试用途，不写入生产库；共享证据使用脱敏车牌/VIN和记录标题。
3. 保持 AppSecret/JWT/数据库密码在后端私有环境。小程序配置本机后端地址，重新构建并导入当前产物，取得真实车主会话。
4. 完成车辆录入与查询、两车切换、无图手动档案保存、列表分页、首页总数和最近记录；确认页面数据与落库一致。
5. 验证失败重试不重复写入、修改正文换幂等键、成功审计与业务同事务；以另一车主验证跨用户车辆/档案访问被拒。尚未拿到第二个真实微信测试身份时记录该实操项待验收，保留现有自动化隔离证据。
6. 更新执行记录，附环境版本与脱敏结果。若发现缺陷，同步修复相关页面/接口并运行针对性测试，推送 PR，完整 CI 通过后再合并；完成后进入私有图片联调。

## 本机已执行计划：私有图片与拍照录入联调

1. 在隔离 Docker 项目建立私有 MinIO 桶和独立账号，启用 ClamAV；保留现有数据库，私有参数不入库。
2. 核对官方病毒库更新与扫描新鲜度，用真实干净图片验证上传为本人 CLEAN、失败补偿和原图同键重试；合成病毒测试不代替官方库验收。
3. 验证图片归档、本人预览、他人拒绝、短时签名到期与重新获取；本机 HTTP 结果独立记录，完整微信图片须可达 HTTPS 地址。

## 功能开发后执行：可信 HTTPS 与微信实际图片/真机

2026-10-06 已完成本机资源核对，PR #21 合并后主分支 CI 六项通过；用户选择先检查并准备部署方案。当前没有已核实的公网入口，详见[部署方案与设备矩阵](../superpowers/specs/2026-10-06-https-device-design.md)。先确认部署路径和环境资源，再交付对应模板并执行实际验收。

1. 核对已有测试服务器、域名/证书、微信后台权限和可用 iOS/Android 设备。只收集非敏感入口与能力信息，私有参数由环境保管。
2. 优先复用可管理的 HTTPS 测试入口，为后端和私有 S3 签名分别配置手机可达地址；若选择微信云托管，先明确现有 HTTP 上传/签名适配范围。回环自签证书不作为正式入口。
3. 用只读预检与实际设备验证网络、真实登录，再走原生相机拍摄、权限/取消、图片上传、归档、预览与签名到期重试。记录版本、设备及脱敏结果。
4. 核对当前测试号/主体的手机号能力，具备时完成授权绑定、刷新及退出撤销；另一真实车主复核图片/车辆隔离。能力未具备时独立保留待验收项。
5. 如发现缺陷，修复并用独立 PR/完整 CI 交付；不以 H5 合成选图或本机自签 HTTPS 代替微信相机与真机证据。

## 网络与外部条件

现在可继续本机模拟器开发，无需先购买域名。手机局域网调试须使用手机可达地址和受控调试设置；正式自建后端使用备案 HTTPS 通讯域名。微信云托管可通过指定接口免配通讯域名，但需评估现有 HTTP 与图片签名流程的适配，再决定迁移。详见[网络环境说明](../operations/MINIAPP_NETWORK_ENVIRONMENTS.md)。

现有 [HTTPS 只读预检脚本](../../scripts/check_auth_readiness.py)适用于有证书的部署入口，不接受本机 HTTP；本机冒烟结果与公网预检分别记录。手机号能力、短信、生产车型数据、服务器与存储的待办见[依赖清单](S0_DEPENDENCIES.md)。
