## 下一项的操作计划：本地车辆与档案真实业务联调

1. 从最新 `main` 建立独立分支，确认健康接口 200/UP、匿名车辆接口 401/40100及 V001–V005 结构；记录源码提交和本机容器版本。
2. 在隔离测试库准备标识清楚的最小四级车型和两辆测试车。种子限定测试用途，不写入生产库；共享证据使用脱敏车牌/VIN和记录标题。
3. 保持 AppSecret/JWT/数据库密码在后端私有环境。小程序配置本机后端地址，重新构建并导入当前产物，取得真实车主会话。
4. 完成车辆录入与查询、两车切换、无图手动档案保存、列表分页、首页总数和最近记录；确认页面数据与落库一致。
5. 验证失败重试不重复写入、修改正文换幂等键、成功审计与业务同事务；以另一车主验证跨用户车辆/档案访问被拒。尚未拿到第二个真实微信测试身份时记录该实操项待验收，保留现有自动化隔离证据。
6. 更新执行记录，附环境版本与脱敏结果。若发现缺陷，同步修复相关页面/接口并运行针对性测试，推送 PR，完整 CI 通过后再合并；完成后进入私有图片联调。

## 网络与外部条件

现在可继续本机模拟器开发，无需先购买域名。手机局域网调试须使用手机可达地址和受控调试设置；正式自建后端使用备案 HTTPS 通讯域名。微信云托管可通过指定接口免配通讯域名，但需评估现有 HTTP 与图片签名流程的适配，再决定迁移。详见[网络环境说明](../operations/MINIAPP_NETWORK_ENVIRONMENTS.md)。

现有 [HTTPS 只读预检脚本](../../scripts/check_auth_readiness.py)适用于有证书的部署入口，不接受本机 HTTP；本机冒烟结果与公网预检分别记录。手机号能力、短信、生产车型数据、服务器与存储的待办见[依赖清单](S0_DEPENDENCIES.md)。
