# R7c2 非实时人工诊断下一步

用户2026-10-15已确认：独立授权的运营诊断人员处理；运营配置可受理/离线留言/暂停受理及来源说明；车主提交时重验当月资格，仅共享主动提交文字和车型，历史档案另行授权。该决定继续遵守整R7完成后才上传代码、迁移、测试、文档。

## 实施顺序

1. 增加独立诊断运营权限，默认关闭且不继承邀请、目录或审核权限。配置有效期、版本、来源说明及受理状态，未配置UNKNOWN且不受理。可受理仍是异步服务，不承诺实时响应；离线可提交留言；暂停拒绝新提交。
2. 车主明确选择本人有效车辆、用途确认和本次文字；在受理事务中锁定当前资格政策、配置及必要来源，再按提交时点重算北京月份、有效新客数和政策窗口。保存资格/配置/车型快照及来源版本以便复算；不得沿用AI页旧资格或假设邀请奖励已发即有资格。
3. 有独立权限的运营人员按明确分配处理；采用当前会话、权限、分配人和状态/版本复核，撤权或转派拒绝后续读取/回复。区分待处理、处理中、已回复、已关闭；回复与关闭有审计及幂等。车主可在失去新提交资格后读取本人既有会话，避免把跨月资格失效当成删除历史答复。
4. 诊断只共享本次文字和车型。订单历史档案授权不自动沿用到诊断；本步不默认开放图片或整车档案。若后续需要档案附件，必须单独冻结诊断用途的逐条授权契约。
5. 同步R6资格投影service_available：只有当前资格达标且诊断配置允许受理/离线留言时才开放真实入口，不以ELIGIBLE直接推断服务已开放。车主入口接入既有AI页，明确三态和非实时说明；运营在小程序受限入口配置、分配、回复。事件与消息只传最小提示，读取仍核对诊断会话当前归属。诊断不使用订单通知表中的order_id伪装工单来源。
6. 与R7c3衔接账号/用途/会话隔离的草稿和不可变请求键持久恢复；未决提交不允许编辑后复用旧键，明确冲突重新读取确认。

## 验收

未配置/未授权默认关闭；离线可留言/暂停拒绝；R6跨月、政策停用、锁等待越界和会话撤销竞态；分配/转派/回复版本竞争；审计与事件原子；不同运营/车主隔离；提交结果丢失重试唯一；前端草稿/切号/迟到/重新进入与构建。
