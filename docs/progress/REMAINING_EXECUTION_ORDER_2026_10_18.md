## 1. 排序原则和范围

采用“按依赖拆分一个功能”的方式：先做录音、附件、确认页、权限、恢复和适配契约，后接真实识别；先完善已有资金状态机的必要测试与恢复，后接正式支付。单纯把整个功能都放到最后会遗漏可独立完成的部分；先连供应商则会使业务开发等待账号、密钥和环境。

“外部接口”指供应商识别、短信、微信服务端、正式支付、消息投递、嵌入服务等真实渠道。仓库自身前后端、本地 MySQL/对象存储/扫描设施属于本地验证环境；小程序录音和文件选择属于可先开发的平台能力，其真实系统行为在真机阶段单独验收。

不恢复 PC 后台或扩大到商城、实时客服等排除范围。正式 H5 产品仍沿用此前范围决定。正式资料许可、生产账号、凭据、域名和设备可在开发期间准备，但真实渠道编码与联调排在 A 段之后。缺少某个外部条件时跳到其他已具备条件的 B 段单元，保留该项缺口，不阻塞独立任务。

### A1：统一剩余范围和录入详细规格（第一执行单元）

1. 统一当前进度、下一步入口及 UI 文档中的历史状态提示，保留原始基线和历史记录；明确 F02/F03/F05/F14 的具体缺项。
2. 细化录音、拍照/文件附件、识别候选、人工修正、确认入库及失败恢复的规格；先检查现有私有文件链路、档案表单和 AI 输入限制，确定复用点。
3. 将“输入已采集”“附件已上传”“识别已成功”“用户已确认保存”“正式渠道已验收”分别建模，避免占位按钮或上传成功被显示为识别完成。
4. 明确录音/文件格式、大小与时长上限、缓存期限、用途授权、来源和错误码；在该单元规格中给出具体默认值后再实现，不把选择推到编码过程中。

完成标准：中文规格、分步任务、接口和必要迁移清单齐全；标明哪些无需第三方、哪些仅能在 B 段验收；没有重复建设已有的积分、券、派工或社区能力。

### A2：语音与 AI 附件的本地采集流程

1. 档案与 AI 入口补录音开始/结束/取消、时长反馈、重录、授权拒绝和不支持提示；封装原生录音接口，处理页面隐藏和账号切换。
2. 补 AI 图片/文件选择、类型与大小校验、预览/移除及上传重试；复用私有上传和扫描机制，新增媒体类型单独校验，不能仅放宽现有图片白名单。
3. 明确附件与当前账号、车辆和本次提问/录入的归属；退出、切号和迟到回调不得串入其他会话。跨页系统选择器返回时不得误丢本次合法输入。
4. 提供文字输入和手动填写回退。没有 ASR/OCR/多模态适配时显示服务未开通，不自动发给当前文本 AI，不虚构转写或图片理解结果。

完成标准：页面真实接入采集封装，本地前后端可验证受控附件及归属、失败重试和清理；离线替身只验证协议；录音真机、转写效果和 AI 多模态理解不计本段完成。

### A3：识别候选、人工确认与适配边界

1. 复用现有手动表单，补行驶证、VIN、仪表盘、档案图片及语音文本的候选展示与修改确认；按业务场景拆输入，不构建无实际用途的通用识别平台。
2. 候选带来源和状态；未经确认不修改车型、车辆里程、档案或健康读数。识别失败、低可信或不支持时可回退手填。
3. 补取消、超时、迟到结果、并发提交、重复确认和账号隔离；写入继续使用既有权限、幂等和事务边界。
4. 设计可替换的识别适配契约及本地契约测试，覆盖成功、空结果、格式错误、超时、供应商不可用。合成结果仅进入隔离测试，不做正式数据种子。
5. 小程序入口按实际能力开放：未接入的功能保持明确不可用或手动回退，不能将只返回 501 的服务标为识别完成。

完成标准：本地候选→修正→确认→入库流程和异常测试通过；记录“业务集成可测试，真实识别未完成”。若选择自托管 OCR/ASR，模型来源、安装资源和准确率仍在 B2 单独验证。

### A4：本地质量门禁与现有业务收口

1. 为本轮变更运行相关后端、数据库/HTTP 和小程序测试与构建；阶段收口再做完整回归，避免无变更反复跑全量。
2. 增加核心业务覆盖率度量，依据原文验证至少 70%，范围写明券、邀请、考核、里程及相关关键状态流；覆盖不足时补有实际风险意义的测试。
3. 补可复跑的隔离端到端场景：车主管车/问诊准备、预约到接车施工核销归档、商家申请到审核开通。使用测试资金时报告明确标注。
4. 建立本地性能脚本与数据准备：核心读 P95 < 300ms/P99 < 800ms、写 P95 < 500ms，首页/商家列表/订单创建各 500 并发、错误率 < 0.1%。隔离测试库，记录硬件、数据量、预热、并发方式及结果；不把真实 AI/微信延迟混入本地核心接口成绩。
5. 检查权限矩阵、上传、限流、脱敏、撤销与重放；403/404 按实际安全契约统一验收预期。补本地备份恢复、迁移升级和回滚演练，保护已有数据。

完成标准：保留实际执行报告；失败明确修复或记录阻碍。缺 Docker/模型/扫描规则等条件的项目标为未执行，继续其他独立工作；本地性能与安全结果不代替生产复验。

### A5：交付资料和外部接入准备

1. 补车主、店长/店员、技师的完整操作手册，复用已有专项指南，说明未接正式渠道时的界面状态。
2. 整理版本对应的功能验收矩阵、页面/入口清单、API、SQL 升级、配置项、部署、监控、备份和回滚步骤。
3. 建立统一外部依赖清单：用途、现有适配程度、账号/主体、凭据项、网络/域名、许可、测试条件、验收案例和关闭方式；只写变量名，凭据留在私有配置。
4. 保留完整待验列表：正式支付退款、识别效果、真实身份、新客奖励、知识检索、官方通知与真机等不能因文档或模拟测试完成而销项。

完成标准：A1–A4 每项均有代码/测试/报告或明确未执行原因；当前软件范围与 B 段依赖对应清楚，下一步接入无需重做业务页面。

## 3. R9-B：本地单元收口后接外部服务

### B1：正式身份及联调环境

先建立可信 HTTPS、微信主体/AppID 与合法通信域名、隔离预发布数据库、私有文件和扫描设施；在已有实现上完成真实微信登录、手机号、商家短信、员工绑定和门店激活。验证多角色、停用、撤销、跨店/跨用户隔离及生产配置拒绝测试身份。没有正式身份和可信文件访问前，不开展真实资金验收。

### B2：识别、转写和多模态输入

顺序为行驶证 OCR/VIN 解码及车牌来源核定 → 仪表盘里程 OCR → 档案照片识别和语音 ASR → AI 图片/文件理解。逐项接 A2/A3 已完成的采集、候选、确认及回退流程。

OCR 可按原文采用自托管服务；外部采购与自托管均需合法模型/数据来源及真实样本效果。没有合法车牌匹配来源时保持本人车牌匹配，明确该原文能力仍有差异，不推断车牌对应车型。模型或上游不支持多模态时保持文本回退，不把附件地址直接塞给文本接口。

完成标准：每种真实样本的正确、模糊、失败和人工纠正均有记录，私有文件经明确用途授权后才发给实际处理方；成功识别不绕过用户确认。

### B3：真实授权资料与向量检索

取得正式语料许可和嵌入服务/模型后，接 Milvus 索引与检索，复用已有版本、精确车型、用途、有效期、撤回及 AI 引用校验。先小规模合法语料验证召回与无匹配，再开放使用；服务失败保留关键词检索。当前无真实资料期间不制造正式语料和检索效果报告。

完成标准：来源与许可可追溯；真实问题和正确/错误车型样本有检索结果；停止/过期资料及撤销授权不能继续进入新引用。真实效果与合成契约测试分别报告。

### B4：正式支付、退款、对账与结算

复用已有预约、订单、券占用/返还、佣金和持久恢复，接正式支付创建、通知验签、主动查询和退款；之后补日对账、差异处理及本期必要结算能力。验证重复/乱序回调、支付超时、取消竞争、退款失败恢复、佣金冲销和真实金额。

完成标准：正式身份与资金渠道有独立证据，金额/渠道流水/订单/券/佣金一致；真实资金与 LOCAL_TEST 严格隔离。资金测试须限定可控订单与金额，不自行对真实客户发起扣款。

### B5：微信订阅、邀请码与传播

接关键订单/接车/退款/券提醒的订阅模板、授权和可靠发送，复用站内事务消息去重；未订阅或发送失败可站内查看。补官方小程序码、邀请分享及真实新客归因、双方奖励到账验证；不依赖客户端“分享成功”回调发奖励。

完成标准：有真实送达/拒绝/失败/重试记录；消息不越权，重复投递不重复奖励，老用户和测试身份不产生正式新客。

B2、B3、B5 在满足各自依赖时可调整相对顺序；B4 真实资金必须在 B1 后进行。不得因等待某一供应商而停止其他已具备条件的单元。

## 4. R9-C：最终验收与发布

顺序：iOS/Android 三端真机完整链路 → 正式渠道与预发布性能/安全复验 → 已有数据升级及备份恢复/回滚演练 → 监控告警验证 → 整理完整交付证据 → 微信提审及授权发布。

真机覆盖录音、相机/相册、文件选择、扫码、签字、私有图片、PDF、分享和系统授权；尤其补 A 段只能用替身或模拟器验证的行为。正式环境还需确认监控地址、线上地址与告警联系人。

完成标准：原文上线门禁满足，未完成项不隐去；测试、代码合并、预发布部署和正式上线分别记录。部署/发布按当时用户授权执行，本计划不代替真实客户资金操作或正式发布授权。

## 5. 每个执行单元的固定流程

每个单元按“检查当前实现 → 确定详细规格与分步任务 → 后端与页面 → 相关测试及必要联调 → 更新接口/迁移/手册/状态”推进。复用本项目已有模式；改变权限、文件类型、识别写入或资金规则时先明确业务契约。

状态分别记录：未开始、实施中、本地完成、真实渠道待验、正式验收通过。不得用“已规划”代替“已实现”，也不得把局部测试数量累加成完整后端结果。

当前下一项为 **A1：录音、附件和识别确认的详细规格及任务拆分**；随后 A2 → A3 → A4 → A5，再进入 B 段。不因本次规划新增提交推送、合并或部署操作。
