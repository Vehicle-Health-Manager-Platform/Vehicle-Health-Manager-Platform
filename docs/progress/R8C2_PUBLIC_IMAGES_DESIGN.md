# R8c2 独立脱敏图片设计

2026-10-17，用户已确认逐张选择、独立脱敏副本、本人确认和人工审核。无自动OCR或隐私识别供应商。

## 来源与公开边界

在已有有效公开施工经验下逐图申请。车主仅选择当前本人车辆档案中本人上传且扫描CLEAN的原图，并另行上传已经手工遮挡/裁剪隐私的副本。两文件ID必须不同，服务端读取副本后检查真实图片、尺寸与像素上限，重新编码为PNG以去除EXIF等元数据，得到服务器预览哈希。独立脱敏不等于系统能证明视觉内容没有隐私，车主和审核人均须实际查看副本。

公开图片采用服务器保存的独立PNG快照，经受控、无缓存API返回，不发原图URL、对象键、私有文件ID或无权限签名。重新编码只去元数据，不能替代遮挡和人工审核。父公开经验、当前车型/车辆归属、原图关联与文件扫描状态失效时拒绝新读取；撤回后拒绝新字节请求，已下载内容无法远程收回。

## 状态、权限与恢复

独立开关默认关闭；本人创建/状态/撤回，运营can_review仅查看主动提交的副本，不读取原图或档案；同款车主只读取获批副本。PENDING/APPROVED/REJECTED/WITHDRAWN及版本CAS、永久创建回执、审计/事件原子，审核和撤回共用串行锁，旧批准不得覆盖撤回。来源哈希和公开快照绑定，当前可见性每次复核。

上传、对象存储读取和图像处理不放进持数据库锁的业务事务；短事务在保存前重新锁定并核验当前源。图片单独授权，不沿用文字授权。配置/读取失败显示不可用，私有原图继续私有。

真实MySQL覆盖跨人/跨车/父撤回/源变化、CAS/并发/幂等与失败回滚；图像测试覆盖非法/超大图和元数据重新编码；HTTP覆盖三角色与无配置。实际页面覆盖源选择、副本上传、明确确认、审核/撤回和受控展示及生命周期清理。原V001不改，新增迁移后更新全量表计数与Compose原始挂载校验。
