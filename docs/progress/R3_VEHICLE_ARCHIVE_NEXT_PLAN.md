# R3 车辆档案下一阶段规划

日期：2026-10-11。承接R2c，范围微信小程序与必要后端。本文是实施队列，R3未编码；各单元开工前落具体中文规格/计划。

## R3a 录车入口与识别确认（紧接着实施）

1. 核对 VehicleController、手动录车、目录发布过滤、文件私有授权和 OCR 服务，补四入口：手动、车牌匹配、行驶证OCR、VIN解码。车牌只匹配本人已授权车辆，不能用车牌查询他人车主资料；新车不能仅凭车牌推断车型。
2. 补严格车牌/VIN输入、目录车型选择及识别结果确认/修正。识别候选与本人确认入库分离，失败/低置信度/无车型匹配回退手动；重复提交与身份切换不重复录车。
3. 明确行驶证私有上传、识别用途与保存期限、识别供应商输入/输出白名单、超时/重试/来源记录。VIN需要有授权车型数据源，不用规则猜完整车型；供应商失败不返回虚构成功。
4. 当前 services/ocr/src/server.py 的 /recognize 返回501，/health标记UNAVAILABLE。先交付真实入口、确认/回退与适配契约；选择具备授权的实际OCR/VIN来源后验证识别效果。未有真实效果证据的识别项继续标未完成，不要求短信开通才推进。
5. 按规格→后端/契约/迁移→微信页面→实际数据库/接口联调与中文验收四段上传GitHub。验证本人归属、证件文件跨身份拒绝、字段修正、供应商失败、停用目录、幂等/回滚；原生相机/真机单独验收，不拿离线样例充当通过。

## R3b 照片与语音录档

养护/维修照片结构化识别、语音转写与结构化录档，用户复核后保存；来源、原文与修订可追溯。复用已有手动/施工档案，不重写冻结施工事实。上游不可用可手填；文件授权、失败重试、弱网草稿随入口补齐。真实识别/转写须有独立供应商证据。

## R3c 接车识别与受控报告

补商家扫码定位本店订单、仪表盘里程识别与人工修正、独立油表照片槽及必要展示；复用既有七图/里程比对/争议，不改变第二次异议和超时自动处理排除项。补本人完整证件/养护档案展示与报告导出、私有分享过期/撤销；六指标评分/趋势计算在R4，报告不造缺失数据。技师关联档案最小授权保持R7，不开放全车主资料。
