# 整R7收口补缺设计

2026-10-16，按已授权[收口计划](R7_COMPLETION_NEXT_PLAN.md)核对后实施。

## 发现与处理

1. 登录回跳：R7页面均会隐藏清理/重新授权，但角色登录页缺少返回入口，运营登录始终转默认工作区。使用当前页面栈中的精确路由白名单及角色/ID校验，车主/门店/技师登录后显示“返回本次服务页面”；运营仅当当前权限允许原页面时返回，否则进入既有合法落点。无任意return_url、不持久化页面参数，不自动复用原账号权限或提交内容。
2. 技师施工：已有服务器报工/签字唯一事实及原键回执、当前接单/图片来源复核；客户端文字和未知请求仅内存。补技师登录响应账号ID的内存保留；本机显式文字/配件/工时草稿（七天）、账号/工单隔离和确认后的不可变报工/签字请求落盘。照片/签名位图、临时路径和私有URL不保存为草稿，未知请求只保存原正文/文件编号/键，供当前身份服务器复核后查询事实或原键重试。
3. 恢复顺序：重新读取当前工单/施工事实，校验两份快照的工单和状态一致及当前已接单；匹配已提交报工全部业务字段或原签名文件编号时确认成功，不重发。尚未执行且状态可写时只允许原正文/原键重试；状态不同或现有记录不匹配时拒绝重发，保留待核对提示。本机存储失败阻止发送，清理失败保留原请求且阻止新写。撤权时不显示或恢复内容，401保留未知请求至同账号重新认证，其他失权按当前范围清理。多页面不能覆盖未决请求或误清后续请求。
4. 诊断受理配置：新建/修订/发布/停用也保存账号隔离的不可变正文和原键；每次重试先读取本机原记录，多页面不能覆盖。服务器通用回执保留24小时，客户端从首次保存未决请求计23小时后阻止重发；超窗或损坏时先重新授权并读取服务器配置，由用户明确核对后只清理本机记录。清理使用原记录比较，不能清除另一页面刚保存的请求。
5. 其余R7写：档案授权/分配/关闭/已读用服务器当前事实＋CAS/唯一性恢复，通知新键读不会改read_at或重审。共享履约写流程原先允许未知结果后改正文生成新键，已改为冻结原正文/原键/身份并提供明确原请求重试；派工目标、履约动作及时段关闭也不能通过页面reset绕过。跨重启未持久保存的旧履约操作依赖重新读取服务器事实及既有状态/唯一约束，不能称为跨重启原键恢复。
6. 身份切换：车主和技师先写入新响应的账号ID再发布token，防止同步观察者用新会话关联旧账号草稿；凭据仍只在内存，不进入恢复数据。
