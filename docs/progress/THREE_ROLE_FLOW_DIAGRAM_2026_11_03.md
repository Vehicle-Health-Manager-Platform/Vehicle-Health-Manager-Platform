# 三端泳道图：各自做什么 + 彼此怎么交接

日期：2026-11-03｜分支：`docs/three-role-flow-diagram`｜基线：`main` `d238bec`

## 背景

`README` 原有的 `docs/assets/flow-main.svg` 是一条**单链路**七段流程（预约 → 接车 → 确认 → 施工 → 核销 → 评价 → 归档），
能说明"订单怎么走"，但看不出"车主、商家、技师各自在哪些阶段出手、哪一步要交给另外一端"。
本轮按用户要求补一张泳道图：**三端各自的职能**与**相互交接点**同图表达，中英各一份，仍嵌入两份 README。

## 设计

- 六个阶段沿横轴（`01 预约·报价` … `06 评价·归档`），三条泳道沿纵轴（车主端 / 商家端 / 技师端），
  底部一条**共享后端**带。
- 泳道内部用卡片列出该端在该阶段的具体动作；某端在某阶段不参与时，用虚线框写"本阶段不参与 + 由谁做"，
  而不是留空（技师端只有 `03`、`04` 两列有动作，`0–1`、`4–5` 各留一条虚线说明）。
- 泳道之间六个**编号交接点**：`①` 预约与支付 → 商家、`②` 接车单 → 车主确认（虚线段，属确认/异议回环）、
  `③` 派工 → 技师接单、`④` 质检签字 → 待核销、`⑤` 六位核销码 → 商家、`⑥` 核销完成 → 自动归档。
- 底部共享后端的六张卡片是**三端共用**的部分：身份/角色/权限边界、幂等写入与审计、档案授权逐条可撤销、
  站内通知与扇出、订单与档案单一模型、OCR/ASR 四服务默认关闭；其下一行点明**受限运营入口**
  （目录治理、政策与考核配置、内容审核、对账，仅内部账号、独立权限）是第四条入口，不属于这三条泳道。

内容来源：`docs/user-guides/{OWNER,MERCHANT,TECHNICIAN}.md` 与 `apps/miniapp/src/pages.json` 的 113 个页面及
`docs/STRUCTURE.md` 的三角色 + 受限运营定义，没有引入指南之外的能力。

## 做法

`.cache/gen_flow_roles.py` 一份模板出两份产物：几何完全一致，只有文案字典按语言切换。

| 产物 | 用途 |
| --- | --- |
| `docs/assets/flow-roles.svg` | 英文首页 `README.md` |
| `docs/assets/flow-roles.zh.svg` | 中文对照 `README.zh-CN.md` |

沿用 `flow-main.svg` 已确认可用的表现形式（`<img>` 引仓库内 SVG，动画写在 SVG 自己的 CSS/SMIL 里）：
虚线段 `@keyframes dash` 流动、`animateMotion` 数据包沿交接线移动、`prefers-color-scheme` 深浅色、
`prefers-reduced-motion` 关动效。没有引入脚本，也没有依赖 Mermaid 一类不支持动画的渲染器。

## 排版上踩到的三个坑

1. **英文比中文宽**：同一张卡片中文一行放得下，英文会溢出。改成按估算字宽（CJK 1.0em / 拉丁 0.53em）
   自动折行到两行，卡片高从 28 调到 34。
2. **交接说明被箭杆穿过**：先把说明居中放在徽标下方，向上交接的那三条（`②④⑥`）箭头起点正好落在文字基线上；
   改成"文字放在箭头尖端外侧"，箭头又短到看不见箭头；最终定成箭头贯穿整段间隙、尖端落在泳道边缘、
   六条说明统一排在箭杆**左侧**。之所以能统一放左侧，是因为列宽 172px 大于最长说明（约 120px），
   六条文字的横向区间互不相交；脚本里保留了相交与出框断言，触发会打印 `! hand-off caption ...`。
3. **阶段内容归错列**：初版把车主的"取车对比：接车 vs 完工"放在 `04 质检`，语义上属于取车核销；
   已移到 `05`，`04` 改为"查看质检照片与缺陷"。

## 边界
