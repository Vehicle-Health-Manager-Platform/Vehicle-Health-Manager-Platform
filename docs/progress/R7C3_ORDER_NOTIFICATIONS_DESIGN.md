# R7c3 第二步：关单、退款与异议消息

沿用已授权的事务消息、最小收件箱及当前权限复核方案。本步先补订单事件，诊断专属消息在下一步接入独立运营收件箱。

## 顺序与契约

1. V047 给现有订单 outbox 增加来源键，旧六类事件默认 ONCE，保留全部历史接收人和事件，不回填历史业务消息。唯一约束改为订单＋类型＋来源键。退款申请/撤回/门店决定以退款 ID 与 revision 为来源；异议处理/复核以追加记录 ID 为来源。退款渠道成功/失败以退款 ID 和结果为来源，重复回调不反复提示。
2. 在实际业务事务内发出关单、退款申请/撤回/拒绝/受理/成功/失败、异议提出/处理/不接受/解决共十一类事件。状态、事件、审计及幂等回执一同提交或回滚。退款受理只表示等待渠道确认，不显示已到账；仅已有可信 LOCAL_TEST 结果可触发本地退款成功/失败，不启用正式资金。
3. 关单/异议捕获当时车主、门店和当前技师；退款事件只捕获车主与门店，不扩散给技师。沿用当前身份、订单归属和派工复核；不向后来接手者补发旧消息。
4. 沿用可靠投递及现有三身份收件箱/已读，无新 API、无正文/原因/金额/照片/私有地址。固定提示引导查看本单当前业务事实，旧事件与当前状态分别显示。
5. 真实 MySQL 验证重复退款轮次、异议多条记录、业务/事件回滚、同源去重、迁移旧行兼容及重复执行；重跑相关交易/履约测试，前端全套、微信/H5、迁移与 OpenAPI 检查。

整个 R7 完成前不上传 GitHub。整阶段门禁、诊断消息与需求销项仍待后续。
