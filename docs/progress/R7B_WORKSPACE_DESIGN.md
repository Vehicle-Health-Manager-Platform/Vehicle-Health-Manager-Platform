# R7b 工作台与逐条档案授权设计

用户已确认：车主按订单逐条授权历史档案；门店仅可读取本单已授权记录，技师须已接单；撤销或工单失效后拒绝新读取。整R7完成前不上传。

## 范围与方案

采用当前任务聚合、独立最小上下文与显式逐条授权。批量共享整车档案会超出本次服务用途；仅显示车型不能满足维修历史核对，因此实现车主选择具体记录、具体版本的方案。

- 工作台按已有订单、接车确认、异议、当前派工和报工事实分为待接车、待确认、异议、待派工、待接单、施工中、待核销、来源需核对八组。重复读不推进履约状态，操作仍到既有订单页面。
- 门店范围限本店当前有效账号；技师限当前有效绑定、本人派工且已接受的工单。上下文门店仅RECEIVED/IN_SERVICE/PENDING_VERIFY，技师仅IN_SERVICE/PENDING_VERIFY；OPEN异议拒绝上下文及新增授权。
- 默认仅品牌、车系、年款、配置、本单项目及本单接车里程；不输出车主身份、联系方式、车牌、VIN、全车里程或证件。
- 历史记录只允许保养、维修、故障（类型1/2/10），车主可先预览同一投影和图片，再逐条确认。文本是车主授权的原文，不宣称自动脱敏；用户应在授权前核对。

## 数据、写入及撤销

V044新增order_archive_grant，唯一(order_id,archive_id)，无默认授权、无历史回填。状态ACTIVE/REVOKED，记录当前车主、revision、source_version及授权/撤销时间。

源指纹覆盖原content、结构化字段及revision、类型/车辆/日期、关联文件列表，JSON对象键递归排序。结构化共享采用类型字段白名单，不输出provider_name、source_reference或证件字段。指纹变化后旧授权不读取原文或图片，车主重新核对新版本后方可恢复。扫描状态、文件安全与来源关系另在每次读取时复核。

写入要求UUID幂等键、expected_revision；ACTIVE另需当前source_version，REVOKED不得带它。禁止客户端指定接收人/门店/技师。沿既有WriteIntegrity事务、身份/订单/车辆/档案锁、CAS和审计；版本竞争只有一个成功，审计失败整体回滚。重复键返回历史回执不代表当前仍有权限，页面随后读取当前状态。关闭订单仍允许车主撤销。

## 图片和读取生命周期

手工档案只签当前车主原上传的安全图片。自动归档仅DONE任务、原订单同车同车主、原已签字报工、PROCESS/FAULT/FINISH关联和原技师上传图片；无来源即不可用。每次读取检查CLEAN、未删除、JPEG/PNG、大小1至10MB。

文件签名存储IO前后重新读取当前身份/任务/授权/源和文件关系。撤销、转派、解绑、停用、转车、删除、异议或关闭会拒绝新读取。已返回图片URL不能承诺瞬时撤回，其残余有效期最多300秒。

客户端当前页内预览；到期、刷新、关闭、隐藏及账号/身份/订单变化清理资料与URL，迟到响应和旧到期回调不回填。授权失败结果未知时保留同一正文与键，只允许原操作重试；同账号同订单隐藏可保留未决内存，不跨卸载持久化，持久草稿/恢复在R7c实现。

## 验收与后续

验证跨店/同店其他技师、未接单、撤销、源变更、自动归档、并发CAS、审计回滚、签名竞态、协议严格性、切号/隐藏/迟到及原请求重试；真实MySQL/HTTP、小程序测试、微信/H5构建与V044重放。

本阶段不启用正式微信、短信、资金、供应商或真机发布；这些仍最后R9。R7c接续可靠站内事件、收件箱和非实时诊断，处理范围及分配契约需结合现有身份模型具体冻结。见[整R7计划](R7_IMPLEMENTATION_PLAN.md)。
