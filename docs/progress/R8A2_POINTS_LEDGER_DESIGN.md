# R8a2 可信任务与账本设计（2026-10-16）

已授权按R8计划继续；用户确认三任务、来源配置/未知/不补历史/TEST隔离及档案判定：人工保养/维修/故障任一记录，结构化必填完整且本人确认；自动施工/仅附图/扫描历史不计。

方案比较：直接改旧point_balance无法证明旧值；把奖励放在客户端会漏记或重复；采用独立可信账本+源事务事件，保留旧表/余额不导入。签到显式确认北京日期及政策版本；档案在成功结构化保存事务捕获；AI在真实官方成功返回后重新授权并捕获，不保存问题或答复正文到积分表，失败/降级/替身不计。

身份：新增auth_session.point_identity_source默认UNKNOWN；新建车主会话只有服务器POINTS_VERIFIED_IDENTITY_ENABLED（默认false）和官方微信端点同时满足才标VERIFIED_WECHAT，不借客户端声明、旧openid或邀请资格。刷新沿同一会话保留来源。POINTS_EARNING_ENABLED默认false，AI另需POINTS_AI_VERIFIED_ENABLED默认false和官方成功端点。正式接入/效果仍R9；隔离数据库测试可构造明确证据。

V050四表：point_task_event（冻结政策/原分值/身份会话/源编号版本和哈希、频率键及恢复状态）；point_verified_account；point_verified_entry（每事件唯一）；point_checkin_request（永久user+键+正文哈希+首次结果）。签到user+北京日期；另外user+任务类型+LIFETIME，换政策不绕过。无有效规则/身份时不捕获；不扫描历史补事件。

捕获与原业务同事务（AI在外部IO后独立短事务重验）；源事件PENDING。可靠任务逐事件事务，锁user及账户后写唯一流水/余额/审计/事件DONE，失败整笔回滚并退避；多消费者不可重复，停用账号暂停至恢复。奖励以捕获时完成行为为准，政策之后停用/档案之后修改不改已冻结分值，不自动扣回；只保留最小来源指纹，不能借积分事件读历史正文。来源、会话或确认在捕获前失效则拒绝，不冻结事件。

签到请求包含day、policy_id、policy_revision，原键永久意图避免通用回执过期/跨日重放产生新签到；同日不同键只登记同一事件。原签到首次PENDING回执后刷新当前事实，不能当已到账。读本人overview/flow及当前规则，余额明确为已核验任务积分，旧非零余额或旧流水显示历史待核对，不清零/不导入。

本轮先事件/账本/API与源接入，再本人积分页/恢复；R8a3前无兑换。所有代码/迁移/测试/文档仅本地，整R8完成后上传。验证真实事务、并发、北京日界/窗口等待、过期键、账号/会话撤销、源确认/TEST/AI失败、审计回滚和恢复，再HTTP/前端/构建/109表重放。
