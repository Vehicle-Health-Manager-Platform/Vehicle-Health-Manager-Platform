# R7c2 非实时诊断实施契约

用户已确认[运营诊断方案](R7C2_DIAGNOSIS_NEXT_PLAN.md)。本次依次完成配置/权限、车主留言/运营分配回复、页面/测试文档，整R7完成前不上传。

## 权限和状态

新增can_diagnose处理权限和can_diagnose_manage管理权限，均默认0，与原权限无继承关系。管理者仅看无正文队列、配置及分配信息；正文仅本人车主与当前获派且有处理权限的人员可读。兼具两权限的人员仍需获派才能读正文。

配置沿DRAFT/PUBLISHED/STOPPED和CAS/审计/幂等，唯一发布版本。mode为AVAILABLE/LEAVE_MESSAGE/PAUSED，必须有效期与来源说明；已发布条款不编辑，切换模式通过停止旧版本/发布新版本。无配置UNKNOWN，未生效/到期/暂停/无有效处理人均不受理；离线留言与可受理都为非实时服务，均允许合格车主提交。

留言会话WAITING→PROCESSING（分配）→REPLIED（回复）→CLOSED；未关闭会话可转派，旧处理人立即失去正文权限。车主可追加文字，需重新通过当前受理和R6资格核对；追加后有有效获派人则PROCESSING，否则WAITING。车主、管理者或当前获派处理人可关闭，关闭不可重开。

## 来源与事务

车主提交严格指定本人有效车辆、当前配置版本、文字和用途确认true，不能指定处理人或客户端资格。仅车型标签和主动文字进入会话，不复制VIN、证件、联系人、历史档案或图片。每条文字1至2000 Unicode字符、去首尾空白、拒绝控制字符；历史来源失效不抹除本人既有问题/答复。新增提交/追加时仍须当前车辆归属有效。

诊断控制行序列化配置发布和受理；受理事务重验会话、有效车辆，锁定当前配置、R6发布政策及有效邀请来源，锁等待后按当前北京月和政策截止复算，保存本次政策、月度人数、配置及车型快照。服务开关和规则证据不足不猜测；过月只影响新提交，不剥夺本人既有会话读取。

写入均UUID幂等键、CAS版本及审计；创建用持久提交意图唯一键保留超过通用24小时回执期限的去重，追加/回复/分配/关闭由会话版本约束。重复键重放仍复核身份和当前范围，历史回执不代表仍可追加或已派给本人。审计不保存留言正文，仅动作/会话/版本/状态；文字在受限消息表。

会话与消息、状态事件同事务，诊断事件有独立case_id，不伪造订单号。列表仅状态/版本/时点，详情按消息20条分页，不向管理队列输出正文。消息/已回复状态构成持久异步收件记录；跨业务站内提示及持久草稿/未知结果恢复接续R7c3，当前不宣称这些已完成。
