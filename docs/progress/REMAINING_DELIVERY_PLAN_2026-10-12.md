## 3. 每阶段文档与 GitHub 交付

每个子阶段至少提交：规格和实施计划、API/OpenAPI 及权限说明、迁移与已有数据处理说明（无迁移则注明）、测试/验收记录、执行记录与未验收事实，并更新 `CURRENT_STATUS.md`、`NEXT_STEPS.md` 和本页的状态。阶段收口检查需求 F 编号、代码、用例和证据之间的追踪关系，区分离线替身、真实 MySQL/HTTP、开发者工具、真机与正式资金。

完成一个子阶段后，使用独立 `codex/` 分支提交并推送 GitHub，创建对应 PR；依赖未合并时标明依赖 PR，合并后调整目标分支并复核 CI。PR 附最终提交、测试结果、未验收项和下一阶段。只有 GitHub 分支与 PR 均存在才标记“已上传”；只有所约定检查通过才标记“阶段验证通过”；合并、部署、正式发布另记实际状态。规划本身作为文档阶段单独提交与上传，不将其写成业务功能完成。
