# R4a1 本人目标提醒后端执行

日期：2026-10-12。用户确认采用目标到达提醒，提前提醒后续补充。规格与计划见 `docs/superpowers` 下同日 R4a1 文档。

## 已实现

- 来源限本人当前车辆的手动或附图保养、保险、年检档案。保养接受日期和/或里程，任一到达触发；保险、年检仅日期。默认无目标，不设周期、不推断法定日期。
- 每辆车每类一个当前配置；明确确认后可替换来源。停用保留配置，来源删除/失效停止提示并隐藏旧来源和目标。
- 三个 OWNER 接口：来源 context、设置/停用、车辆三类提醒列表。每次访问及幂等重放复核会话、账号、车辆归属和有效来源。
- 资源锁、版本冲突、UUID 幂等回执、最小审计和目标写入同事务。原档案及 R3c3 分享字段不变。
- V028 可重复执行；初始化/基线 41 表、完整迁移 68 表，OpenAPI 149 操作。现有环境追加 V028，不重放基线升级。

中文字段和错误契约见[提醒 API](../api/ARCHIVE_REMINDERS.md)。

## 本地验证

2026-10-12 定向后端 **8/8**：纯输入/状态 2 项、真实 MySQL 4 项、Spring 安全 HTTP 2 项。覆盖日期当天、里程到达、未知里程、类型限制、他人车辆、来源删除、车辆转移、停用/恢复、版本竞争、替换确认、失效会话重放及审计失败回滚。

本地 Docker 29 使用 api.version=1.44；关闭本地 Ryuk 以使用已有镜像，MySQL 容器由测试生命周期清理。测试库允许创建审计失败触发器，该选项仅在测试容器设置。角色 HTTP 测试不等于真实生产身份验收。完整回归和迁移验证由本阶段 GitHub CI 补充。
