# A4d13 车型适配与方案证据链执行记录

## 范围与结果

2026-10-22，基于 PR203 的 `codex/r9-a4d12-fulfillment-reads` 完成六个新增接口的本地隔离验收：运营车型适配规则读写、方案目录、方案生成、车辆证据及方案预约上下文。分支 `codex/r9-a4d13-plan-evidence`；时段发布作为第七个支撑接口。生产Java及数据库结构未修改。

PR203在本阶段核对时，已完成的六项CI均成功，后端仍运行，后续依赖其实际结果；不将它写作全部通过。本阶段模型明确关闭，验收的是MANUAL降级和本地证据链，不代表外部模型效果或技术适配真实性验收。

## 实施与行为

- 独立套件 `scripts/plan_evidence_api_cases.py` 覆盖七个接口的正常、边界、错误和未授权四类请求。
- 适配规则从缺失开始，依次写入APPLICABLE、NOT_APPLICABLE、WITHDRAW；验证同键重放、变更意图、旧版本、撤回来源必须为null、权限不足和匿名访问。
- 撤回后运营侧版本保持3，旧版本0不能重新写入；旧成功回执可重放但不会复活规则，车主仍看到UNKNOWN。规则版本在车主UNKNOWN投影中为0，运营侧保留撤回版本用于后续更新。
- 同系列不同车型保持UNKNOWN，无车型车辆也不依据EV动力类型推断适配。证据只投影五个车辆字段，不含VIN、车牌；六项缺失观测均NOT_SET，无经验样例时为空。
- 模型配置关闭且无供应商地址/密钥，返回MANUAL；仅保留车主指定的有效目录项目，脱敏问题中的手机号，不增加价格、故障或必做结论；无指定项目时返回空项目数组，停用项目拒绝。
- 真实HTTP发布一个未来时段，预约上下文绑定当前项目、报价版本和价格、车主车辆及日期；验证空页、未选中时段、无效选择、跨车主、项目不匹配与非法参数。UNKNOWN证据原样返回，不表示已确认技术适用，更不表示已创建预约。
- 只读POST不带幂等键；证据审计绑定实际请求体、同意字段、版本、日期、写入原始幂等键和真实身份，拒绝缺失/重复/失败/跳过/部分或替换执行证据。
- 接入 `--plan-evidence-cases`、互斥独立数据库、源文件哈希、CI生成/脚本校验/后端验收和历史证据汇总。
