状态：本地完成；无 GitHub 上传。设计见[契约](R7C3_ORDER_NOTIFICATIONS_DESIGN.md)。诊断专属消息、整 R7 统一门禁尚未完成。

## 实现

- V047 扩展现有 outbox，来源键默认 ONCE 兼容旧行，唯一键为 kind/order_id/source_key；保留旧事件 UUID 和接收人。无新表，共102表，无历史业务事件回填。
- 十一类新事件：取消/过期/退款关闭订单；退款申请、撤回、拒绝、受理、渠道成功、渠道失败；接车异议提出、门店追加处理、车主不接受、车主接受解决。加原六类共十七类。
- 退款同一记录反复申请按 revision 保存不同事实，异议每条追加记录独立。退款渠道同结果即使使用不同回调 ID 也只提示一次；成功后迟到失败不产生退款失败消息。受理与成功分开，不显示到账承诺。
- 退款仅车主/门店；关单及异议保留事件时点车主、门店、当前技师。所有读取和已读继续复核当前身份、订单和派工；来源键不出现在接口。
- 生产埋点在真实状态/文字记录/审计/幂等事务中，事件失败阻止业务提交；原键可重试。接收人使用当前锁定读取，不能沿用事务早前的RR读视图；首次投递时间显式采用恢复扫描同一业务时钟。沿用逐事件原子投递、重启恢复、并发去重和失败退避。
- 前端固定提示扩展，页面仍只读订单号、当前状态及事件时间；无原因、处理正文、资金金额或图片。六项订单通知 API 与响应结构保持一致；OpenAPI仍252操作。
