# R5 券阶段需求闭环

范围为已规划R5a+R5b；以实际代码、验证和冻结规则销项，不用基础表或OpenAPI草案总数替代实现。来源见[原文](../reference/DELIVERY_V1.md)、[阶段规划](R5_COUPONS_NEXT_PLAN_2026-10-14.md)与[用户确认设计](R5B_COUPON_DESIGN_2026-10-14.md)。

- 库存/发放：本店店长草稿、类型/金额/门槛、在售项目、有限库存/有效期、发布冻结/停止，独立运营精选池；来源/发布/发行/库存流水及审计，终身每模板每人一次，最后库存并发唯一胜出。见[R5a执行](R5A_COUPONS_EXECUTION.md)。
- 领取/本人权益：运营精选和指定门店可领、我的券、真实截止提醒、门店与个人入口；旧无来源券未知，过期/停止/来源失效不再新领。
- 现金用券：新接口同快照预览当前报价/本人车/时段和资格，单券不叠加、精确发行店/项目、正现金实付。名额/券/订单原子冻结，支付消费，未付关闭释放，只有全额退款确认成功返原券、不续期。永久创建编号保护通用回执过期后的重试。
- 独立服务核销：本人授权版本/高熵短期码，本店先预览项目/码再确认交付，核销唯一事实/消费/0佣金/审计；二维码与订单码区分、跨店拒绝、持久限流。没有伪造微信/现金支付、订单完成或施工档案。
- 佣金：有可信新合同/实际消费按现金实付冻结既有政策，入驻免佣期保留；独立服务券免佣。无源旧WAIT_COUPON仍待核对，缺少原政策不凭空计费。
- 一致性/恢复：转换在原业务事务；名额/审计/付款/退款失败全部回滚。支付查询/退款查询恢复与券持久重试，多实例不重复消费/释放/返还；矛盾付款/关闭事实不释放，坏记录延后不阻塞批次。
- 客户端：普通及AI预约可进入金额券预约，优惠/实付确认、原请求同键重试、订单券摘要、本人服务授权/记录、商户核销/记录；权限/空态/过期/分页、隐藏与账户切换保护。原四字段预约、现金履约与隐私投影保持兼容。

交付包含所有R5业务代码、V038/V039、测试、生成协议及使用/运维/进度/验收文档。实际7个券相关新增页（R5a4、R5b3），小程序总70页；新增16项实际券操作，OpenAPI总199仍包含其他未实现草案；数据库88表，原基线44表与追踪141行不改。

本地证据及测试范围见[R5b验收](../testing/LOCAL_R5B_COUPONS_ACCEPTANCE.md)。用户要求整个R5完成后再上传，R5b实施期间未推送；最终准确head、上传分支/PR及全套CI状态在PR正文记录。供应商、正式身份资金、真机/发布未被本阶段验收，最后R9；邀请奖励发券属于R6，积分兑换属于R8，不将其误记为R5剩余子阶段。
