## 实现及实际结果

新增显式Linux运行器，复用已有真实HTTP、MySQL、私有MinIO、合成扫描签名和业务审计。模型、71包Linux锁和源码绑定镜像不可变ID，OCR继续仅连接internal网络、非root10001/只读根与模型/2CPU/1536MiB/swap0/128PID，受限子进程初始化模型前加载seccomp。前后核对同一worker及启动身份、过滤器额外存在与READY。

本次Java17/Maven在工作区缓存，通过宿主Docker Desktop命名管道创建隔离资源，关闭Ryuk；新增容器不接收Docker控制接口。只读非root转发容器固定目标ocr:8090，使用本次internal及专用桥接网络，唯一宿主随机端口仅绑定127.0.0.1；入口审计拒绝公开端口、额外挂载/网络、权限或资源放宽。原生代理通过宿主curl.exe透传实际请求和响应，不修改候选或业务结果。转发进程有桥接网络，不声称它自身全面禁网。

最终同一源码两种模式均通过：仅网关模式80项材料/工作台、12项网关及1次成功识别上游TCP连接；微信模式保留80+12项，并通过SDK3.17.2的9项原生检查、上传1/识别2/保存1、共3次成功识别上游TCP连接。每轮模型预检直接HTTP两次另计；TCP连接数不冒称模型内部调用数。源码稳定、签名下载图片字节一致、同受限worker保持就绪均通过。

微信在候选返回、取消和确认带入三个SQL节点均零档案、登记里程100。本人核对前不得带入，确认仅带入，原保存按钮最终只创建一条里程123456且引用本人CLEAN图片的合成档案；登记里程仍100、无辅助材料。页面重入为空，会话、系统API、代理和页面图片引用恢复/清除。

正常JVM关闭后，运行器按外层本次身份对业务容器及网络兜底清理。只接受同名同类型明确不存在，daemon故障不算成功，某资源失败仍继续其他资源；两种成功模式宿主进程、业务/OCR容器及网络和私有env/控制文件均清理。运行日志/身份/令牌仅在已忽略cache，脱敏结果见[报告](../testing/reports/R9_A4D45_LINUX_MILEAGE_2026_10_26.json)，复验准备与入口见[API说明](../api/MILEAGE_RECOGNITION.md)。

小程序1061项、Python审计60项（本轮9、原路径14、镜像18、材料11、交接8）全部通过；普通与隔离微信构建通过，普通包无测试身份桥。契约/覆盖索引核对通过：353契约、339受保护、317项所选历史四类证据、36项登记结论、36套来源。索引不产生业务请求，全API验收仍false。本阶段未重跑A4d44的60项Linux OCR回归和网络出口控制，不把历史结果写成本轮新执行。

## 失败轮次及修正

新增Maven容器挂Docker socket的原方案被自动审批以权限过大拒绝，文件未落地，已撤销并改为宿主工具及关闭Ryuk。官方Java ZIP按发布字节数/SHA256校验后解压到cache，Maven及本地依赖从既有缓存只读提取，未改变全局安装或系统PATH。

首次容器实际预检成功，但Docker仅internal网络不分配发布端口，入口审计拒绝后清理；改为只有转发器双网络，OCR隔离不变。下一轮Surefire未继承父JVM的Docker API兼容属性，400导致测试环境不可用；通过本次JAVA_TOOL_OPTIONS传递API1.44后完整通过。小程序受限环境初次4项loopback EACCES，授权环境1061项全部通过。各失败轮次不计整体成功，最终版本两种模式单独复验通过。
