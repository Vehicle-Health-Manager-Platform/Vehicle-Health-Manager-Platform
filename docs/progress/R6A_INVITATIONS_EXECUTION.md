# R6a 邀请资格与归因阶段执行

## 范围与设计

用户授权“规划好下一步，然后开始实施”，并确认月度新增 1、2、3、4 人四档，累计 1/3/6/10 后重复；每位有效新客双方各一次奖励，档位不额外重复发券。采用[新增注册来源账本设计](R6A_INVITATION_DESIGN_2026-10-14.md)，先完成可独立验收的 R6a，再完成 R6b 奖励。

## 本阶段实现

- V040 三表：稳定随机推广码、首次注册及不可变 owner/staff/merchant 来源、永久手机号摘要历史；旧 invite_record/user.inviter_id 不回填，共91表；补齐Compose新卷原来缺失的V027–V040依赖，冒烟强制验证当前完整结构。
- 九项实际增长接口及严格微信/云托管携码登录、绑定手机资格联动。新增 app/来源证据、客户端资格标志拒绝、幂等码生成及当前身份/门店重验；记录不暴露被邀请人身份。
- 服务端仅新注册归因，已有账号得到 EXISTING_ACCOUNT 轻提示；未知/测试/旧来源不补算正式新客。正式资格默认关闭，官方换码端点和同 app 手机证据才允许资格事件。
- 资格确认发生月按北京时间计数，1/3/6/10 四档重复；历史归因不改，手机号历史不释放，审计失败整体回滚，时钟异常拒绝。
- 新增车主邀请/落地注册/员工推广三页，总73页，个人中心与门店工作入口可达；原首启动路由不改。显式推广上下文与登录重试固定，隐藏/账号切换丢弃迟到响应，读失败清理旧数据。
- 本阶段不发奖励、不创建人工诊断解锁或假装正式分享成功；供应商/身份资金/真机发布仍最后R9。
