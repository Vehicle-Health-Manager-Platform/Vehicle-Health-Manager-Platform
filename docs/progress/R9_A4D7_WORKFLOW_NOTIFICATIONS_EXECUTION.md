## 实施内容

- `scripts/workflow_api_cases.py`：复用预约、LOCAL_TEST 支付签名回调、接车确认、派工接单、防护、施工报告、签字、核销与归档链，在对应状态插入查询。
- 通知由真实业务事务与后台 outbox 任务生成；不插入 notification/outbox 夹具。通知 ID 从实际列表响应取得；证据审计将已读路由绑定到对应订单完成通知，并检查原始请求体、幂等键及重复已读回执。
- 验证匿名、角色不符、跨车主/跨商家、跨通知接收人访问，非法 ID/分页与非空已读 JSON；同键重放和新键重复已读都保持原时间。
- `run_api_acceptance.py --workflow-cases`：独立数据库运行、源文件哈希约束、清理校验；与其他业务套件互斥。共享履约审计新增可选接口数量参数，原套件默认行为保持不变。
- CI 增加生成资产、脚本测试和独立后端验收；覆盖汇总增加本阶段记录适配器，要求签名回调、实际通知 ID/回执和六项数据库不变量。
