# R8a3b 已核验积分原子兑换

2026-10-16。承接已确认的[R8a3规则](R8A3_POINTS_EXCHANGE_DESIGN.md)和已完成目录配置。本步实现事务/API/扣分明细兼容，车主目录选择与确认/持久恢复页面在 R8a3c。

## 事务与来源

- 独立 `POINTS_EXCHANGE_ENABLED=false`；新兑换须同 app 服务器已核验会话、当前有效本人、已发布目录及来源。兑换开关与获分开关独立，已成功兑换的回执不因开关关闭或券过期而消失；每次返回前仍重验当前账号/会话。
- 输入仅 `{catalog_id,catalog_revision}` 和 UUID 幂等键，目录发布后冻结，因此不接受客户端价格、余额、身份、库存或券条款。同本人同键永久保存正文哈希/首次成功结果；跨通用24小时回执期仍返回同一成功事实。不同正文拒绝。
- 锁序：当前会话/本人→券来源门店/项目/券→目录→本人可信账户；与任务到账的本人→账户及券配置的来源→目录一致。目录的源引用读取后必须在锁目录后再次核对。所有等待结束后统一取业务时点，再重验身份、有效期、来源版本/精选池、库存和模板累计次数。
- 同本人＋券模板的全部成功兑换计数，跨目录版本累计，不受公共领取/邀请次数影响。仅 `point_verified_account` 可扣，旧余额/流水不导入；金额不足、无库存、过期或来源变更直接拒绝，余额不为负。
- 同一事务写本人券、永久成功兑换记录、POINTS 券发行凭证、统一账本负数流水、余额/版本、库存事件和审计。提交前无外部 IO，任何失败全部回滚，不留待补券或待扣分半笔状态。

## 数据迁移

V052新增一张 `point_exchange_record`，保存冻结目录/本人身份来源会话/永久提交键与哈希/首次结果/本人券唯一引用。已有 `point_verified_entry` 改为有符号 delta、event_id 可空，并增加唯一 exchange_id；数据库 CHECK 强制收入＝正数＋任务来源、扣分＝负数＋兑换来源，禁止无来源/双来源或0分。`coupon_issue` 新增唯一 points_exchange_id，扩展 CHECK 区分 PUBLIC/INVITE/POINTS，原有公共一次领取唯一索引保留。

迁移必须可重放，不修改 V050/V042 历史定义、不导入旧积分、不预置兑换。统一账本自增 ID 用于收入/支出的稳定分页，收入原响应字段保持，支出返回独立精确结构。页面展示正负号、兑换来源和真实余额。

## 接口与恢复

- POST `/api/point/exchange`：提交目录修订，成功返回冻结目录和本人券/兑换编号、花费及余额、时间。
- GET `/api/point/exchanges`：仅本人成功记录，固定20分页，不暴露身份会话、提交键或哈希。
- `/api/point/flow` 扩展收入/支出联合结构；历史信用流水不重写。

响应 no-store，OWNER身份、精确参数和正文校验，未配置数据库为503。错误不当成功；网络未知用原键原正文恢复，不自动换目录或价格。成功不自助撤销返分，后续R5退款仅返原券；原券过期仍过期。
