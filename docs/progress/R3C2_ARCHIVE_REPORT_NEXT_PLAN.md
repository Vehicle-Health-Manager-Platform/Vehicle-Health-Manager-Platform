# R3c2 本人档案报告与私有导出：下一阶段计划

2026-10-11。当前仅规划，尚未实现。R3c1#111–114接车扫码/油表已实施待合并；OCR/VIN供应商无授权，优先可独立完成的档案报告。范围微信与必要后端，不建PC。

## 交付范围与顺序

1. 核对本人车辆、车辆档案、证件/养护记录、施工完成冻结档案与受限文件事实，落中文规格与实施计划。不能把入驻证件当车辆证件；未采集的证件/保养数据明确未提供，不造评分或六指标。
2. OWNER本人选择车辆与日期区间，后端复核有效会话及车辆归属，生成完整只读报告JSON；包含脱敏车辆摘要、条目时间/类型/来源、可信里程和养护施工记录，未知/缺失字段显式标记。服务按车辆锁/一致读取冻结报告事实，不因分页遗漏条目，超出可导出上限明确拒绝。
3. 基于冻结事实生成中文PDF报告；作为本人私有文件保存，创建带UUID幂等键，同键重试不重复生成。不包含手机号/完整VIN/完整证件图/预约码或长期图片URL；仅本人Bearer下载及短时私有访问，撤销会话/删除车辆后拒绝新签发，下载链接到期后不能重用。PDF中文字体来源/许可与生成失败清理须在开工规格明确。
4. 微信本人车辆档案页增加报告查看/导出，日期过滤、缺数据说明、生成重试与打开文档；隐藏/换身份丢弃回调与清理私有路径。不做商家/技师查看全档案入口，不发送订阅或公开分享。
5. 真MySQL、HTTP安全链、PDF实际文本/文件/中文渲染、跨身份拒绝、重试/回滚/过期与小程序离线/构建，分别保留证据；原生打开PDF及真机到R9。规格→后端/迁移契约→微信→验收四阶段各上传GitHub，合并另按授权。

## 验收门槛

报告每条事实可追到本人原档案且覆盖所选时间；无数据不出假趋势/评分；陌生车主/跨店/技师不能读取、创建或签发；生成失败不残留成功记录/对象；同键同正文复用、换正文拒绝；已生成报告内容冻结，原档案变更不静默改文件；JSON与实际PDF一致且中文可读。
