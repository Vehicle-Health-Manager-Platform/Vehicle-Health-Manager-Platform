# R8c1b2a 私有结构化问答后端设计

2026-10-17。承接用户已确认的独立运营非实时答复、默认私有方案及继续实施指令。使用brainstorming和planning-with-files记录设计；沿项目docs/progress及本地分阶段流程，不重复询问已确认规则，不上传或提交半阶段内容。

## 方案和范围

采用独立社区问答表与can_community_answer/can_community_manage权限，复用事务、严格输入及原请求机制。复用R7诊断业务表会混入邀请资格和旧私有资料；直接公开提问缺少独立授权；均不采用。本轮b2a完成后端与契约、权限兼容及验证，下一b2b做实际页面与本机恢复，b3再做独立公开授权审核。本步不声明整个b2完成。

## 数据和受理

V058增加两项默认0权限及五表：单行串行控制、来源受理政策、问答、消息、事件。政策DRAFT→PUBLISHED→STOPPED，草稿CAS、同一时间最多一个发布版本，来源说明/有效期和AVAILABLE/LEAVE_MESSAGE/PAUSED；两种可受理模式均为非实时答复，无政策UNKNOWN，有效答复人员为零SOURCE_UNAVAILABLE。发布后冻结，不删除历史。创建政策和提问保留永久原键/正文哈希/创建回执，不依赖24小时通用回执。

车主新建选择本人当前有效车型的车辆、MAINTENANCE/REPAIR/FAULT分类、1–2000字主动文字及明确consent。仅保存车型快照、所选文字与受理证据，不读取档案/诊断/图片/联系方式。模型目录或车辆无效拒绝新建/补充；历史绑定原提问人，不随车辆转移。没有邀请资格或积分任务关联，没有额度或历史补录。

## 范围和状态

WAITING→分配PROCESSING→答复REPLIED；车主补充重新PROCESSING，无有效获派人回WAITING；车主或当前获派人可关闭，CLOSED不可继续写。管理者仅最小队列和有效处理人员ID/账号标签，可分配但无正文或车型读取权限；同时持有处理权限也须当前获派。重分配/撤权后旧处理人连原回复回执也不得新读。每次GET与写入/回放复核当前账号及会话。

新建和补充携带当前policy_id/revision，事务内重新核验窗口及受理。已有提问的获派答复/关闭不因政策停止而中断。所有变更expected_revision严格CAS，审计仅最小状态，不含正文；消息/事件/状态/回执同事务提交。未提供通知API或向R7通知混投；此步持久问答事件用于后续独立消息。

## 事务与契约

全体业务写先锁同一控制行，再锁当前身份和涉及的问答行、取得通用幂等记录；仅新输入在变更回调中锁当前受理及车辆/目录。分配涉及两个运营账号时按ID排序，受理检查有效处理账号也按ID排序。业务写之间由控制行串行；离线CLI只按账号/会话顺序，不访问控制行或问答行。鉴权非锁初检后锁内再次复核，CLI权限撤销与账号锁互斥。读在同一只读快照内核验范围与投影。原创建回执先复核当前身份，再恢复历史意图，不重新要求当时受理/车辆仍有效。其余原键24小时内按当前范围恢复，过期后CAS阻止重复，不声称永久恢复非创建操作。

16项HTTP：车主context/list/create/detail/message/close六项；运营政策list/create/update/status四项，handlers一项，问答list/detail/assignment/reply/close五项，共16项。严格角色/ID/页码/重复字段/多余选择器/JSON类型/确认及UUID键；成功单层响应，所有私有响应no-store，未配置依赖503。
