## 实现方案

复用RealMaterialWorkbenchJourneyTest的真实HTTP/MySQL/MinIO/ClamAV旅程及合成扫描签名数据库。仅显式AUTOCARE_NATIVE_MATERIAL_RUN_ID时，在现有断言之后创建独立车主/车辆991，提供临时私有握手，等待原生脚本上传一页合成PDF。默认CI不等待开发者工具，不改变原有用例清单。

Node执行器启动宿主127.0.0.1代理，仅接受本轮身份、固定ARCHIVE/991上传路径、PDF和合法请求键，限制1MiB合成测试请求。multipart字节通过docker exec/curl交给原JVM HTTP服务，不模拟上传响应，不新增容器监听或端口发布。另有需同一合成身份认证的固定测试PDF下载路径，用于微信生成真实临时文件；该路径只提供测试输入，不替代业务响应。限制只适用于测试代理，不修改产品10MiB限制。

原生脚本将合成PDF实际下载为微信管理的临时文件，通过chooseMessageFile结果辅助选入页面，再由页面实际uploadFile上传；验证扫描通过且尚未识别的收据、移除本机引用和重入无引用。JVM核对只有一份本人/本车/ARCHIVE/CLEAN的一页PDF，签名下载逐字节相同，并且没有新增档案。移除本机引用不代表服务器删除。

## 复现

需要Docker引擎、Node/Python和微信开发者工具。先按[隔离构建说明](../testing/WECHAT_LOCAL_FINANCE_ACCEPTANCE.md)构建回环18080测试包并在构建后重开该隔离项目，RPC9420；不要运行finance套件。确认18080未被其他服务占用后，在仓库根目录执行：

```powershell
node scripts/native-material-upload-e2e.cjs --allow-isolated-upload
```

执行器只将UUID运行ID传入Maven测试容器；短期合成令牌、PDF及curl配置保留在忽略的.cache私有目录，完成后删除握手/配置、恢复系统API、清空内存身份、释放页面本机引用（下载临时文件由微信管理，不宣称已物理删除）并关闭代理。测试容器的数据库/存储/扫描等资源按已有旅程清理；失败轮不得登记通过。终端只输出运行目录和完成状态，不打印令牌。只上传最终脱敏report.json。
