## 2. 当前进度结论

核心履约实现已经贯通：预约/隔离测试付款 → 接车八图与损伤标注 → 车主确认/异议及复核 → 派工/本人接单 → 防护/报工/质检签字 → 核销 → 自动归档/本人评价。入驻审核、员工与门店资料、标准目录治理、取消退款业务、支付查询恢复、佣金账单和本人档案 PDF 导出也已实现。

尚不能按原文称为完整可运营 MVP：健康驾驶舱、结构化 AI 推荐到预约、券与邀请等 P0 闭环仍缺；积分、考核、问答等 P1 未完成；正式身份、真实资金及设备/发布验收未收口。不存在有依据的统一完成百分比。

## 4. 按三端汇总尚欠功能

### 车主端

1. **车辆与档案**：真实 OCR/VIN、照片/语音识别后确认、完整证件/记录展示、限时报告分享与撤销。
2. **健康与 AI**：评分/六指标趋势/五类提醒；结构化方案、真实项目和商家推荐、预约联动；多模态、同款经验检索、非实时人工留言。
3. **服务消费**：商家详情、位置/评分排序、区域回退、公开评价与总结；用券；完整施工进度/质检证据与通知。
4. **福利与社区**：券、邀请、积分、任务、问答与分享；“我的”补车辆/福利/邀请/积分/任务/通知隐私设置入口。
5. **原文入口**：专属优惠、二手车/新车服务仅按入口要求规划，不扩建交易商城；没有实际承接服务时不得假装可交易。

### 门店端

1. 仪表盘里程识别与确认；取车前后证据对比；接车/施工消息。
2. 本店券模板、库存/发放、券池投放、核销；券成本与佣金规则联动。
3. 店员推广码和拉新来源；考核中心/等级/复算明细。
4. 实用工作台、订单/退款/收入/券/拉新统计、本店履约所需客户信息、价格异常数据。
5. 与订单关联的最小档案授权；接车/防护草稿、离开提示与弱网恢复。
6. 正式账号激活、短信与设备/真实资金结算验收，放最后接入。

### 技师端

1. 本人工单关联车辆的必要档案/病史，只读且受工单及绑定状态约束。
2. 待接/进行中/待质检工作台摘要及下一动作。
3. 报工/照片/签字草稿恢复、任务通知、离开提示与弱网重试。
4. 真实员工微信绑定、相机/相册/图片预览/签字、多设备验收。既有报工核心无需重做。

## 5. 容易漏判或需先定规则的事项

- **取车对比**：原文 §8.3 的 `/api/check/delivery/compare` 出现在 OpenAPI/旧契约，但实际后端控制器未提供该业务；文档列有接口不等于实现。安排 R7a 明确接车基线与完工证据的只读对照、差异确认及归档范围。
- **经验卡片触发差异**：完成事件已可靠写入私有档案；当前卡片仍与后续评价请求关联。原文 §12.1 的“订单完成自动写档案并生成社区卡片”不能整体销项。R8c 明确是否在无评价时生成私有草稿；任何草稿公开仍须车主授权与审核。
- **六指标口径**：原文 §5.6 同列“电池”和“电瓶”，需要明确是否同一项、数据来源及评分含义；不能直接把示例百分比做成真实测量值。
- **奖励和考核**：40/40/20 权重与月度循环已有要求，但不能推导出奖励库存、金额、获分条件、考核分母和等级阈值。相应阶段应冻结可复算的业务规则；原文 UI 中的券金额和积分数字视为展示样例。
- **公开评价**：现有评价本人私有、不可修改。公开/匿名授权、撤回、测试评价隔离及商家评分计算先定规则，再接评价总结；不自动公开旧私有评价。
- **受控分享**：分享内容/接收身份/有效期/撤销审计需独立授权模型。撤销阻止后续服务器访问，不承诺远程删除接收人已经保存的图片或 PDF。
- **异常体验**：已有 UUID 幂等、部分重试和账号切换隔离；统一持久草稿、登录失效回跳、超时重试、系统取消回调仍需逐页核对。不能对写接口统一盲目自动重试。
