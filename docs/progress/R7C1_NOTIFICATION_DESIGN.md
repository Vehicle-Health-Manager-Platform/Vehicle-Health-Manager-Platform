# R7c1 可靠站内通知设计与实施计划

沿用户已授权的整R7计划实施可靠事件、本人收件箱与已读。整个R7完成前不上传代码或文档。

## 本步范围

先覆盖六个既有、每订单只发生一次的事实：付款成功、接车完成、派工、技师接单、施工签字完成、核销完成。自由留言、诊断处理权限和持久草稿接续R7c2/c3；关闭/退款/异议等事件以后按独立来源补充，不用状态轮询伪造已发生通知。

采用业务事务内outbox保存事件、定时后台投递。相比同步直接发通知，可独立恢复并扩展渠道；相比扫描历史审计回填，可准确冻结当次接收人且不误推旧业务。V045新增一张outbox表，复用原notification表；无历史通知回填，不发送正式短信或微信。

事件保存唯一(kind,order_id)、随机事件UUID、当时车主/门店/技师ID、发生时点，不保存照片、联系方式或自由文本。业务代码中明确埋点，与状态/审计/幂等同事务；写事件失败则业务回滚，重放不重复事件。派工通知捕获当时技师；晚投递不把旧事件发给后来接手的人。

每事件独立事务SELECT FOR UPDATE SKIP LOCKED，插入notification并标记DONE同提交；事件+接收人唯一去重。失败单独记录固定错误码和有界退避，后续事件继续处理；不永久放弃或把错误详情写入消息。一个调度周期最多20事件。读接口不创建或投递事件。

收件箱分别为车主本人、当前门店（店长/店员共享本店已读）、技师本人。每次读取/已读都校验当前会话与角色、有效账号/门店/绑定，以及当前订单车主/门店/派工归属；旧事件失权后从列表和未读计数剔除。消息仅固定类型、发生时点、订单号/当前状态与已读时点。跳转既有订单页继续按该页权限处理，不因消息授予历史档案权限。关闭的本人订单仍可保留事件事实，不代表仍可读施工上下文。

GET本人收件箱分页20及未读计数；PUT单条已读要求UUID幂等键、严格空JSON正文，不接受客户端接收人，已读时点不可被重试刷新，审计失败回滚。客户端刷新/隐藏/切号/换角色清理资料，未决已读仅原键重试；不冒充R7c3持久恢复完成。
