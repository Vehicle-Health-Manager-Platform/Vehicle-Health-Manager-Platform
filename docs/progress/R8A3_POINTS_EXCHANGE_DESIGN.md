# R8a3 积分兑换设计

用户已确认：已发布精选池服务券和金额券均可兑换；正整数积分价和每人限兑次数由运营配置；同一券模板跨目录修订累计限额；成功不支持自行撤销返分；失败则积分、库存和发券全部回滚；订单退款仍按 R5 返原券，不重复返积分。

## 实施顺序

1. **R8a3a 兑换目录配置（本次）**：独立 can_points；读取真实精选券来源，绑定发行修订和精选池修订；来源说明、积分价、每人模板累计限额、生效窗口；草稿/CAS/发布冻结/停止；同模板最多一条发布目录；永久创建回执及本机原请求恢复。仅配置，不开放兑换或改动余额。
2. **R8a3b 原子兑换**：只扣已核验账本，锁定当前账号、目录、券来源、库存和账户；同模板统计历史成功兑换，换版不重置。永久提交键/正文哈希/首次回执；扣分、扣分流水、库存、本人券、POINTS 来源与审计同事务。失败不留半笔兑换。公开领券/邀请发券限额互不混用。
3. **R8a3c 本人体验及验收**：本人目录、原始报价确认、独立未知兑换请求恢复、带扣分的流水、券入口；真实 MySQL 并发/余额不足/缺券/过期/来源变更/审计失败/越权与前端回归。

## R8a3a 细则

- 不复用 can_coupon，积分运营仅能读取已发布精选池券，不能编辑券、发券或调整精选池。服务券和金额券继承 R5 的冻结条款。
- 请求必须携带 coupon_id、publication_revision、pool_revision。创建、改草稿、发布均按门店→项目→券来源→目录锁序复核真实来源；拒绝非精选、停止、发行修订或池修订变更、来源门店或项目失效及已过期券。可为尚未开始的券提前配置；目录窗口必须包含于券的原始窗口。无库存不伪造补货，实际兑换后续另行检查。
- points_cost 和 per_owner_limit 均为 1–1000000 整数，无默认价格或限额。限额单位始终为本人＋券模板终身成功兑换数，发布后不能改，停止后另建目录也不清零历史。
- 发布后仅能停止，不允许重新打开或修改，过期发布条目须先停止才能发布下一条。数据库生成列唯一索引保护跨运营并发发布。
- 创建永久回执按创建人＋UUID 与正文哈希保存；通用 24 小时回执失效后仍返回首次草稿，不重复建目录；重试首先复核当前运营会话和独立权限。更新/发布使用 CAS。
- 本机恢复单独按运营账号隔离，不与任务配置或签到共用存储键；恢复沿用原正文和键，页面隐藏/换身份丢弃旧响应。

## 验收与边界

R8a3a 验收独立权限、来源版本/窗口、并发唯一发布、发布冻结、停止、永久创建回执和审计失败回滚；前端校验/请求恢复、微信/H5 构建、V051 真 MySQL 重放及 API/运维文档。R8a3b/c 未完成前不声明可兑换。所有 R8 成果仅本地，整 R8 完成后才统一上传代码、迁移、测试和文档。
