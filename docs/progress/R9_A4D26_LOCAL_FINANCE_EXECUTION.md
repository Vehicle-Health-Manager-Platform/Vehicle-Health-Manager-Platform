# A4d26 微信小程序本地资金记录

2026-10-23，基于A4d25提交`93145b6`，开发分支`codex/r9-a4d26-local-finance`，前置为尚未合并的PR216。用户再次明确微信小程序范围并授权每阶段完成后上传GitHub，本阶段按该范围实施。

## 实现结果

- 小程序新增`pages/operator/finance`，从运营工作区“资金记录”进入。原生日期及渠道picker；测试/正式分开查，观察时间及统计窗口用北京时间显示；异常和未成功数量可见。离页/切换选择/权限/身份即清除旧结果，迟到响应不回写。主入口仍为`pages/index/index`。
- 共用后端实现现有占位契约`GET /api/admin/reconciliation`，严格只收date、channel，复用当前有效运营身份的独立can_analytics聚合权限；仅返回全平台聚合，不返回交易或用户明细。
- 北京时间单日半开区间，当天截止观察时刻，跨日退款按退款成功日统计。金额使用BigDecimal及十进制字符串；成功事实需原订单、金额、时间、事件及同意等来源一致。损坏、缺失或未分类来源使总额为未知；上限10000条，超限拒绝而非静默截断。
- 渠道账单、净额和对账差额仍未知；本地净额不是渠道已对平、佣金或结算。无供应商请求、无资金写入、无新表或迁移，no-store读事务。
- 同步生成源、完整成功响应schema、中文契约、验收库存、覆盖索引、逐项结论与CI门禁。当前仍352项契约、316项所选四类历史证据、36项未具备完整历史证据；全API验收false。
- 结论表新增implemented-local分类记录本功能，保留缺证据事实；纠正cloud-login“没有控制器”误判为已有实现、可信正式网关待验，并复跑现有开关与登录测试。
