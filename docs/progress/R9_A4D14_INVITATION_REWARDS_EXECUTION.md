# A4d14 邀请奖励政策与发放证据阶段

## 范围与结果

2026-10-22，基于PR204的 `codex/r9-a4d13-plan-evidence` 完成本阶段，分支 `codex/r9-a4d14-invitation-rewards`。PR204核对时后端CI仍运行，已完成检查成功，不记为全量通过。

复用已有 `run_reward_acceptance.py` 和 `RealInvitationRewardJourneyTest`，强化真实旅程并把报告纳入总覆盖。新增八个原缺少所选历史四类证据的接口：奖励政策列表/创建/修改/状态、来源券列表、当前政策、车主奖励记录和商家奖励记录。邀请编码、券创建/发布/入池及券包视图为既有支撑，旅程合计14个接口、144个HTTP请求，不重复计数。

## 实施内容

- 强化分页读取：第二页必须存在数组且为空，避免只检查200。
- 增加 `reads_never_issue_rewards`：读取奖励、券包、政策和非法查询前后，批次、券发行与库存流水数量不变。
- 对已完成的车主和员工批次再次直接调用生产处理器，并等待真实调度周期，确认不重复发券。
- 保留真实审计失败触发器、整对事务回滚、冻结政策快照、来源/库存等待与恢复、员工仅奖励被邀请人、身份条件不足不奖励、隐私和ID重叠隔离等检查；共17项不变量。
- 奖励执行器声明 `CLEANUP_ROLES={'mysql'}`，只要求其实际创建的MySQL资源被移除；严格拒绝缺失、多余、非布尔或非字典清理证明。
- 覆盖汇总按可信模块声明清理范围，其他存储旅程默认仍要求原五类资源；报告自身不能放松清理要求。新增正反例验证MySQL单资源场景和原有默认拒绝行为。
- 复用现有CI的真实Java旅程、`--check-only`报告校验和Python测试，不增加重复执行任务，也未修改生产业务Java或schema。

脱敏报告：`docs/testing/reports/R9_A4D14_INVITATION_REWARDS_2026_10_22.json`。

- 144个真实HTTP请求全部通过，14个接口均有正常、边界、错误和未授权四类证据。
- 17项检查全部为真；审计失败时整对发行回滚，政策替换后重试仍用原冻结快照，库存不足不部分发放，来源停用不继续发券。
