# A4d41 微信原生真实里程识别与档案保存

2026-10-24，基线8f99a36 / PR231，分支codex/r9-a4d41-native-mileage。微信小程序及共享后端范围，不做PC开发，生产网关默认关闭。

## 实现与验收设计

仅增加页面/候选组件稳定定位标记，不增加产品调试流程。隔离构建的既有身份桥仅在开发者工具生效，普通微信包不含身份桥。新增专用--native开关，在A4d40真实模型/MinIO/网关旅程后，为独立合成车主992握手，原991网关用例不变。

原生临时文件真实上传，通过明确选图和用途同意后请求真实里程网关。第一次机器候选需要人工检查，未勾核对不能带入；取消已返回候选撤回用途同意，再识别必须重新同意。第二次识别后检查/勾选/确认带入，最后由原保存按钮创建一条档案。

候选返回、取消候选、确认带入三个节点，JVM直接检查车主992档案0条、登记里程100、CLEAN图片1条。最终核对档案仅1条、里程123456、本人图片引用、签名下载字节相同，登记里程仍100。基础80项用例的“无档案”等事实属于可选原生旅程之前的基础阶段，不扩大成整个运行期间没有档案写入。

回环代理严格限定当前合成身份的图片上传、指定车辆/文件/用途网关JSON与固定档案请求，只传原始字节，不替换模型或后端响应。网关旅程模型调用计数要求3次：原991一次、原生992两次；前置模型自检的两次推理另记。系统mock、会话、本机页面引用、代理、私有配置、服务和容器逐项记账；WeChat临时下载文件由系统管理，不声称物理删除。
