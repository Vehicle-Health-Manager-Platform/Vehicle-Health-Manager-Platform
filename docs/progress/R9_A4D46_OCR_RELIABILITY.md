# A4d46 微信小程序 OCR 可靠性补验

2026-10-26。承接 main afa7e93 和规划 PR238 / 6c6afea；本阶段只扩展隔离验收工具、测试和证据门禁，未发现需要修改生产 worker、网关或小程序候选状态机的缺陷。交付对象始终为微信小程序及共享后端。

## 实现与验收方法

扩展既有 `run_linux_mileage_acceptance.py --reliability`，默认路径不注入故障。宿主先验证本次容器标签与运行状态，再在非 root 容器中通过 pidfd 锁定 worker，复检 PID、启动时间、准确命令及 UID 后发送 STOP/KILL。STOP 必须实读停止状态；注入无正向证明即失败。没有容器获得 Docker 控制挂载，没有改动生产 8 秒推理、30 秒启动或网关 15 秒 HTTP 等待截止。

共享 JVM 测试通过本次私有目录的固定命令握手请求注入，不接受任意 PID/命令。传输超时仅暂停本次转发器的不可变容器 ID，实读 Paused 状态；超时后恢复并让废弃连接排空，下一次业务请求独立识别，不重放失败请求。OCR 仍为 internal 网络、10001 用户、只读根/模型、2 CPU、1536 MiB、swap 0、128 PID 及受限 worker。

微信 SDK3.17.2 中，代理先从真实共享网关取得 200/123456 候选，只延迟原响应字节；在取消、页面隐藏、页面离开、切换另一合成车主会话、切换表单类型之后释放，字节 SHA256 前后相同。五个场景均确认没有候选核对按钮、原里程输入框严格为空、没有档案保存请求，并以 SQL 核对。隐藏通过 navigateTo/navigateBack 触发生命周期；类型切换使用工具强制 picker 事件验证保护，普通交互在识别中本来禁用。它们是开发者工具辅助事件证据，不是手机后台/触摸验收。

## 实际结果

最终微信模式完整通过，脱敏结果见[报告](../testing/reports/R9_A4D46_OCR_RELIABILITY_2026_10_26.json)。保留原 80 项材料/工作台、12 项网关和 9 项微信原生检查，另有直接 OCR 故障、7 项网关故障/恢复请求、5 项微信在途场景。

- 直接 OCR：停止 worker 后约 8 秒返回 503；两个故障轮的并发请求均 429，立即拒绝。退出请求受控失败；两轮都替换 worker，下一真实请求识别成功，随后观察未再重建。非法 JSON 返回 422，最终真实请求仍成功。
- 网关：推理超时 8.071 秒、繁忙 0.052 秒、退出 0.518 秒、传输超时 15.057 秒，均 503/50300，不生成成功候选；三次独立恢复请求均 200、正确里程 123456、必须本人核对。8 个 SQL 检查点零提前档案/辅助材料、登记里程和原图片归属不变。
- 微信：在途五种状态均拒绝迟到候选；原 9 项明确同意、本人核对、只带入不保存和原保存旅程继续通过。共上传 6、识别 7、保存 1；8 个 SQL 节点均零提前档案、登记里程 100。最终只由原按钮保存一条 123456 且关联本人 CLEAN 图片的档案，登记里程仍 100、无辅助材料；重新进入为空。
- 网关到上游成功建立 TCP 连接 15 次，包括错误/超时连接；不冒称成功推理次数或模型内部调用数。直接探针及模型预检另计。最终恢复 worker 持续 READY、UID/seccomp 约束保持；运行前后源码摘要一致。
- 故障控制线程、宿主 JVM/原生运行器、本次业务/OCR 容器和网络均已清理，私有 env/配置/会话控制文件已删除。

小程序回归 1078/1078（新增 2 项延迟字节控制测试）；普通微信构建及原生样式/无测试身份桥门禁通过。Python 57 项审计回归通过（Linux 18、Linux/JVM 9、真实网关 14、材料 11、新故障 5）。契约生成、覆盖索引及逐项结论检查通过，仍为 353 契约、339 受保护、317 项历史四类证据、36 项登记结论；全 API 验收仍 false。没有新增 API、迁移或生产行为变更。

## 轮次与限制

首先验证直接故障加普通网关模式成功；第二轮加入网关故障与五种微信在途状态成功；第三轮按最终源码增加 15 秒传输超时及严格输入框空值断言，完整成功。前两轮仅为探针/开发证据，交付报告绑定最终第三轮源码。新增临时目录测试首次在沙箱遇到权限错误，本机授权环境重跑通过。两次辅助命令误用了不存在的额外检查脚本名称，已改用仓库现有门禁及 `summarize_api_coverage.py --check`，没有将错误命令计为成功。
