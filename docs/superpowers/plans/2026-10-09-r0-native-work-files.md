# R0.1b2b 微信原生文件、防护、报工与签字计划

日期：2026-10-09。依赖 #71 / `07705bc`，沿用已确认原生验收设计，仅微信小程序及必要后端。

## 实施范围

1. 复用 b2a 隔离来源准备，创建独立合成订单；真实测试付款和七图接车、确认/派工/接单作为 HTTP 准备，明确未真实扣款，不冒充本阶段原生操作。
2. 微信工具内创建命名合成 PNG 本地文件，官方 chooseMedia/chooseImage 结果辅助选择该文件。原生页面按钮触发真实 wx.uploadFile→后端扫描→对象存储；不替换上传、请求或业务响应。选择器实际点击、相机仍待独立验收。
3. 无防护时原生技师页面不能报工；商家勾选必需防护项，上传真实文件并提交；取消系统回调不入库，确认后入库、刷新可读。
4. 本人技师上传施工/完工照片、填方案/分析/工时、明确无故障件/无配件，提交完整报工。原生表单和真实数据库核对。
5. 实际画布空白不能上传；用原生触摸事件绘制合成测试笔迹，真实 canvasToTempFilePath 生成 PNG、读取大小、上传、扫描，确认后进入待核销。不是实际人员手写签名，也不算真机。
6. 本店商家和本人技师读取结果；他店/未派技师不能读取证据。私有签名链接获取与图片实际渲染分开记录，测试证书失败不关闭正式 TLS 校验。
7. 复用 b2a 的系统 showModal 结果辅助，当前弹窗实际点击未通过；checkbox 使用原生 change 事件。清理选择/弹窗 mock、内存身份、短会话及命名本地测试文件，保留隔离审计。
