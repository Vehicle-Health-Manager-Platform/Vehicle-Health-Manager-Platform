# B1a 微信云开发开通与部署准备

用户决定：微信云开发作为后续接入方向，短信后续再做；2026-10-26确认环境尚未开通。本阶段交付可执行准备与本地检查，不执行账号开通、付费、云部署或正式身份验收。交付对象是微信小程序及现有共享后端。

## 技术路径

推荐云托管承载现有Java17/Spring Boot容器，MySQL继续使用容器外的受控实例和现有版本迁移；小程序复用callContainer和既有云登录入口。官方[云托管概述](https://docs.cloudbase.net/run/introduction)说明其支持Java容器及VPC访问MySQL。具体环境必须实测是否支持项目所需的微信托管调用和可信身份头，不能仅凭“CloudBase环境已创建”开启信任。

云函数适合补充事件/定时任务；将所有Java业务和MySQL事务迁往云函数/文档数据库或PG会产生额外迁移、兼容和验收工作，本阶段不实施此替换。现有MinIO签名/扫描流程也不能因启用云存储而自动视为完成，私有文件存储适配单独推进。

## 开通顺序

1. 由持有该小程序管理权限的账号打开微信开发者工具，确认当前AppID和主体后进入“云开发”。按[官方环境创建说明](https://docs.cloudbase.net/quick-start/create-env)完成服务条款与角色授权，优先创建隔离测试环境。当前不创建生产环境，不预设免费资格或费用；资源和套餐以控制台实际能力、预算和授权为准。
2. 在控制台核对云托管功能、可用地域、目标小程序授权与私有调用能力。记录EnvId、地域和后续服务名；这些标识可用于配置，服务端密钥不进入聊天或仓库。若选定产品不支持callContainer/可信身份注入，则保留现有云登录开关关闭，先修订接入方案。
3. 准备同地域/VPC内可达的外部MySQL，限定最小数据库权限，按docs/sql/migrations当前版本顺序部署并核对迁移记录、备份和恢复路径。不能把云开发自带文档/PG库填进MYSQL_HOST，也不能沿用Compose服务名mysql/localhost。
4. 使用仓库根目录为构建上下文，`deploy/cloudrun/Dockerfile`构建Java后端；服务监听端口与SERVER_PORT保持一致。首次部署仅健康与身份必要配置，上传/正式支付/短信等未验收功能不凭准备检查自动启用。
5. 先核对目标服务仅能经受信微信链路访问，公网不能直接伪造X-WX身份头，再按受控配置开启WECHAT_CLOUD_RUN_ENABLED。CLI中的“private gateway declared”只核对本地声明，不替代控制台检查和真实公网负向请求。
6. 小程序构建指定同一EnvId与服务名，核对源码manifest中的AppID与后端一致。保留现有正式包无测试身份桥门禁；首次真实联调由车主/技师开始，商家/运营短信登录继续保持未接入，不使用固定码或测试身份绕过。

## 已实施的配置预检

扩展现有`scripts/check-wechat-identity-readiness.mjs`，保留原R0检查模式，增加显式云部署模式：

```powershell
node scripts/check-wechat-identity-readiness.mjs --cloud-deployment --env-file deploy/cloudrun/env.example --miniapp-env-file apps/miniapp/.env.example --deployment-file deploy/cloudrun/deployment.example.json
```

模板执行预期为configurationReady=false、cloudDeployed=false、formalIdentityAccepted=false，退出码2表示成功生成待验报告；1表示读取/JSON/参数错误，0仅帮助。使用真实配置时复制为受忽略的*.local文件并私下填写；三个输入显式隔离，不继承其他进程凭据。部署声明只支持固定schema，不接受任意字段。

检查范围：后端云开关、MySQL/JWT/微信字段状态，外部数据库地址，前后端/部署声明的环境与服务一致性，实际源码AppID一致性，以及公网关闭/微信可信网关的本地声明。只输出固定检查项与状态，不输出值、文件路径、账号、EnvId或异常内容。

云登录可不使用AppSecret，但现有手机号绑定客户端仍需服务端AppSecret及正式手机号权限；预检分开记录两者。无论字段是否齐备，始终保留环境归属、调用兼容、真正公网隔离、数据库迁移、真实身份/手机号、文件存储和iOS/Android验收待办。

## 后续分阶段推进

- B1b：云环境和MySQL就绪后，验证云托管健康、真实微信车主/技师登录、员工绑定、刷新/退出与跨归属拒绝，保留真实环境版本和脱敏证据。
- B1c：具备微信手机号权限后实测绑定、拒绝、凭证重放与归属核对。短信后接，届时恢复商家/受限运营的正式短信验收，不删除该交付范围。
- 云存储阶段：选定私有对象存储/云存储后适配受控直传、扫描、归属、签名访问及撤回；保留既有用途同意/本人核对/档案保存边界。
- B2–B6及C阶段仍覆盖正式支付退款/对账、录车OCR/VIN、材料/AI/知识、消息分享、500并发性能和手机/发布门禁。云平台能力可承载实现，不能替代商户权限、内容授权或手机实测。

## B1a退出条件

配置预检负向与隐私回归通过、普通及云通道微信构建通过且无测试身份桥、源绑定交付索引一致、开通清单与实际未完成项明确；上传独立GitHub PR并核对head CI。由于环境尚未开通，本阶段不宣称B1正式身份接入完成，也不把测试声明当成真实云端证据。
