# R0.1b3 私有图片原生预览与工具交互计划

日期：2026-10-10；依赖 #73 / `c60674e`，沿用已确认的微信原生验收设计与下一步安排。

## 实施

1. 核对当前本机公钥证书有效期与回环 SAN、下载端口及后端签名原点。若下载服务未运行，仅启动既有回环 TLS helper；旧私钥缺失时在忽略目录生成独立短期本机证书，不覆盖旧证书，不写入系统信任库、不关闭 TLS 验证。只停止本任务启动的进程。
2. 导出既有核销/评价/档案执行函数，保留独立 CLI；新建独立合成来源，前序检查单列。
3. 评价图片、施工档案图片与 PNG 签名分别验证授权、显式信任本机公钥的实际 HTTPS 下载、微信 getImageInfo 解码，以及页面真实预览按钮。签名视觉截图确认合成笔迹；成功回调与实际视觉结果分别记录。
4. 尝试当前官方 SDK 的系统弹窗确认/取消，读取真实回调并记录成功或具体未支持证据；不以 RPC 空结果作为点击成功。选择器只验证实际支持的工具能力，不增加固定业务响应 mock 来冒充真实选择。
5. 当前隔离构建用于本机 HTTP 业务准备的 URL 校验例外必须单列；即使图片在此模式可显示，也不算正式域名/TLS/手机真机验收。来源身份、私有链接和截图只留忽略目录。
6. 清理原生测试身份、短会话、mock、源文件及本阶段运行时探针；关闭本项目并移除临时 URL 例外。服务器合成来源/审计保留。

## 收口

中文执行/验收及最新进度、缺口、下一步。小程序回归、正式微信/H5 构建和无身份桥检查；上传 `codex/r0-native-preview`，堆叠 base 为尚未合并 `codex/r0-native-completion`，等待最终六项 CI。只上传，不合并/部署。

如果原生工具不支持实际点击或当前证书不能直接预览，如实交付失败提示与可重复诊断，不宣称全部通过。正式短信/员工绑定、正式公网域名证书、授权 iOS/Android 真机继续独立推进；PC 运营后台取消。
