# A7.1 中文实施计划

基线与规格见 [核销规格](../specs/2026-10-09-a7-redeem-design.md)。各阶段验证后更新执行记录、提交推送并创建 PR；未合并时后续 PR 使用前阶段分支为 base，合并按顺序改回 main。

1. **规格与现状**：更新 A4–A6 实际合并状态；规格自审、界定 A7.1 与后续范围；上传规格阶段。
2. **核销后端**：V015 不可修改核销记录；复用 A6 证据检查，可信付款与测试隔离；事务独立防猜额度、幂等、双审计、读权限；封堵通用 COMPLETE；登记 OpenAPI/接口与 SQL 重放清单。真实 MySQL、HTTP 及已有回归验证后上传。
3. **小程序**：商家验码页、详情入口、车主码展示与核销结果；独立会话/生命周期/原键重试、敏感码清理、测试提示。小程序测试与微信/H5 构建后上传。
4. **联调收口**：真实 HTTP 闭环及拒绝矩阵、gstack H5 实际交互（使用明确的合成测试身份）；完整 CI；更新验收/阶段总结/下一步规划后上传。

失败先修复再收口；CI 尚未结束只记录待验证，不宣称通过。正式收款、真机与直连图片预览依赖不作为本地测试通过的结论。
