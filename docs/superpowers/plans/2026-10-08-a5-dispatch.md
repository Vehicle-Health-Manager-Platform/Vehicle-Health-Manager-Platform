## A5.2：后端与数据库

### 身份和锁

- 在 `backend/src/main/java/com/autocare/platform/order/` 新增严格 `TechnicianActor` 或共享身份包的等价类型；校验 JWT subject/type/role/jti/AppID/binding/merchant/expiry，拒绝绑定凭证。
- `ReservationStore` 增加技师会话数据库复核：全部身份字段一致、会话未撤销未到期、员工/绑定/商家有效；读取也复核，写入及缓存命中带锁。
- 复核并调整 `gateway/identity/JdbcIdentityRepository.bindTechnician` 与 `StaffCodeOperations`：统一商家→技师员工→绑定，定位信息先读、锁后再检查。保留解绑历史、员工码安全规则和已有身份用例。
- 新服务保持商家→时段→订单→派工→接车单→幂等记录顺序，与现有预约/到期/接车/车主决定一致。不得把本人技师员工锁放到商家锁之前而造成反向等待。

### 迁移和服务

- 新建 `docs/sql/migrations/V012__technician_dispatch.sql`，加派工 `assigned_by`、`accepted_at`；可重复执行、50 表不变，保留订单唯一键和 V001。
- 更新 `deploy/compose/compose.yml` 挂载、`scripts/verify_mysql_schema.sh` 新列/重复执行检查、`docs/sql/SCHEMA.md`。真实数据库用例覆盖旧行和异常值；先盘点备份再迁移，不自动补证据或覆盖历史派工。
- 新增 `TechnicianAssignments` 服务与对应商家/技师 Controller，在 `ReservationConfiguration` 按现有数据库条件注册，实现契约的六个接口。
- 复用 `WriteIntegrityService`：授权与资源锁在幂等记录之前，状态在实际变更回调检查；派工一次成功审计，接单订单迁移与通用审计同事务。
- 服务端读取完整接车/确认/派工记录计算 `can_accept`，写入再次复核，不只信任时间列或前端状态。
- 同时修改 `MerchantOrdersController` 拒绝通用 START_SERVICE（43004），`OrderStatus.actions` 移除其投影，保留状态矩阵和内部映射；同步已实现接口文档、前端旧按钮/测试基线，避免接单被绕过。

## A5.5：本机联调与收口

A5.2–A5.4 已用 Testcontainers 与替身证明协议、权限、幂等、竞争和回滚，但都是**进程内服务层或 MockMvc**：真实 JWT 校验链（签名、`app_id`、`binding_id`、会话吊销）、Spring 安全过滤器、真实容器与真实本机 MySQL 从未在同一条链路上跑通。A5.5 补这一段，并完成 A5 收口。

新增 `docs/testing/LOCAL_TECHNICIAN_DISPATCH_ACCEPTANCE.md`，本机脚本驱动**真实后端容器 + 真实隔离 MySQL**。合成车主、商家、两名本店技师（同一 `merchant_id`）与另一店技师/商家的会话由本机脚本用 `JWT_SECRET` 铸 JWT 并写 `auth_session` 铸造，属§4 明示的**测试桥接**，与真实微信/短信登录、真机页面分开计，不写成真实登录通过。

| 会话 | 来源 | 用途 |
| --- | --- | --- |
| 合成车主 | 铸 `user` 会话 | 建单、支付桩、接车、车主确认（走 A3/A4 真实接口） |
| 合成商家（本店） | 铸 `staff_account/MERCHANT` 会话 | 候选查询、派工、派工详情 |
| 合成技师甲/乙（本店） | 铸 `staff_account/TECHNICIAN` 会话 + 当前 AppID 有效绑定 | 本人列表/详情/接单；乙用于「另一技师拒绝」 |
| 另一店商家/技师 | 铸他店 `merchant_id` 会话 | 跨店归属与不可见拒绝 |

| 用例 | 覆盖 | 断言要点 |
