# A2 订单履约状态机实施与收口计划

日期：2026-10-07。依据：[已确认履约规格](../specs/2026-10-07-fulfillment-state-design.md)。

## 交付边界

交付八种订单状态、服务端动作矩阵、商家操作入口、同事务迁移审计与幂等。接车单、车主确认、派工、报工、核销由后续步骤提供；证据缺失时明确拒绝操作。真实支付和真机验收仍单独记录。

## 执行顺序

1. 合并六项 CI 已通过的规格 PR #32，确认 A2 PR 的目标为 main。
2. 审阅状态迁移、锁顺序、身份与店铺隔离、重复动作及失败回滚。修正重复动作多写审计、前端空备注拦截、新建 Compose 漏装 V009。
3. 补共用写入服务回归：明确无状态变化可缓存响应而不再写成功审计；声明状态发生变化却跳过审计时整体回滚。
4. 本机执行小程序测试、状态矩阵与 HTTP 契约测试、双端构建；完整 MySQL 并发与触发器回滚由 GitHub CI 执行。
5. 本机仅在隔离测试数据库应用 V009，保留既有数据卷、私有配置和局域网端口。升级运行镜像并用真实接口验证缺接车证据仍返回 43001、订单保持 PAID。
6. 用 gstack browse 操作 H5 商家订单详情，确认按钮实际发出请求、业务拒绝正确显示；不得给运行库伪造接车时间来演示成功。
7. 更新执行记录及下一步规划，提交 A2 PR。六项 CI 对应最终提交全部通过后合并，核对主分支。
8. 进入 A3 接车检查设计：手填里程、七张照片、商家图片归属与短时访问、验预约码、接车单事务。书面规格确认后再编码。

## 验收要求

- 非法跨状态操作、其他店铺、撤销身份、前置缺失均无状态变化和成功审计。
- 相同幂等键返回原响应；新键重复已完成动作返回 changed=false，不新增两类成功审计。
- 状态迁移、迁移审计、业务审计、响应缓存任何一步失败均回滚。
- 已接车后仍占预约名额。测试夹具仅证明状态机能力，不计作真实接车验收。
- 新数据卷自动安装 V009；旧数据卷须显式补迁移。
