# R0.1b2a 微信原生确认、派工与本人接单计划

日期：2026-10-09。依赖 #70 / `87dace4`，沿用已确认的 [原生验收设计](../specs/2026-10-09-wechat-native-acceptance-design.md)。本单元实施微信小程序，PC 已取消。

## 拆分与取舍

履约后半段依赖原生选图/防护照片/签字。先完成不依赖工具文件选择的确认→派工→本人接单，再做文件与防护/报工，最后核销/评价/档案。七图接车用真实 HTTP 上传和提交准备；不记为接车页面上传验收。

## 本阶段

1. 独立测试构建及内存身份桥沿用 b1；普通微信产物无桥门禁保留。
2. 新建命名合成账号、独立订单；先核对本机容器、V019/61表、回环地址、运行 JAR 与测试支付配置。订单使用真实 LOCAL_TEST 付款回调（未真实扣款）和七张经真实扫描的 PNG 准备。
3. 商家原生页面读取本店订单/测试标识；车主未确认时实际派工被拒且数据库无派工。
4. 车主原生确认接车单；取消确认不写入，确认成功写数据库。
5. 商家选择本店已绑定技师；取消派工不写入，确认派工后页面/数据库一致。
6. 他店商家和未被派工技师不能查看目标详情；被派技师本人取消接单不改变状态，确认后进入施工中；刷新后原生页面仍正确。
7. 所有按钮/系统弹窗操作如实记录工具支持方式；不替换业务请求响应或直接调用页面方法。系统弹窗不能实际操控时记录边界，不宣称手指交互通过。
8. 成功/失败均清空本次内存身份、注销短会话；保留隔离测试审计，凭据与报告只在忽略目录。

### 工具核验后的调整

当前工具 `Tool.native` 返回空结果却不关闭弹窗，`Tool.invokeNativeMethod` 返回等待 automator 响应超时。为继续验证页面业务，采用官方 `App.mockWxMethod('showModal', result)` **只提供系统确认/取消结果**，随后原生按钮处理与 HTTP/数据库仍真实执行，结束恢复方法。实际弹窗按钮点击未通过，不作为本单元完成条件；保留为独立待验收项。旧 `App.evaluate` 不受支持不代表 SDK evaluate 不受支持：官方 SDK 使用 `App.callFunction`，本次纯函数探测返回 4；本阶段仍沿用隔离身份桥，未扩展正式包入口。

## 收口

脱敏原生报告、中文验收/执行/缺口与下一步更新、小程序测试及普通微信构建通过；提交推送 `codex/r0-native-dispatch`，PR base 指向未合并的 `codex/r0-native-publication`，确认最终六项 CI。仅上传，不合并/部署。

本单元完成不等于完整 R0：原生接车上传、防护/完整报工/签字、核销/评价/档案后半段、正式短信和手机仍待后续验收。
