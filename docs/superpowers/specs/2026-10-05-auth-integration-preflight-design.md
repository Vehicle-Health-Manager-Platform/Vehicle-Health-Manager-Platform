# S0 真实登录联调预检与验收清单

日期：2026-10-05。基线为已合并 PR #12–#16 的 `main`。现有车主、技师与商家身份接口已通过自动化测试；本地和仓库没有可供真实微信登录联调的测试部署或私有配置证据。用户选择先交付可执行的联调预检与验收清单。

## 目标与方案

联调人员拿到测试后端地址后，先运行一个只读命令判断外部入口是否满足最基础的网络与认证契约，再依照清单完成环境和逐角色验收，并记录脱敏证据。比较三种做法：① 仅写人工清单，无法快速重复核验入口；② 编写无凭据的只读预检脚本并配人工清单，可重复执行且不接触秘密；③ 自动执行真实微信登录，需要账号、动态验证码和私有密钥，当前环境不具备。采用②。

## 可执行预检

新增 `scripts/check_auth_readiness.py`，使用 Python 标准库，接受唯一必填参数 `--base-url`。只允许带主机名的 HTTPS 原点 URL，可含显式端口和一个尾随斜杠；拒绝路径、查询、片段及 URL 内嵌用户名或密码。脚本依次请求 `GET /actuator/health` 和不带任何凭证的 `GET /api/vehicle/list`，每个请求有有限超时，使用系统证书验证 TLS，任何重定向均视为失败。健康检查须为 HTTP 200 且 JSON `status=UP`；匿名车辆列表须为 HTTP 401 且 JSON `code=40100`。输出每项通过或失败及无敏感数据的原因；任一失败以非零状态退出。网络、证书、超时、非 JSON、错误状态和重定向均按失败处理。脚本不接收账号、令牌、密钥，不调用登录、写入或发送验证码接口，也不输出响应体或请求头。

预检只证实从运行脚本的机器到测试入口的 TLS、健康接口和匿名保护；不能证实小程序合法域名、真机网络、数据库迁移、微信 `code2Session`、手机号授权或短信送达。

## 人工验收文档

新增 `docs/operations/AUTH_INTEGRATION_RUNBOOK.md`：列出环境负责人须在私有配置中核对的 HTTPS/合法域名、V002/V003 数据库迁移、微信 AppID 与轮换后 AppSecret、JWT 密钥、可用微信测试账号和手机号能力；商家短信服务商与发送器独立列为商家验收前置条件。文档只记录“已核实/待确认”、验证人、日期和脱敏证据，不记录秘密值、手机号、验证码或令牌。

验收矩阵覆盖车主首次和重复登录、微信手机号绑定、技师未绑定与绑定、角色隔离、访问令牌刷新与旧刷新令牌拒绝、退出后会话失效；商家覆盖验证码送达、一次性消费、过期、错误码与限流，并明确短信通道未实现前保持阻塞。每项写明操作、预期结果、证据与失败记录方式。只有真实环境操作完成才可标为通过；自动化测试和本脚本不得代替真机与真实微信结果。

## 验证和交付

为 URL 解析、健康响应、匿名 401、重定向及网络失败编写离线单元测试，通过可注入的请求函数模拟响应，不依赖真实后端。运行测试与 CLI 的无效地址负例，更新运维文档入口和 S0 依赖/进度说明。提交独立 PR；环境未到位时保留真实登录联调为待验收，不宣称登录完成。
