# 剩余履约接口验收设计

最新工作区已包含 A4d9–A4d11，PR202 八项CI成功，所选历史四类证据覆盖267/352项。本阶段基于实际剩余清单补齐十个接口：商家时段列表及关闭、车主可约时段与订单列表、商家技师列表及派工详情、商家和车主施工详情、商家和车主核销凭证。

复用现有预约到归档的真实HTTP链，在支付前、派工后、签字后、核销后插入状态读取。相比仅SQL插入终态，可以验证当前身份和状态投影；相比重复私有附件旅程，本方案针对尚未覆盖的列表、凭证和关闭语义。时段在订单履约完成后关闭，验证关闭不篡改已完成订单，并从可约列表消失。

每个新增接口具备正常、边界、错误、未授权四类用例；增加跨车主/门店、空页、未核销空凭证、非法分页/日期/ID、关闭幂等和同键变更意图。运行器使用独立数据库与LOCAL_TEST支付；图片仍为数据库元数据夹具。日期从隔离种子实际生成的时段取得，证据审计将真实查询绑定到该日期，避免运行时间漂移或伪造分页。

验证完整履约终态、唯一记录、唯一时段关闭审计和签名支付回调，生成默认关闭的Postman资产并接入CI和历史证据汇总；保留全量API验收false。完成后推送基于PR202的草稿PR。未验证外部资金、真实身份、文件上传、真机和生产环境。
