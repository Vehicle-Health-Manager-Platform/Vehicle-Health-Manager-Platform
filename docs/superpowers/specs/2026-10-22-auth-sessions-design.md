# 认证会话轮换与退出验收

按用户授权继续规划并实施，复用隔离MySQL/真实HTTP/Newman；目标为刷新、业务退出、运营退出3接口，车辆列表为存活支撑。相较真实微信/短信接入，这里直接准备明确合成身份和会话，只验服务端凭证处理，不扩大为真实登录验收。

轮换成功后旧refresh不可再用，新凭证绑定原subject/role/app/jti，900秒access；旧access可继续到退出。失效/过期/错应用/停用车主或员工的refresh被拒，并且事务回滚不改原哈希。运营独立会话不能通过普通刷新或普通退出，独立退出要求空JSON及无查询。

退出后原始及轮换访问凭证、refresh均不可用，另一车主会话保持可用。用Barrier同步两请求刷新同一独立凭证，只能一成功一401，再验证赢家凭证及退出失效。

刷新响应产生的动态凭证需从真实私有执行结果提取、校验HS256签名和会话声明，逐条匹配后续正文/身份。归档只含用例结果、哈希及布尔证明，不含令牌、刷新值、秘密或私有执行报告。严格元数据/正文/角色/状态与清理证明，CI和历史汇总接入后阶段上传草稿PR，不自动合并。
