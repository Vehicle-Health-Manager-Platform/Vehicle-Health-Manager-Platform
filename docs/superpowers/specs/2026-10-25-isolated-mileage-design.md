# A4d43 隔离OCR接入微信验收链路

用户已要求规划后直接实施，并逐阶段上传GitHub。基线430ba21 / 草稿PR233，范围仅微信小程序与共享后端，生产OCR默认关闭。

选择复用已有真实模型/MinIO/共享网关和微信原生旅程，仅替换验收中的进程内ObservedEngine为生产ProcessRecognizer。另建整套工具会重复鉴权/存储/SQL验证；只做私有HTTP自检则不能证明网关和原生保存链路。本阶段采用第一种方案，不改公共契约和页面行为。

运行前自检改为isolated_check：固定模型在独立子进程经私有HTTP识别两次、错误JSON不重载并完整关闭。旅程另外创建独立worker，仅在父进程统计原始请求委托次数及是否复用同一子进程，不在父进程解码图片、不替换请求或响应、不把委托次数称为模型内部调用次数。

旅程必须保持12项网关与80项材料/工作台HTTP证据；微信可选模式仍要求9项原生检查、候选/取消/带入三个SQL检查点零档案、原保存按钮最终只写一条正确档案，登记里程100不变。网关模式恰好1次worker请求，微信模式恰好3次（基础1+原生2），拒绝请求不得进入worker；预检两次单独计数。两种模式均须验证真实进程隔离、固定截止、同一预热进程复用、服务/worker及容器清理，否则不通过。

故障恢复沿用A4d42真实OS进程与HTTP回归，本阶段不声称已执行网关在途崩溃的微信交互。合成图片/身份/ClamAV签名以及选图、switch/input辅助均明确标识，不扩大为真实仪表、手机权限、正式微信身份或Linux容器验收。

源码/报告审计和开关负向回归通过后，执行真实隔离模型+JVM旅程及微信旅程，再检查普通微信包无身份桥、交接/覆盖结论与清理。交付草稿PR依赖PR233，不合并部署。自审：无待定接口，不新增正式凭据或图像日志，观测只保留数量/布尔/资源限制和源码摘要。

实施中补充：两轮原生在业务前导航失败，经逐步探针和单变量对照，同一包3.17.4返回pageNotFound属性错误，3.17.2成功。仅隔离项目固定3.17.2，原生报告与审计增加SDK版本必备证据；CI增加14项运行器审计。普通产品包SDK配置保持既有值，不将本机对照扩展为普遍版本结论。
