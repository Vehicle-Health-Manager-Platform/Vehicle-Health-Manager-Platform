# A4d44 Linux OCR镜像与出口约束

2026-10-25，基线782daa5 / PR234八项CI成功。范围为微信小程序共享OCR基础设施，用户已要求规划后实施及阶段上传，不合并部署。

普通Dockerfile仍服务默认关闭场景。另建显式启用的Linux CPU推理镜像及Compose覆盖，固定Linux依赖和模型摘要、非root、只读根与模型、2 CPU/1536MiB/128 PID/64MiB临时空间。启动先验证模型及依赖，缺失或摘要错误不监听HTTP。Windows锁不用于Linux，模型不在推理时下载。

采用两层网络约束：OCR仅加入internal桥接网络，后端保留默认网络并连接该私有网络；模型子进程在初始化引擎前加载Linux libseccomp规则，拒绝socket/connect等网络调用。仅internal网络不能证明宿主机服务不可访问，故不把其当完整沙箱；父HTTP服务需保留监听能力，子进程依旧使用既有有界管道、硬截止与父死亡清理。规则缺库/装载失败或请求的策略不支持时启动失败，不降级。

与只改网络相比，子进程策略能直接阻止第三方模型库网络访问；与把宿主机直接推理当镜像验收相比，独立镜像/受限容器保留Linux真实部署证据。固定离线模型准备与容器启动分开，构建需要网络，运行不依赖外部模型仓库。

验收以实际结果为准：构建固定依赖镜像；校验Compose资源/网络并实际inspect；私有网络内客户端健康及两次真实合成里程图推理、未授权拒绝、同worker复用和无写库；真实Linux进程套件及seccomp正反向探针；外部控制服务正向可达、OCR内部网络反向不可达。拒绝推理容器提权或挂Docker socket。所有自有容器/网络/控制文件清理，失败轮次和拉取阻塞如实记录。

若官方基础镜像或依赖拉取仍受阻，完成代码、配置及可运行的Linux策略测试，记录尚未得到的镜像/模型容器证据，不替换来源冒充通过。真实仪表、手机和生产上线不属本阶段已验范围。自审：无待定接口、无产品凭据写入仓库、无原图日志，不把配置或替身测试冒充真实模型。
