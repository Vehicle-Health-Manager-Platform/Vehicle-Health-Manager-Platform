# S1 首页本人车辆与档案摘要

日期：2026-10-04。用户确认在 PR #15 基线上先交付 F04 中可由真实车辆和档案数据支持的首页内容。

## 范围与依据

首页显示本人车辆选择、当前车辆的车型和脱敏车牌、当前里程、手动档案记录数及最近一条记录。用户可从首页进入所选车辆的档案 Tab，并在两页看到同一当前车辆。无车辆、无记录、加载、失败、重试和账号切换均有明确状态。健康评分、指标、五类提醒、券与邀请、同款车友经验依赖尚未确定的规则或数据源，本步不显示推测值。

比较三种方案：① 前端组合已验证的 `GET /api/vehicle/list` 与 `GET /api/archive/list`，无需重复读接口；② 新建首页聚合接口，未来适合承载评分和提醒，但当前只会复制已有查询；③ 从本地缓存展示，不能保证记录最新。采用①。首页摘要只读，不新增数据库迁移、写接口或业务审计。

## 状态与数据流

新增车主内存车辆选择模块，保存当前车辆的列表响应对象（只含脱敏标识），与 `ownerSession.accessToken` 生命周期绑定。身份变化立即清空选择；不写入持久化存储。首页和档案 Tab 复用此选择。选择车辆后立即清空前车摘要，并以所选 `vehicle_id` 请求档案第一页；使用服务端 `total` 作为记录数，第一页第一项为最近记录。切换车辆、切换身份或页面隐藏时，迟到响应不能覆盖当前页。每次首页显示都重新请求；档案 Tab 显示时也重新查询所选车辆。

车辆选择复用 `VehicleList` 的服务端分页和失败重试。首次列表有车且无选择时默认选第一辆；选择在后续页的车辆后，刷新第一页不能悄悄改回第一辆。若所选车辆被删除，档案查询返回 404，显示可恢复的提示并允许重新选择车辆。跨身份不会复用上一车主的选择或摘要。

## 页面与验证

首页保留五 Tab 车主壳，车辆列表和摘要由真实接口驱动；最近记录显示类型、日期、标题，可点“查看完整档案”切换 Tab。空车状态引导手动添加车辆，空记录状态引导进入档案录入。失败时提供重试或重新登录，错误文案沿用既有 API 客户端的安全提示。不显示原始 VIN/车牌或带签名图片 URL。

离线测试验证默认选择、多页车辆选择保持、多车切换、摘要服务端总数、空记录、失败重试、身份切换和迟到响应。运行小程序/H5 构建及 CI。H5 实际交互与微信模拟器在工具可用时单独复核；构建和替身测试不计作真实微信或私有环境联调。PR 以 #15 为基线，合并顺序接在 #15 后。
