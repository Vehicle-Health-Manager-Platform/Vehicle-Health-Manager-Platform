# R0.2a 微信身份配置检查规格

用户确认：短信服务尚未开通。范围仅微信小程序和必要后端。

选择只读离线检查：相比现在指定供应商编写适配，可先整理实际依赖；相比直接尝试短信登录，不依赖未开通服务。沿用已有 R0 正式身份路线，提供服务端配置缺项报告及开通后的实施顺序。

## 输入、输出及边界

- Node 22+ CLI，默认读取当前进程环境，`--env-file` 显式文件独立解析、不与进程环境合并。
- 输出仅固定字段名称、缺失/占位/格式状态和固定待验收项。不得输出配置值、手机号、令牌、文件路径或底层异常。
- 检查 MySQL 四项、JWT 至少 32 UTF-8 字节、微信 AppID 格式及云托管开关。直连换码需要 AppSecret；云托管选定路径不需要换码密钥，但关闭公网访问必须单独实证。不能据此声称直连端点可用。
- `configurationComplete` 仅表示本检查的静态规则满足；数据库连接、官方微信换码、真实员工绑定、短信登录未验证。`formalIdentityAccepted` 固定 false。
- 当前代码没有正式短信 sender 实现，`SMS_PROVIDER` 不能激活发送器。服务尚未开通记录为本阶段事实，供应商接入时需更新检查器。
- 无网络、数据库写入、验证码发送、员工码签发/轮换，也不新增 HTTP 或小程序登录捷径。
- 退出码 0 为帮助，1 为参数/读取错误，2 为输出待完成正式验收报告（包括静态配置全部满足时）。

## 验收

验证缺项、完整配置仍未正式验收、云/直连差异、非法配置、UTF-8 字节规则、供应商字段无效、无敏感输出、显式文件隔离和固定错误。纳入现有小程序测试 CI，中文记录模板检查结果。此规格自身已核对范围、输出与实际后端规则一致，无供应商参数占位实现。
