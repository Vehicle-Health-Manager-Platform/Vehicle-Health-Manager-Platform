# A4d-5 接口验收覆盖核对设计

用户要求继续规划、实施并逐阶段上传。上阶段退款页PR195仍独立等待CI；本阶段从origin/main创建独立分支，不依赖或改写其代码。

## 方案

采用自动核对工具，而非人工维护完成数：从当前OpenAPI得到唯一操作，核对16套Postman清单/集合/历史报告和3套专用HTTP旅程，输出确定性的JSON与可阅读缺口清单。重跑全部业务旅程会消耗较长时间且仍不能指出覆盖盲区，本阶段先建立准确总表，后续再按缺口补用例并执行。

本阶段交付的是核对工具及覆盖缺口，不是新业务接口或全API通过证明。当前执行状态始终NOT_RUN，全量验收标志始终false；历史证据保留记录来源与哈希、明确未复跑当前后端。匿名401不折算正常/边界/异常/归属验收。

## 核对规则

- 当前契约按方法及路径唯一标识，兼容已有确定性生成operationId。未知ID、错误方法/路径、重复用例、无效分类和统计不一致均拒绝。
- Postman定义与集合逐项对齐；历史报告必须通过、源码在原执行期间稳定、清理成功、集合哈希相符；已执行案例与清单名称/分类/状态完整对应，汇总分类及请求/断言数量一致。
- 专用HTTP报告按现有runner的inventory函数核对方法/完整路径/状态/角色及名称；核对检查与资源清理均成功、请求数量和分类汇总一致。只导入其定义，不启动容器或执行外部调用。
- 同一接口在多套验证中的证据保留来源，统计按接口去重；缺少报告保留已设计状态，损坏或不匹配的已选报告使工具失败。
- 输出仅包含接口元信息、统计、来源相对路径与哈希，不复制token、原始HTTP正文、私有URL或SQL。输出固定排序，无动态时间戳，支持--check检查版本内报告漂移。
- 跨平台输入指纹统一CRLF到LF；历史集合原始哈希只接受同一当前内容的LF或CRLF字节表示。换行差异不误报，正文变化仍拒绝；用模拟Linux/Windows文件树验证相同输出。

## 实施与验收

1. 实现汇总与严格校验、历史/设计/当前执行分层。
2. 用合成小数据测试去重、匿名不算业务、缺失报告、失败/重复/缺失案例、哈希漂移、未知操作、错误路由/方法、错统计和专用旅程校验。
3. 对仓库真实19套输入执行，生成每接口缺口及领域分组；建立CI重现/漂移门禁。
4. 运行相关脚本测试、语法检查及CI改动审查，不重跑未变化的前端/后端业务并冒称本次通过。
5. 更新执行报告、后续补测顺序并提交推送独立GitHub分支/PR。真实渠道、性能、安全和设备验收保留后续阶段。
