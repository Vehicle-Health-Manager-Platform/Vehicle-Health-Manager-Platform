# R2a 订单完成事件可靠归档规格

日期：2026-10-11。用户已授权按下一步规划开始实施；承接 R1c #89，微信小程序及必要后端。正式身份与真实资金留 R9。

## 方案与范围

选择复用 service_archive_job：核销完成事务入队，后台独立事务生成档案。同步生成会把附件/归档失败耦合到核销；新增独立队列会重复唯一性和恢复逻辑，均不采用。R2 分为 R2a 完成归档、R2b 支付契约/取消退款、R2c 佣金台账与冲销。本轮只实现 R2a，不制定或编码未确认的资金取消窗口。

## 冻结规则

- 新核销完成事务同时写完成状态、核销凭据、状态流水、审计、幂等与归档任务；任务入队失败则整次完成回滚。无评价也入队。重复核销/并发消费只产生一份档案。
- 复用可信付款/核销、唯一已签提交报工、安全照片、车辆归属校验；缺来源不伪造，任务保持可恢复。消费成功才标记 DONE，失败档案/附件/审计整体回滚。默认 SERVICE_ARCHIVE_ENABLED=false 不变，只停消费，事件不丢失。
- V023 只将任务 review_id 改为可空，并添加 card_requested 默认 0，可重复迁移；已有任务、档案、评价和授权状态保留，不自动回填历史完成订单。review_id 为 null 明确表示完成事件来源，API 和微信客户端都支持，不能用 0 伪造评价。
- 新完成档案快照 source.review_id=null，后续评价不得改写该快照。已有评价任务继续保留 review_id、原快照及消费行为。
- 后续评价复用同一任务，完成来源只设置 card_requested=1。启用原有 EXPERIENCE_CARD_ENABLED 时，消费者验证真实评价与归档来源后创建一次私有 DRAFT；不得自动授权/公开。未评价绝不生成经验卡片。旧 DONE 任务启用卡片开关仍不自动回填。
- 卡片来源信任同时校验既有档案冻结快照和独立评价；完成来源 null 与评价来源非空分别验证。测试档案仍标注 test_mode，不能进入公开经验。
- 后台对 PENDING 归档及 DONE 且 card_requested 的草稿任务记录分类失败和下次重试时间；关卡片开关时只继续归档，不清掉草稿请求。批次有界、仍按订单→任务→车辆锁序。
- 微信档案页接受 null 评价来源，保留工时/照片/来源订单；已完成订单提供档案入口并说明后台生成、不依赖评价。原生页面/真机验收独立登记，不用构建替代。
