# 接车争议与恢复履约验收设计

以 PR198 为基础，补齐商家争议处理和车主争议复核两个接口的正常、边界、错误和未授权四类执行证据。采用完整履约链新增独立套件；相比只测静态处理接口，此方案验证争议解除后能实际派工、施工、核销和归档；相比扩展生产状态规则，本阶段优先核实既有契约。

预约和 LOCAL_TEST 支付完成后，真实提交接车单，车主提出异议。无商家说明时接受必须失败，争议期间派工必须失败。商家第一次说明，车主拒绝，商家追加第二次说明，车主接受；恢复争议前 RECEIVED 状态，并继续原有履约流程。以 HTTP 建立争议和通知来源，不插入争议/通知 SQL 夹具。

处理说明验证 1/500/501 字边界，复核验证拒绝理由必填、非法决定、额外字段、跨车主/商家、重复决定、同键重放与变更意图。证据审计保留支付签名检查，同时绑定争议写入原始请求体和幂等键。数据库验证四条追加记录、五条争议审计、一次打开及恢复、11 条唯一事件和26条通知，最终订单完成且归档唯一。

使用独立后端/MySQL/网络并校验清理和源文件一致性。生成默认关闭的 Postman 集合，接入 CI 和历史证据汇总；不宣称生产资金、真实身份、真实图片上传或全量接口已验收。验证完成后提交并推送以 PR198 为基线的草稿 PR。下一阶段处理私有接车/施工附件访问缺口。
