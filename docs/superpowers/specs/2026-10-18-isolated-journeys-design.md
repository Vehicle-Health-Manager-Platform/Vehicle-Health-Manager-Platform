# R9 A4b 隔离核心业务端到端

## 目标与取舍

沿用已授权的 A4b 执行队列，采用 Spring Boot 随机端口 + Testcontainers 全新 MySQL + 全部有序迁移。相比改造绑定历史容器的脚本，新测试不接触现有数据库，且在默认后端 CI 中自动执行。相比仅组合已有 JDBC 或 MockMvc 测试，本方案使用真实 HTTP、JWT 校验、数据库业务 Bean 与持久化结果；不替换业务服务。

## 场景

1. 车主手动建车、档案录入、重复提交、列表脱敏、AI 未配置回退及跨用户隔离。问诊只验准备与未配置响应，不调用外部模型。
2. 门店发布时段、车主报价预约、LOCAL_TEST 签名支付通知、完整接车/车主确认、派工/技师接单、防护/报工/签字、门店核销、后台任务归档与车主查阅。检查状态与证据唯一性、重放与跨店/跨角色限制。
3. 入驻申请、运营审核开店、重放唯一性、待激活账号拒绝登录。正式账号激活在现有软件中尚未实现，留 B1，禁止通过 SQL 改成 ACTIVE 并冒充真实激活。

## 隔离及配置

每次测试仅新建 Testcontainers MySQL；不接收已有数据库地址，不清空历史库。业务数据和已扫描图片元数据为合成夹具；不证明真实上传与扫描。身份使用测试密钥签 JWT 并插入对应会话，正式校验器仍参与；不证明微信、短信登录。测试支付显式隔离 profile 与开关并用真实本地协议签名；不产生资金。

增加 MYSQL_PORT（默认 3306）以支持随机映射端口；其他配置与生产默认开关不变。异步归档轮询有界，报告失败/跳过不能算通过。标准 JUnit 报告保存证据；提供一条命令执行的本机/Docker 入口并校验实际测试报告。

## 完成标准

三条旅程真实执行成功，关键落库断言通过；在 CI 自动运行并保存报告；中文说明覆盖能力、复跑方法、未完成激活/正式渠道/UI 真机的边界。本阶段不声称覆盖全部 352 项 API，不声称满足原文全部 Postman/Newman 验收；A4c 性能/恢复在后续阶段。
