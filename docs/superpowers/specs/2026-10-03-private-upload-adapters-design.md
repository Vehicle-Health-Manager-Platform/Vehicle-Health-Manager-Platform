# S0 上传真实服务适配器与签名访问设计

> 2026-10-03。承接已确认的[下一步规划](../../progress/NEXT_STEPS.md)。用户已确认私有 MinIO/ClamAV 环境尚未配置，先在可丢弃 CI 服务中验证。本文待审阅，尚未实施；以 PR #9 分支为基线。

## 本步目标与方案选择

为小程序车辆档案图片补齐真实存储、病毒扫描和签名访问基础。本步接入现有 `PrivateUploadService`，提供真实 MinIO 与 ClamAV 适配器、权限复核后的内部签名服务、部署配置及容器验证。HTTP 上传与签名接口、上传幂等/限流/对象清理随后独立交付；上传基础能力可用后优先进入 S1 车辆与档案页面，不扩展为其他基础设施建设。

推荐官方 MinIO Java SDK 加 ClamAV `INSTREAM` 协议。MinIO 操作与签名由 SDK 提供，扫描通过受限 TCP 流发送已验证字节，不共享宿主文件路径。

备选一是自行实现 S3 HTTP 与 SigV4，可少引入 SDK，但需要自行维护签名、错误解析和兼容性；备选二是客户端直传与异步扫描，需要隔离对象、状态流转及恢复任务。当前选择同步扫描、服务端存储，复用上一阶段的校验和补偿核心。

## MinIO 适配器与私有性

- 官方 SDK 固定使用核对时 README 给出的 `io.minio:minio:9.0.3`，Java 17 构建由 CI 验证；MinIO 服务复用仓库已校验摘要的固定版本构建。
- 应用只使用服务端配置的固定桶，上传对象键由现有核心生成；实现 put、幂等 delete、对象状态查询和 GET 签名。SDK 网络连接、读写及整个调用均需有有限超时，底层错误映射为安全的应用错误，不输出 HTTP trace、凭据或签名。
- 上传和签名前都检查桶存在及策略读取成功。本步采用保守规则：仅接受未设置 bucket policy 的桶；任何非空策略均拒绝，包括看似受限的策略。仅明确的“无策略”结果可接受，权限不足、解析错误、网络故障及桶不存在均拒绝。
- 适配器限定 MinIO 目标，不声称该策略检查适用于任意 S3 服务。CI 以真实匿名 GET/list 被拒绝作外部证据；桶策略与其他访问控制必须由部署环境共同维护。
- 应用请求不创建桶或更改已有策略。部署初始化显式创建专用私有桶；已有桶仅检查，不清空其策略。为上传配置独立服务账号和所需最小权限，Milvus 使用的凭据与桶不改为上传用途。

## ClamAV 扫描适配器

- 使用 `zINSTREAM` 的 NUL 命令结束符、四字节网络序块长度和最后零长度块，每次调用独立连接；不发送客户端文件名或本机路径。
- 限制输入不超过现有 10 MiB，上限加一的内容不得送入扫描；连接超时默认 3 秒，整个扫描默认 30 秒，响应最多 4 KiB。必须限制连接、发送和接收整个过程，不能只设置读取超时；超时关闭连接。
- 仅精确的正常扫描成功响应返回 `CLEAN`，正常病毒发现响应返回 `INFECTED`。错误、超限、截断、未知/畸形响应、缺少结束符与连接失败返回 `UNAVAILABLE`，不记录原始扫描输出。
- Compose 内部提供 ClamAV，TCP 端口不映射到外网。部署使用官方固定版本或摘要镜像，其具体值及镜像可用性在实现提交中记录，不使用 `latest`；生产启用官方签名库与更新，未就绪时不放行上传。扫描大小与流大小配置至少覆盖 10 MiB，并对扫描超限启用告警/拒绝，不能把引擎跳过视为安全通过。

## 内部签名访问

新增受信任调用方使用的签名服务：接收服务端主体和文件 ID，先调用现有 `readable` 检查本人、未删除与 `CLEAN`，再检查私有桶及对象存在、类型/大小与元数据一致，最后签发 GET URL。主体不由客户端输入决定，文件对象键不由调用方选择。

配置分开设置 `MINIO_ENDPOINT`（后端可达）与 `MINIO_PUBLIC_ENDPOINT`（客户端可达）；使用同一桶、凭据和显式 region，对客户端地址直接签名，不在签名后替换 hostname。公共端点未配置时拒绝签发，不能自动用 `minio:9000`。

端点只接受固定 http/https 地址，不允许 userinfo、查询、片段或非根路径；真实部署要求 HTTPS，本地/CI 通过明确的开发配置允许回环 HTTP。默认签名有效期 120 秒，配置范围 1–300 秒；客户端取得 URL 后可在有效期内访问，因此权限变更不会立即撤销已签出的 URL，这一边界须写入接入说明。返回 URL 和到期时间，不记录 URL 或完整签名参数。此服务没有 HTTP 路由。

## 配置与部署

沿用缺少依赖时拒绝操作的行为。真实适配器由明确启用开关和完整私有环境变量创建，未启用时不自动选择替身；配置启用但缺失/非法时启动失败并给出不含秘密值的提示。

新增上传专用桶、服务账号凭据、region、公共端点、ClamAV 主机/端口及超时配置的占位说明。开发 Compose 的专用初始化步骤可使用私有 root 配置创建上传账号/桶；应用使用服务账号。不得打印秘密值，不覆盖既有存储策略。官方签名库更新失败或扫描器未就绪时保持不可用，初始化与健康检查不等于业务验收。

不新增数据库表、迁移或 OpenAPI 操作；不在本步启动用户的真实部署，也不改变现有身份凭据。

## 验证与验收边界

1. 协议测试：实际 TCP 对端验证命令、分块字节一致、结束帧；模拟正常/病毒/错误/畸形/超长/截断响应，以及连接、发送、读取超时。验证错误不会使核心存储文件。
2. 真实 MinIO 容器：应用适配器上传/删除；匿名 GET 和 list 拒绝；签名 GET 得到相同字节；过期签名拒绝；添加公开策略后上传及签名拒绝；缺失桶、错误凭据与对象不一致拒绝。签名使用与测试客户端一致的回环端点，不使用容器内部 hostname。
3. 真实 ClamAV 引擎容器：使用固定测试签名库及无害命中样本确认感染拒绝，正常图片样本通过，错误/不可用时不放行；联合 MinIO 与 MySQL 验证上传核心保存成功与病毒拒绝后无对象/元数据。测试签名仅挂载到可丢弃测试容器，不成为生产默认配置。这证明协议和引擎接入，不能证明生产官方签名库覆盖率或更新状态。
4. 签名服务：跨主体、删除、非 CLEAN 文件不进入签名步骤；缺少公共端点与存储故障拒绝，URL/凭据/扫描原文不进入日志。实际 HTTP 上传与微信图片预览在下一阶段接入时验收。
5. 容器测试在 CI 必须执行，Docker 不可用不得跳过。保留六项 CI；本机 Java/Maven 或 Docker 不可用时只记录 CI 证据。完成后更新进度、接入说明和下一步规划，并推送独立 PR。
