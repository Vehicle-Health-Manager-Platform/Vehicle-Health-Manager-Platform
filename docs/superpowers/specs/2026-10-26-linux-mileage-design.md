# A4d45 Linux OCR共享网关与微信旅程

基线5358ef6 / PR235，2026-10-26。用户要求规划后直接实施、逐阶段上传GitHub。范围仅微信小程序及共享后端，不合并部署。

复用现有80项材料/工作台、12项网关和可选9项微信原生旅程，新增显式run_linux_mileage_acceptance.py --allow-isolated-linux-mileage。默认Windows隔离worker路径保持兼容。业务夹具和审计复用，Linux生命周期单独管理；仅Linux私有HTTP自检不足以证明共享网关和原保存流程，本阶段补全连接。

Linux OCR镜像按A4d44锁/模型重建并绑定不可变ID，运行于唯一internal网络，保持非root、只读、限资源与worker seccomp。最初的双网络Maven容器方案因挂Docker控制套接字被自动审批拒绝，已撤销。采用工作区缓存的官方摘要校验Java17和Maven，在Windows宿主运行JVM，经当前Docker Desktop命名管道管理测试资源，关闭Ryuk；新增容器均不接收Docker控制接口。非root/只读/限资源的字节转发容器连接internal及本次专用桥接网络，唯一随机端口绑定宿主127.0.0.1，目标写死ocr:8090，不替换请求或响应。实际Docker验证表明仅接internal不能发布宿主端口，因此仅转发容器使用双网络；不声称转发进程本身禁网。OCR自身不公开宿主端口。原生代理采用宿主curl.exe访问本次JVM。

通道记录成功上游TCP连接：网关模式1次、原生模式3次（基础1+原生2）；预检直接HTTP两次另计。连接数不称为模型内部调用数。核对相同worker启动身份、过滤器和实际资源、严格拒绝证据缺项，继承A4d44明确缺失与探测故障区分，只清理本次标签归属资源。

微信旅程固定已验SDK3.17.2，合成图片与身份、选择器事件有辅助；三个SQL节点零提前档案，最终原保存按钮仅一条正确里程及本人图片引用，登记里程100不变。Linux与默认模式分别计证，私有env/配置/会话和所有自有容器网络必须清理；无真实仪表/手机/正式身份或压力验收声明。Ryuk关闭后，业务夹具容器和网络以外层运行ID打标签，由JVM正常关闭及运行器异常兜底双重清理；不能把daemon故障当资源缺失。
