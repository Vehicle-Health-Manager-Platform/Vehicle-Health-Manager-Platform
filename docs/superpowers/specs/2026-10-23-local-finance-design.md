# 小程序运营资金记录查询

用户本轮要求规划后直接实施，并逐阶段上传GitHub。终端为微信小程序，使用现有受限运营身份；不开发PC页面。选择先做本地可验证查询，再接正式渠道；直接接渠道会等待账号与账单，继续只补材料不能填补功能。

## 本阶段A4d26

实现已有契约 `GET /api/admin/reconciliation?date=YYYY-MM-DD&channel=WECHAT|LOCAL_TEST`，与小程序运营资金记录页。复用现有独立 `can_analytics` 权限，只返回平台级金额/计数，不返回用户、订单、交易流水号或商户敏感详情。后端每次核对当前运营会话、停用及权限，前端入口仅作展示控制。

北京时间单日半开区间，当前日截止观察时刻，未来日拒绝；支付按paid_at、退款按refunded_at归日，跨日退款不回写原日。成功但时间缺失者以created_at归日并标异常。非成功记录按created_at计为未成功，不计入金额；未知状态或成功证据矛盾计异常。选定渠道独立查询，退款由原支付渠道归类；无法归类的支付/孤立退款单独计数并使金额未知，避免当成正式零收入。

成功金额须CNY、正数、订单支付金额相符、非删除订单/支付、正确唯一成功事件与非空渠道流水号；退款须原支付成功且同订单同金额、退款成功事件、完整同意时间、时间先后正确。读取上限10000支付/退款（含归属未明来源），超过返回409并提示拆分日期/人工处理；不静默截断。金额使用BigDecimal，两位十进制字符串。存在异常时对应支付/退款总额及净额为null，不展示部分金额冒充完整总额。

渠道账单尚未接入，`channel_statement.state=UNAVAILABLE`，渠道净额及差额固定null；本地净额仅指所选日成功支付减成功退款，不是佣金、到账或结算。所有响应no-store，查询无写入、无渠道调用、无幂等键。未配置数据库503；匿名401，错误角色403，无权限403，失效会话401，错误参数400。

小程序使用原生日期picker、渠道picker及查询按钮，明确“测试资金/正式渠道记录”、观察时间、异常/未成功计数和未知原因。修改选择、离开页面、权限或身份变化立即清除旧结果；迟到响应不得覆盖当前选择。展示金额不经Number转换，响应须核对日期、渠道、时间窗口、金额/状态一致性。
