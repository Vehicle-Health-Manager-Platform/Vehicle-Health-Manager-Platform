# R3c2 本人档案报告与私有导出规格

日期：2026-10-11。范围为车主微信小程序与必要后端；沿用车辆档案已有本人 OWNER 会话、`vehicle_archive` 和私有图片授权。无 PC 页面、公开分享、OCR/语音/健康评分开发。

## 用户目标

车主从当前选中车辆导出完整、可离线查看的中文 PDF，内容只反映已录入且可追溯的档案。原始规划在档案页已有“导出完整档案”入口；本阶段不复刻尚未实现的六项指标、分数和证件记录。

## 已核实数据源

- `vehicle`：本人未删除车辆、当前登记里程、车型目录快照关联；车牌与 VIN 仅作脱敏摘要。
- `vehicle_archive`：本人车辆的手动/拍照记录；input_type=4 施工归档仅包括 `content.source.user_id` 等于当前车主的记录。施工归档带有冻结的完成内容、实际工时/配件/测试标记及来源事件，不读取正在施工的临时记录。
- 施工照片继续经现有本人专用档案权限接口查看。导出 PDF 只显示关联照片数量和小程序查看提示，不嵌入图片、不签发长期图片 URL。
- 当前没有车辆证件专用表、六项健康指标或可信健康评分来源。报告明确显示“当前无可用记录/尚未提供”，不把商家资质、订单预约码、其他车主数据当车主档案。

## 方案比较与决策

1. **推荐：服务端读取一致快照并直接返回私有 PDF。** 以 `GET /api/archive/report` 接收本人车辆及可选完整日期区间，服务端在同一只读 `REPEATABLE_READ` 事务校验会话/车辆并聚合完整来源，事务结束后由 PDFBox 生成。普通 HTTPS 传输以 `application/pdf` 由小程序下载；微信云托管 `callContainer` 传输使用明确的 JSON Base64 信封（同一 PDF 字节），因为现有云传输封装只承载 JSON。两种传输均使用 OWNER Bearer、`Cache-Control: no-store`，不存报告、不产生 `file_object`、不改变业务表或审计、不需要写操作幂等键。PDF 超过 3 MiB、档案超过 500 条均返回 409 并提示缩小日期区间；不静默截断或传回部分 PDF。
2. **服务器保存 PDF 对象和快照记录。** 可重看历史报告，但长期复制车辆档案，需要删除/保留策略、访问授权、对象补偿清理和新的隐私生命周期；本阶段不选。
3. **小程序分页后本地拼 PDF。** 复用现有接口较多，却可能在分页间档案变化，容易漏记；还需要在小程序包内分发大型字体和 PDF 库。本阶段不选。

## 输入与筛选

- 路径：`GET /api/archive/report?vehicle_id={id}`，OWNER Bearer。可选 `from=YYYY-MM-DD&to=YYYY-MM-DD`，二者必须同时出现、真实日历日期且 `from <= to`；区间首尾均包含。拒绝重复参数及未知参数。无日期过滤时导出车辆全部当前可见档案。
- 已知日期按档案 `recorded_at`（日期部分）筛选。无日期过滤时包含发生日期为空的记录并注明日期未提供。选了日期区间时，不猜缺失日期；PDF 明确给出因日期缺失而未能归类的记录数。
- 数据在一个本人可见的一致快照中读取。范围与现有本人档案列表一致：可见手动/拍照档案，以及 `content.source.user_id` 属于当前车主的施工自动归档。历史语音档案当前不在档案列表可见范围，本阶段也不新增读取权限。软删除记录、其他车主归档和未完成/异议施工证据排除。
- 上限 500 条。查询采用 501 条界限判超限；超过时拒绝生成，建议缩小时间范围。

## PDF 内容与隐私

1. 标题、生成时间（Asia/Shanghai）、车辆车型和来源范围。
2. 车牌/VIN脱敏摘要（只保留满足项目现有脱敏规则的掩码）、当前登记里程并标注“车辆登记值”，不声称其来自最新核验。
3. 保养、维修、保险、事故、改装、违章、年检记录：发生日期（未知则明示）、录入来源、标题、备注、手动记录的里程、附件张数。施工来源额外列实际工时、配件或“未使用”、报工/签字/核销时间以及测试施工标识。
4. 页尾说明：资料仅汇总已有档案；未提供的证件/合规材料、健康分、六项指标与趋势不会推算。施工测试记录会清楚标记。档案标题和备注按纯文本绘制，不执行标记或脚本。
5. 不包含完整车牌、VIN、手机号、姓名、预约/核销码、文件对象键、可分享 URL、其他车主/员工身份、签字图或照片原件。用 Noto Sans SC Regular TrueType 字体嵌入实际使用字形；源自 `@expo-google-fonts/noto-sans-sc@0.4.4` 的 OFL-1.1 字体文件（单个 TTF 10,559,284 字节，约 10.1 MiB），仓库同时保留字体许可证，不引入 MIT 运行代码。字体必须可由 PDFBox 加载并在测试 PDF 中提取中文文本。

## 页面与访问控制

- 档案页当前车辆区域提供完整导出及可选日期范围；明确区间含首尾。超过上限显示筛选建议，仍允许重新选择区间。
- 普通 HTTPS 模式使用带 OWNER Bearer 的 `downloadFile`，要求配置的 HTTPS API 来源、200 状态、`application/pdf` 和 1 字节至 3 MiB 文件。云托管模式使用 `callContainer` JSON 接口，严格校验信封版本、MIME、文件名、Base64、声明长度和解码后 1 字节至 3 MiB；不得把临时 `cloudrun.invalid` 哨兵作为下载地址。
- 下载期间页面隐藏、退出/切换账号、切换车辆、发起新导出时，取消仍可取消的下载任务、递增请求代次并丢弃旧回调。打开原生文档查看器时保留其临时文件，回到小程序或页面销毁后删除；不会把个人档案持久写入小程序缓存/本地数据库，也不添加公开分享链接。
- 返回固定中文错误，不把 SQL、对象存储或文件系统错误显示给车主。下载报告不访问也不暴露商家/技师页面权限。

## 错误语义

`400` 输入/参数非法；`401` OWNER 会话无效；`403` 角色错误；`404` 本人车辆不可用（与不存在统一）；`409` 当前条件超过 500 条或生成后 PDF 超过 3 MiB；`503` 数据读取、许可字体或 PDF 生成暂不可用。所有成功/错误响应 no-store。超限/故障只返回错误 JSON，不返回部分 PDF。

## 验收

- 同一数据库快照完整、可按首尾日期筛选；未知日期不静默混进日期区间，全部导出包含未知日期并可解释。
- 真库隔离验证车主A/B、软删除车辆、input_type=4 的 `source.user_id` 过滤、500/501边界、撤销会话；普通 HTTP 安全链仅 OWNER 可达且成功返回真实 PDF 字节。
- PDF 结构可解析、文本提取含中文和记录字段、页数合理，字体含许可证且仅嵌入使用字形；超限/失败无文件/表/审计副作用。
- 微信离线覆盖筛选校验、Bearer/文件名、普通下载与云托管 Base64 信封、PDF MIME / 大小拒绝、取消/隐藏/身份/车辆切换迟到结果；微信原生构建、H5 构建与 CI。
- 本机/CI 能证明程序生成和文本内容，不等于真机 `openDocument` 中文视觉验收；原生设备与正式身份继续 R9。

## 明确排除

持久报告历史/删除、分享链接/有效期/撤销、订阅消息、真实证件识别、语音转写、六指标或健康评分计算、其他端档案访问、PC后台与产品内对话式 AI。
