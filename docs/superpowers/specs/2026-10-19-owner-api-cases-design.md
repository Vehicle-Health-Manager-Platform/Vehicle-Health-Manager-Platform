# A4d-2a 车主车辆/档案 Newman 场景

按既定A4d-2域顺序先完成8个无需外部供应商的实际接口：品牌/车系/车型、车辆列表/添加/本人车牌匹配、档案列表/添加。沿用brainstorming的范围梳理与planning-with-files记录，用户已要求直接实施及阶段上传。

复用A4d-1隔离网络/数据库/后端及Newman入口，增加--owner-cases，在同一轮先验证338匿名接口和默认模板禁发，再执行61项车主案例。使用新建库的合成两车主、一门店身份与真实JWT校验，不替换业务服务；仅本机私有环境文件保存临时令牌。

每个接口覆盖正常/边界/错误/未授权类别，具体包括分页空结果/非法尺寸、0里程/负数/整数越界、VIN/车型错误、车牌匹配归属和非法覆盖、标题80/备注1000边界及超限、非法日期/类型/不支持来源、重复与同键异载荷、跨用户车辆/档案/图片、角色403及匿名401。使用204条状态/安全响应/业务断言并核对车辆/档案/幂等/审计数据库事实，失败案例不得产生额外记录。

校验Newman实际请求身份、方法、路径、查询、状态、断言完整性及8接口四类覆盖；匿名、越权按实际401/403/404或隔离列表200契约，不用统一403替代安全语义。报告仅含安全计数/案例ID/覆盖/摘要，原始Newman含令牌，仅在被忽略.cache，不上传。

完成本阶段不等于全部352 API、全部车主功能、PDF/结构化/上传/健康读数或真实身份已完成；旧PC/H5排除不恢复，性能延迟仍未达标。默认Postman集合禁发，隔离入口显式开启。每次构建与实际运行保留来源稳定性及清理结果，CI复用完整构建jar并测试生成资产漂移。
