# 下一阶段设计：微信原生验收

日期：2026-10-09。基线PR #65，提交da75ef34b029eb781915c598b7c2e37e3f32eed5；六项CI全绿，后端437、小程序217、真实HTTP43项通过。#65仍OPEN，base为codex/a7-publication-miniapp。本文件是下一步规划，尚未实施本阶段。

## 方向与取舍

主要产品继续是apps/miniapp中的微信小程序，包含车主、商家、技师和独立运营审核工作区。

| 顺序方案 | 收益 | 依赖与取舍 |
| --- | --- | --- |
| 先模拟器，再短信与真机（采用） | 先解决原生运行与自动化连接，已有本机环境可以推进；后续获得可重复验收基线 | 模拟器不证明真实相机、手机网络或正式短信 |
| 先正式短信，再模拟器 | 更早完成商家/运营真实登录 | 需要供应商、签名、模板、受控账号与测试手机号，当前未确认 |
| 先正式资金与退款 | 推进交易闭环 | 需要单独资金规格、商户配置与回调/对账，当前原生验收缺口仍存在 |

## 首个实施单元：本机微信模拟器

1. **工具连接**：核对已安装CLI版本及支持参数。仓库已有simulator-smoke.cjs和文档示例，将工具HTTP服务端口11927与自动化WebSocket端口9420分开；上轮只设置--port 9420，自动化连接失败，端口混用是待验证原因。先确认当前项目绝对路径、端口用途、RPC握手及实际当前页面，不能把auto命令成功当成页面验收。
2. **当前产物**：从基线源码重新构建mp-weixin，记录提交、构建时间、AppID、后端镜像/JAR摘要与61表迁移状态；确认导入的是本工作区产物。模拟器使用受控本机接口，保留已有域名校验默认值；如HTTP调试需例外，仅写入忽略的私有配置并记录、还原，不修改正式构建默认设置。
3. **路由与身份**：扩展现有模拟器脚本，检查车主/商家/技师入口、五Tab、接车/确认/派工/报工/核销/评价/档案、经验卡片/同款、运营登录/审核。受保护页面未登录时的跳转或登录提示按实际业务预期断言，不把成功导航当成业务通过。
4. **原生业务流程**：优先验证真实微信登录。订单业务可以使用命名隔离栈中的合成账号和来源；需要合成会话时只允许测试构建内的内存桥，独立标注，不向正式包加入测试登录接口、固定短信码或生产令牌。页面必须调用真实后端；不替换uni.request业务响应来证明流程通过。
5. **审核闭环**：本人卡片授权→运营待审→批准/固定码驳回→另一同款车主读取→本人撤回→再次查询隐藏；核验不同车型/其他车主/员工角色隔离、权限撤销、登录过期，以及离页/换车/换账号后重新查询。正式短信未配置时503是预期失败；合成OTP仅证明业务协议，不计正式登录通过。
6. **原生文件流程**：在工具允许的选图能力下验证上传、错误提示、报工PNG签字与私有访问；不宣称模拟器调起真实相机。证书或对象地址不可达时保存具体错误与待验收项，不关闭正式TLS校验来宣称通过。

脚本有连接/RPC/页面加载超时；失败退出非0；成功/失败/跳过分别记录。只清理本任务创建的连接、会话与临时文件，已有IDE和其他项目保留。截图、日志、凭据放忽略目录，仓库只上传脱敏摘要和可复核脚本。

## 后续独立实施单元

- **正式短信**：先获取供应商选择、签名/模板ID、受控服务端凭据与测试手机号，分别接入已有商家发送接口和OperatorSmsSender；核验发送/限流/一次消费/供应商失败/退出。凭据仅服务端，当前未配置继续503。无需为模拟器阶段等待此依赖。
- **真实微信与手机**：确认有授权的微信账号及iOS/Android设备，先验证手机到后端的网络，再验三端身份、相机/上传/预览、签字、审核/同款/撤回。直连接口与wx.cloud.callContainer按真实选择分别记录，不用离线运输测试代替云端验证。
- **发布准备**：V019备份与重复迁移、客户端升级、权限配置与回滚演练完成后，再提交开启发布开关的审阅方案。当前不合并、不部署、不打开EXPERIENCE_PUBLICATION_ENABLED。

## 完成判定与范围

首单元完成须有真实微信模拟器连接、实际页面断言、原生请求连真实隔离后端、审核闭环及拒绝矩阵、脱敏验收报告，代码与文档分阶段上传且对应CI通过。不能依赖设备/供应商的本机工作先完成；缺设备/短信能力的项目明确待验收，不能记为跳过后全部完成。

资金收退款/取消争议订单、第二次异议、超时自动处理、公共图片、商家评分/考核/增长、原PC运营管理均另列。规划仅补齐已实现微信业务的运行证据，不扩展上述功能。
