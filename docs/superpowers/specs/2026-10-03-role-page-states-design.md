# S0-7.1f-3 三角色基础页面状态设计

> 2026-10-03。承接 [下一步规划](../../progress/NEXT_STEPS.md)。此文档为待用户审阅的设计；尚未实施或验收。

## 方案与范围

推荐沿用 `apps/miniapp` 的角色入口和车主五 Tab，抽取统一请求错误及状态展示，将已有身份接口的实际结果接入页面。这样可以覆盖三角色流程，且不依赖尚未实现的业务列表或生产短信发送器。

其他方案：只修改商家页面，改动较少但会遗漏车主和技师入口；重建三角色完整工作台，涉及尚无接口的业务页面，超出本步身份与状态骨架范围。采用第一种方案。

本步覆盖微信登录、技师员工码绑定、车主手机号绑定、商家短信请求与登录、三角色退出。车辆、订单、AI 等页面保持明确的待接入状态；没有实际读接口时，不将“待接入”写成“空列表”。业务空状态随对应读接口接入验证。

## 请求与状态

- 在独立服务模块统一解析 HTTP 状态、平台响应和网络失败，页面收到具有稳定类型的错误。公共请求不附加业务令牌；员工码绑定携带短时绑定凭证，手机号绑定和退出携带业务访问令牌。
- 页面保留最近成功的身份结果，单独记录当前操作及加载、成功或失败状态。请求过程中禁止重复提交；完成后恢复可操作状态。
- 无后端地址：说明服务尚未配置。网络失败或超时：说明无法连接并允许重试。401：提示身份验证失败；受保护操作提示重新登录。403：提示当前身份无权限。429：提示稍后重试。503：显示服务暂不可用；短信未配置的服务端消息传达给用户。其他错误保留安全的服务端提示或通用失败信息。
- 失败不签发或伪造会话；登录成功必须具备有效形态的访问令牌和匹配角色。技师待绑定成功响应必须具备绑定凭证。退出成功清除当前角色会话；失败保留会话并提供重试。

## 三角色页面行为

- 车主：修复 `RoleLanding.vue` 缺少 `ownerSession` 导入导致的初始化问题；继续在内存共享车主会话。登录、手机号授权与退出均显示本次操作状态，手机号授权取消不触发接口。进入五 Tab 后可返回身份页；业务内容显示待接入。
- 技师：待绑定时显示员工码表单，绑定成功后隐藏表单并清空员工码和绑定凭证。绑定凭证被拒绝时引导重新微信登录。接口失败不丢失可重试输入。
- 商家：账号、密码和六位数字验证码在提交前校验；短信发送与登录分别显示加载状态，实际成功发送后才显示已发送。503 不启动成功发送提示。登录成功后清空密码与验证码，显示已验证身份和业务待接入提示。
- 页面沿用当前绿色按钮和卡片样式，以统一状态卡呈现提示及重试操作。提示语不展示令牌、验证码、密码或手机号原文。

## 离线验证与交付

使用测试专用接口替身覆盖成功、待绑定、断网、超时、401、403、429、503、无服务地址及格式错误的响应；替身不进入正式页面入口，也不签发可用于后端的凭证。验证请求地址、鉴权头、重复提交抑制、敏感输入清理及失败后的会话行为。

运行小程序和 H5 构建；以 H5 页面实际检查角色入口、车主登录页初始化及状态交互。若微信开发者工具可用，导入当前构建目录并复核三角色入口和车主五 Tab；若无法完成则如实记录未验证，不以 H5 或 CI 代替模拟器证据。

完成后更新执行记录、当前进度和下一步规划，推送独立 PR（以文档 PR #6 分支为基线），确认六项 CI。真实微信或短信联调仍属于 S0-7.1f-4，需要私有凭据、数据库、HTTPS 后端和短信通道。

## 自检

范围集中于已实现身份接口的状态与现有导航，未引入新业务接口或短信供应商决策。失败状态与会话规则可由离线响应验证；模拟器、真实微信和生产短信分别记录实际证据。实现前等待用户对本设计的审阅。
