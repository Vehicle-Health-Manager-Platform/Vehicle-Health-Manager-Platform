# OpenAPI生成源与已交付契约一致性修复

用户授权继续规划与实施。最新代码PR215已完成取车对比三端，当前CI有1项真实失败；先收口基线，避免继续叠加失败。

根因：A4d21与22修改交付JSON中的三处实现标记及取车对比操作，生成器缺少这些修订。临时定向输出复现4操作漂移，components相同。

方案：沿用生成器分层方式增加R9修订层，编码现行四操作，不读取交付JSON作为输入。生成入口拆为无写入build_document与兼容默认生成main；新增--check只比较规范文本，遇漂移/缺文件失败且不写入。CI先运行生成回归和--check，再跑现有schema任务；保留最后生成/git diff门禁。

回归要求：首个完整生成对比在修复前失败；生成与现行JSON在统一LF/CRLF换行后的规范文本一致、连续两次稳定、JSON结构关键语义（只读正文、无写键、权限及响应）不丢失；--check漂移/缺文件/非法JSON不改文件，并验证生成不依赖交付JSON。

不修改生产Java、数据库、API路径、业务行为、历史证据或结论分布。阶段目标是修复真实CI失败；财务对账另起下一功能阶段，必须明确渠道账单缺失，不能拿本地金额相减冒充真实渠道对账。完成全部schema检查后上传依赖PR215的草稿PR，不自动合并。
