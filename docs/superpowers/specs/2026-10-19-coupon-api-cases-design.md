# A4d-2b2 券交易生命周期验收

## 范围与选择

延续已确认的分域 Newman 验收，以现金券与服务券为本阶段完整范围。复用已有全新 MySQL/后端/合成会话及真实 HTTP 方法，增加可复跑 Postman 案例；仅复用旧 JUnit 不能补齐交付资产，一次扩展全部剩余领域又无法清楚定位生命周期失败，因此按券域独立交付。

## 现金券

真实 API 创建/发布/领取，不植入已发券或已支付订单。报价 12.34、优惠 5.00、实付 7.34；首次预占后取消释放，再创建支付单，以 LOCAL_TEST 签名通知消费；退款申请/同意/失败均保持 USED，只有可信成功通知返原券 AVAILABLE，不延长有效期、不恢复发放库存、不绕过终身限领。重新预占并取消，原合同仍保留 RETURNED 历史。检查客户端金额覆盖、过期版本、错角色/归属、重放与同键异体拒绝。

## 服务券

独立 SERVICE 券授权码→本店预览→核销。检查外店、他人券、错误码与版本、重复核销、佣金 0.00、授权码不出现在列表/审计；服务券不生成支付、订单或施工档案。授权码与订单预约码分开。

## 运行及证据边界

每个本阶段接口覆盖正常/边界/错误/未授权。复用运行器并将业务集合加载/执行收敛为共用流程，保持现有命令、默认禁发与报告字段。校验实际方法、路径、查询、身份和断言；对实际支付/退款正文重新计算 HMAC，重放须相同签名字节；数据库核对合同状态、唯一事件、库存、有效期与业务事实。仅发布脱敏报告，私有 JWT/授权码/签名留 .cache。

启用隔离 local-payment-test，合成支付/退款通知直接经过真实验签与事务，不调用实际退款供应商，不声称外部调度或资金已验收。供应商查询/提交、真实账号与渠道接入后置。全部 API 验收和性能延迟达标仍未完成。
