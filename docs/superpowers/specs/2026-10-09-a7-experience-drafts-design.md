# A7.2c1 私有经验卡片与车主授权规格

日期：2026-10-09。依赖 A7.2b 的 PR #56；用户授权规划后直接实施，按阶段上传 GitHub。

## 范围与方案

选择「结构化私有摘要 + 明确授权送审」，先完成可独立验收的车主流程。另一方案直接复制施工原文/照片需要额外身份与图片脱敏；一次建设完整运营登录、权限、审核与公开推荐跨度较大，安排为 A7.2c2。当前运营端社区审核页为空壳，没有可复用的运营认证链路。

本阶段不提供公开读取或审核批准接口，不将卡片写入现有 community_content。PENDING_REVIEW 是车主已授权的待办状态，不能等同审核通过或发布。下一阶段须建立运营认证、最小审核权限、审计、公开 DTO、撤回后立即隐藏与同款车型筛选，然后接入该待办。退款、取消争议订单、第二次异议和超时自动处理另列。

## 生成与可靠性

归档消费者成功写入新施工档案时，在同一数据库事务创建 experience_card；同订单、同档案各唯一。采用已有可靠 service_archive_job，归档、卡片和最小系统审计任一失败则共同回滚，待原任务重试。无需第二条异步链路，不重复消费、不扫描历史档案补写。已完成旧归档任务再次消费不生成卡片。

V018 先于新版后端部署。EXPERIENCE_CARD_ENABLED 默认 false，只控制新归档生成；既有卡片查看、撤回不受生成开关影响。开启之前的已完成任务不补写。SERVICE_ARCHIVE_ENABLED 仍控制原消费者。

## 内容与隐私

只读来源为 A7.2b 校验后的冻结施工快照；固定标题「施工经验摘要」，摘要仅含 version=1、工时分钟、配件种类数量、是否未使用配件、施工月份。不得推断维修效果、故障结论、真实里程或价格。不复制报告、评价自由文本、配件名称/品牌/型号、任何图片、签名、文件 ID/键/URL、手机号、车牌、VIN、人员/商家名称或订单码。

卡片私有元数据保存原车主/车辆/订单/档案/评价 ID 与 test_mode，API 仅原车主且当前仍拥有该有效车辆可读。测试卡片明确标记且禁止授权送审，不进入真实推荐、评分或 AI 来源。只展示可信的结构化事实，保留原档案和评价不修改。

## 状态与授权

新卡片 DRAFT，默认未授权。车主勾选独立声明后，以严格 JSON `{ "agree": true, "consent_version": "experience-v1" }` 和 UUID Idempotency-Key 提交，DRAFT/WITHDRAWN → PENDING_REVIEW；服务端保存声明版本、授权时间、撤回时间与递增 revision。声明：仅授权上述不含照片/原文的摘要接受审核，并在后续审核通过后用于车友经验展示；可撤回，原记录保留。

提交必须复核有效会话、本人当前车辆、原档案及冻结来源仍一致，无未解决争议且仍可信核销付款。测试来源、来源改变或不完整拒绝 409。无任何自动公开。相同状态重复请求不新增业务审计/revision。UUID 幂等重放须复核身份，旧请求不能把撤回后的卡片重新送审（返回 409，需刷新并产生新操作键）。

撤回接口严格空 JSON，任何已拥有卡片的 DRAFT/PENDING_REVIEW → WITHDRAWN；来源后来缺失也可撤回，但仍要求本人当前车辆。清除有效授权字段、记录撤回时间，revision 递增，业务审计只含状态/revision/声明版本，不含原文或身份资料。新键可重新授权真实卡片，必须重新勾选。

## 接口与页面

- GET /api/experience-cards?vehicle_id=&page=&page_size=：本人车辆分页，页码≥1、每页1–50，不允许未知/重复参数。
- POST /api/experience-cards/{id}/consent：上述严格声明载荷，无 query 参数。
- POST /api/experience-cards/{id}/withdraw：严格 `{}`，无 query 参数。

全部响应 no-store，角色 OWNER，非本人 404、无效角色 403、失效会话 401、非法输入 400、状态/资格异常 409、数据库失败 503。所有数字须在 JS 安全整数范围。

小程序档案页入口「我的经验卡片」，按车辆选择分页；显示 DRAFT/PENDING_REVIEW/WITHDRAWN、固定摘要、测试标签、来源订单。独立未预选授权框；测试禁送审；明确待审核尚未公开，可撤回/重新授权。网络失败保留同操作 UUID 供重试；已成功操作或明确失败刷新后新键。隐藏、卸载、换车、换账号时清理界面并屏蔽迟到响应。
