# A7.2a 本人订单评价规格

日期：2026-10-09。用户已授权“规划好下一步，然后开始实施”，按本规格连续实施并逐阶段上传。

## 来源与范围

来源：`docs/SPEC.md` §3 的核销→评价流程、C25；`docs/reference/DELIVERY_V1.md` C25 的评分/文字/上传图；`docs/progress/NEXT_STEPS.md` A7.2a。A7.1 #45→#48 未合并，规格分支直接依赖 `codex/a7-redeem-e2e`。

比较三种方案：纯文字评价实现较小但缺来源图片要求；同时实现公开评价、匿名与修改会引入尚未确定的展示与审核规则；选择本人唯一评分+文字+私有图片，完成 C25 输入与本人查询，公开规则独立确认。

本阶段规则【实施假设】：总评分为 1–5 的整数；必填说明去除首尾空白后 1–500 个 Unicode 码点；可选 0–3 张 JPEG/PNG 图片，使用现有本人私有上传与安全扫描。提交后不可修改、不可再次提交不同内容；仅本人可查询，不向商家、社区或匿名用户公开，不计入商家评分或 AI 总结。页面提交前说明规则并二次确认。后续若开放公开展示，需另有授权和内容审核规格。

## 接口与严格输入

- `POST /api/order/review`，OWNER，必需 UUID `Idempotency-Key`，JSON 正文必须恰含 `order_id`、`rating`、`content`、`photo_file_ids`，禁止额外字段、重复 JSON 键、尾随 JSON、查询参数。ID 为 1–9007199254740991 整数；图片 ID 不重复，数组顺序为展示顺序；正文最多 8192 字符。输入规范化后参与幂等摘要。
- `GET /api/order/{id}/review`，OWNER，无查询参数，返回 `order_id/can_submit/unavailable_reason/test_mode/review`。无资格以 `ORDER_NOT_COMPLETED`、`REDEMPTION_UNVERIFIED`、`OPEN_DISPUTE`、`PAYMENT_UNVERIFIED`、`ALREADY_REVIEWED` 表示；已评价仍可读本人记录，不能再提交。
- `review` 为 null 或 `review_id/rating/content/photo_file_ids/submitted_at/test_mode`。写入响应恰为 `order_id/review`。不投影用户、员工、付款 ID、预约码、付款流水、存储对象键或图片签名 URL。
- 图片预览沿用 `/api/file/{id}/access` 本人安全签名接口；文件失效时显示不可预览，不删除已有文字评价或补发公开 URL。
- 全部评价响应（含业务失败）`Cache-Control: no-store`。400+40001 输入/同键异载荷；401/403/404 身份及归属；409+44001 无可信资格；409+44002 已有不同评价；422+42200 图片不安全/非本人；503+50300 未配置或事务失败，原键重试。

## 资格与历史处理

每次首次提交、相同键重放、新键提交均复核当前会话和本人归属。首次资格要求订单未删除且 COMPLETED、无 OPEN 争议；有唯一核销记录，商家与订单匹配、时间非空；核销绑定的付款为唯一 SUCCEEDED/CNY/金额相同/非空流水与付款时间，唯一同通道有效 PAID 事件、非空事件摘要，订单无任何付款异常（含历史软删除）。核销 `test_mode` 与 LOCAL_TEST/WECHAT 通道一致，其员工历史记录属于订单商家。测试标识继承可信核销记录，客户端不能指定。

核销是已经过施工、七图与签字验收的历史事件。评价不重新依赖当前技师登录、施工原图仍在或当前测试付款开关；付款及核销一致性仍实时复核。不对历史 COMPLETED 订单补核销记录或资格。读取已保存评价只复核本人会话与订单归属，保留本人历史反馈；提交重放仍复核资格和所附图片安全状态。

## 数据与事务

V016 新建 `order_review`（order_id 唯一，user_id、redemption_id、rating、content、test_mode、submitted_at）与 `order_review_file`（review_id+position 唯一、review_id+file_id 唯一）。无自动回填、无修改/删除 API，重复迁移安全，V001–V016 共 57 表。

沿用 `WriteIntegrityService`；锁当前 owner 会话/用户→本人的订单→核销→付款/事件/异常→评价→按 ID 排序的文件。首次写入评价、图片关系、ORDER_REVIEW_CREATE 审计和成功幂等缓存同事务，任一失败全部回滚。审计仅记录 order_id/review_id/rating/photo_count/test_mode/submitted_at，避免重复记录文字及私有图片；成功响应缓存是受服务端访问控制的本人数据。

相同键/相同规范化内容返回原响应；同键异内容 400；新键同内容返回同一评价、无重复审计；新键异内容 44002；并发同内容两次成功但只保存一次，并发不同内容只有一个成功。订单状态仍 COMPLETED，不增加订单状态迁移。

## 小程序

已完成订单详情增加评价入口；评价页读取服务端资格和本人记录。评分按钮 1–5、说明输入、最多 3 张相册/拍摄上传、移除/原图重试/本人预览。选中未上传图片时不能提交。等待二次确认时锁表单；身份、订单、页面代次和正文变化会使旧回调失效；网络/503 原载荷原键重试；离页清空文字/图片/待提交键，重入重新读取服务器，账号切换清空全部状态。已经提交时只展示记录；测试来源持续明确“未真实扣款，不公开、不计入商家评分”。
