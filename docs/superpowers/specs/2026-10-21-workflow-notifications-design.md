# 施工查询与站内通知验收设计

依据交付文档和覆盖清单，下一步补齐十个已实现接口的可复现验收证据：接车上下文、接车单、技师工单、施工详情，以及车主/商家/技师通知列表和已读操作。

采用现有完整履约用例作为支撑，在对应状态插入查询；订单从预约支付到核销归档均通过真实 HTTP 驱动。相比仅静态补清单，该方案能验证事件与当前权限；相比外部供应商联调，不依赖尚未提供的生产凭证。支付使用 LOCAL_TEST，图片仍是隔离数据库元数据夹具。

通知由事务 outbox 及后台任务实际生成，不写入通知 SQL 夹具。三端从列表查找订单完成事件，捕获真实通知 ID，再验证标记已读、同键重放、新键重复、越权与非法参数。证据审计绑定实际响应 ID，并验证签名回调和全部四类用例。数据库最终应有六种唯一事件、16 条接收通知、三次已读及三条审计。

执行器使用全新且自有的数据库、容器与网络，结束验证清理；生成默认关闭的 Postman 资产并接入 CI。覆盖汇总保留历史证据性质，不声称全量当前接口通过。完成后提交并推送依赖 PR197 的草稿 PR。外部微信消息、真实上传/支付和生产验收继续单独跟踪。
