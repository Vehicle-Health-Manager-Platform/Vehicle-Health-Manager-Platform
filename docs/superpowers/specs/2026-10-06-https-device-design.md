- 小程序私有配置使用本机 HTTP。上传应用私有配置使用 Docker 内部存储地址和回环 HTTPS 签名地址；原始登录环境中的外部 S3 地址为示例值，不是已有部署证据。检查只输出地址类别，未读取或输出密钥值到共享记录。

## 2. 路径比较与推荐

| 路径 | 本步工作 | 依赖与取舍 |
| --- | --- | --- |
| 自建可信 HTTPS（推荐） | 在用户管理的测试服务器接入 TLS 网关，复用现有 Spring Boot、MySQL、扫描和私有 S3 接口 | 需服务器、备案域名、完整可信证书链；与当前普通 HTTP 请求/上传及签名下载契约匹配，预计客户端改动最少，这是基于现有代码的判断 |
| 微信云托管 | 先验证 `callContainer` 请求、上传、会话与独立图片下载适配，再部署 | 官方免配通讯域名能力限指定调用方式；不能把当前 HTTP 客户端原样当作已适配。需云环境权限及资源预算 |
| 手机局域网调试 | 在明确的本地网络范围提供可达 API/图片地址，测试真实相机交互 | 可先取得设备交互证据；不能据此完成常规 HTTPS/合法域名验收。当前回环监听仍需调整 |

推荐先确认自建 HTTPS 方案，交付部署模板和运维步骤；服务器到位后执行部署，再由实际设备完成验收。尚无服务器时可以完成模板与容器配置验证，但公网和真机项目保持未执行。

## 3. 推荐方案的数据流与边界

使用两个独立 HTTPS 原点：API 域名和私有图片域名，均以手机可达的 443 端口提供服务。方案中的名称表示用途，不是已取得的域名。

1. 小程序通过 API 原点调用登录、车辆、档案、上传与文件短时访问接口。AppSecret、JWT 和数据库凭据仅保存在后端私有环境。
2. TLS 网关将 `/api/` 转发到后端，保留现有上传大小上限、扫描请求超时及错误契约；精确开放 `/actuator/health`，其他管理端点保持内部访问。外部提供 TLS 1.2/1.3，证书与完整链由管理员私有挂载。
3. 后端上传至内部私有 S3，应用只使用独立上传账号。MinIO 管理控制台、MySQL、扫描 TCP 与监控不提供公网入口。
4. `MINIO_PUBLIC_ENDPOINT` 使用图片 HTTPS 原点。图片网关原样保留签名请求的 Host、对象路径和查询参数，避免修改编码或重写路径导致签名失败；只允许预览所需的 GET/HEAD，匿名无签名访问仍应拒绝。签名下载不重定向到内部地址。
5. 网关日志不记录完整签名查询、认证头或请求正文。错误诊断仅保留状态、阶段和脱敏追踪标识；必须核对实际服务器/CDN的日志规则，不能只检查应用日志。
6. 小程序私有构建配置改为真实 API 原点。微信后台登记实际请求/上传/下载原点，域名与端口字符串保持一致；关闭调试例外后分别验收 iOS/Android。

模板只新增可选部署入口；现有本机环境及数据卷继续保留。外部环境使用独立测试数据库、私有桶和账号，按 V001–V005 核实迁移；现有数据库先备份，再执行缺失迁移，不能依靠容器初始化脚本补迁移。只在隔离测试库使用合成车型。

现有 MinIO 版本仅有本机开发证据。外部存储必须单独确认维护状态、S3 兼容性、备份和资源预算；不能因本机联调成功便认定其满足生产运维要求。复用当前适配器时，先用目标存储验证上传和签名读取。

## 4. 环境负责人需要提供的信息

| 信息 | 允许共享的内容 | 提供方式 |
| --- | --- | --- |
| 测试服务器 | 是否已有、所在地区、操作系统/架构、管理员是否可部署 Docker、可用的非敏感入口 | 回答能力信息；登录凭据留在私有环境 |
| 域名 | 可管理的域名、备案状态、是否可添加两个子域名 | 只提供域名和管理能力 |
| 证书 | 是否可取得覆盖两个原点的系统可信证书及完整链、续期责任人 | 私钥通过服务器私有挂载；不提交仓库 |
| 微信后台 | 当前 AppID 能否登记域名、添加体验成员、是否具备手机号能力/额度 | 管理员核对后台能力；不发送 AppSecret |
| 设备与身份 | 是否有 iPhone/Android、微信版本、能否使用第二个测试身份 | 不收集个人手机号、openid 或令牌 |
| 存储与预算 | 复用测试 S3 或新建资源、测试数据保留时间、预算负责人 | 资源开通与付费由用户管理 |

缺少资源时先完成模板验证和验收准备。代码或文档无法证明域名已备案、证书已签发、手机可达或微信主体已取得手机号能力。

## 5. 中文实施顺序

1. 确认本书面方案及部署路径，收集上一节中的非敏感资源信息。
2. 为选定路径编写独立部署模板、私有配置示例及部署/回滚说明；自建方案先验证 Nginx 配置、API路由、上传错误和签名参数透传。模板中的测试证书仅验证配置，不能作为可信公网验收。
3. 在用户管理的测试服务器部署指定源码版本，核对数据库迁移、私有桶、独立账号、官方扫描库新鲜度与健康状态。配置证书/DNS和公网规则后核对 API、图片域名。
4. 运行 `python scripts/check_auth_readiness.py --base-url https://实际API域名`；默认系统证书验证，预检失败先修复入口。随后取得新的测试签名，在可信链下确认实际图片字节、匿名拒绝与到期失效；共享记录不保存完整签名 URL。
5. 构建并导入当前小程序，配置微信通讯域名及体验成员。在关闭调试例外的 iOS/Android 上执行下一节矩阵。
6. 按真实观察记录结果；缺陷用独立 PR 修复并完成 CI。资源缺失的用例单独记录；交付模板通过不等于公网、手机号或真机通过。
7. 回滚先恢复上一后端/小程序版本及网关配置；数据库和文件保留，不执行删卷。数据库迁移兼容性和恢复步骤必须在执行前核实，不将切换镜像当作数据库回滚。

## 6. 真机验收矩阵

每项记录源码/构建版本、设备/系统/微信版本、网络类型、日期及脱敏证据编号。状态使用“未执行 / 通过 / 失败 / 依赖未具备”。两种系统分别记录；仅一台设备通过不能推定另一平台通过。

| 编号 | 操作 | 判定 |
| --- | --- | --- |
| N1 | 关闭调试例外，在 Wi-Fi 与移动网络访问 | API 与图片地址均可达，证书/域名校验正常 |
| L1 | 微信登录、重复登录、刷新、退出 | 真实身份复用；旧刷新和退出会话被拒；沿用登录验收清单 O1/O2/S2/S3 |
| P1 | 点击手机号授权；另测取消授权 | 能力具备时绑定成功且只显示脱敏号码；取消不误报绑定。手机号 code 与登录 code 不混用；无能力时独立记录 |
| C1 | 拍照入口首次授权、拒绝/恢复权限、取消拍摄 | 真实相机调用；拒绝/取消后可返回或重试，无空图档案 |
| C2 | 真实拍摄并上传，断网失败后恢复重试 | 本人文件 CLEAN；原图同键重试不重复落库；至少一张成功图片方可保存，最多五张 |
| A1 | 保存拍照档案，查询列表与首页 | 图片引用、记录来源和车辆归属一致；手动模式仍兼容 |
| I1 | 原生预览，等待签名失效后重新获取 | 实际图片可解码；旧地址到期被拒，重新获取后恢复 |
| X1 | 第二个真实车主尝试访问第一车主的测试车辆/档案/文件 | 服务端拒绝跨用户访问；共享证据不含真实身份值 |
