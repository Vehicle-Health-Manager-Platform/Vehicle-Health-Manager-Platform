# S1 本人车辆档案手动录入与查询

日期：2026-10-04。承接 PR #12 图片 HTTP 入口、PR #13 小程序图片操作、PR #14 本人车辆列表与手动录入。用户确认先交付七类档案的通用字段与图片关联。

## 范围与方案

交付车主小程序中按本人车辆创建、分页查询手动档案及预览已归档图片。档案类型沿用 `vehicle_archive` 的 1 保养、2 维修、3 保险、4 事故、5 改装、6 违章、7 年检；`input_type=3`。通用字段为类型、发生日期、可选里程、标题、可选备注与最多五张图片。各类型专属字段、拍照识别、语音转写、编辑删除、订单自动归档及首页评分提醒留待后续步骤。

比较过三种存储方式：将文件 ID 写入旧 `attach_urls` JSON 改动少，但名称和内容不符；各类型分别建表需要过早确定专属字段；新增档案文件关联表能保留稳定文件 ID、顺序和清晰的关系，因此采用关联表。现有 `vehicle_archive.content` 只保存版本化通用字段，不保存图片 URL。

## 接口与身份

- `POST /api/archive/add`：正式且有效的 OWNER 会话，`Idempotency-Key` UUID 必填。正文仅接受 `vehicle_id`、`archive_type`、`recorded_date`（`YYYY-MM-DD`）、`mileage`（可选非负 INT）、`title`（去首尾空白后 1–80 字符）、`notes`（可选，最多 1000 字符）、`file_ids`（0–5 个不重复的正整数，保持顺序）。拒绝未知字段。服务端从令牌取车主 ID，不接受正文中的用户 ID。成功响应 `archive_id` 和 `vehicle_id`。
- `GET /api/archive/list?vehicle_id=…&page=1&page_size=20`：正式且有效的 OWNER 会话；页码最大 1000000，页大小 1–100。先验证车辆属于本人且未删除，再按 `recorded_at DESC, id DESC` 分页。响应 `{list,total,page,page_size}`；每项返回上述字段及 `archive_id`、`created_at`，图片只返回有序 `file_ids`，不返回对象键或签名 URL。
- 图片先经既有 `POST /api/file/upload` 上传。保存档案时在数据库事务内复核每个 `file_object` 属当前车主、未删除且 `scan_status=CLEAN`；不可用或不属于本人的文件统一拒绝，不泄露他人文件信息。预览时逐个调用既有 `GET /api/file/{id}/access` 获取短时 URL，过期后重新签发；URL 不持久化。
- 参数错误为 400；失效会话为 401；非正式车主为 403；车辆或图片不可用为 404；数据库未配置或暂不可用为 503。响应不包含原始 SQL、对象键、令牌和签名 URL 日志。

## 持久化与一致性

新增 V005 迁移，创建 `vehicle_archive_file(archive_id,file_id,position)`，以 `(archive_id,position)` 为主键，另设 `(archive_id,file_id)` 唯一约束及文件索引。既有 `vehicle_archive.attach_urls` 保留给旧结构，本流程不写入该列；新记录的 `content` 为 `{"version":1,"title":"…","notes":"…","mileage":123}`，`recorded_at` 保存所选日期的零点，API 始终按日期输出。仅使用稳定文件 ID 引用附件。

创建事务锁定并复核有效会话、有效用户和本人未删除车辆，随后校验文件元数据，写档案与关联表。复用 `WriteIntegrityService`：同键同规范正文在 24 小时内返回原响应，同键异正文拒绝；每次重放都重新检查会话，业务记录、响应和成功审计一起提交。审计保留档案 ID、车辆 ID、类型与附件数量，不保存标题、备注或签名 URL。跨车主或失败请求不产生成功审计。

## 小程序流程

档案 Tab 的车辆列表提供当前车辆选择；切换车辆重新加载对应档案，首次为空、加载中、失败与重试各有明确状态。录入页显示通用字段、图片选择与上传、待保存附件及移除操作；可无图片保存，只有上传成功返回的文件 ID 可加入档案。提交时锁定表单；超时或 503 使用原幂等键和原正文重试，修改正文才换键。保存成功回到所选车辆列表并刷新。身份切换、页面隐藏或卸载后忽略旧请求结果，清除私人表单与短时 URL。图片预览失败可重试签名，不将 URL 当作档案数据。

## 验证与交付边界

MySQL 集成测试覆盖本人和跨车主车辆/图片、删除或未扫描图片、附件顺序、多车分页、并发重复、幂等正文变化、会话撤销后重放、审计失败回滚。小程序离线与 H5 替身交互覆盖空态、切车、上传后关联、无图记录、失败重试和身份切换；运行构建与微信模拟器路由检查。记录实际执行证据并更新 OpenAPI、迁移说明、进度文档及独立 PR。CI 和模拟器通过不替代真实微信、私有 MinIO/ClamAV、HTTPS 合法域名或真机联调。生产车型来源与 PR #12 → #13 → #14 的合并顺序仍按既有计划处理。
