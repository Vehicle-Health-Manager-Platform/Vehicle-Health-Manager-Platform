# S0 HTTP 上传与图片访问设计

> 日期：2026-10-04｜状态：用户已批准，A 后端实现及 CI 已完成；B 小程序图片入口待实施｜基线：main / 17f3e6e

## 1. 目标与范围

为下一步 S1 车主车辆档案提供受保护的图片上传和短时预览入口，复用现有文件校验、MinIO、ClamAV 与签名适配器。先完成后端 HTTP、持久化幂等及失败核对；随后独立交付小程序图片选择、上传和预览，每步验证并推送 GitHub。

首步仅允许正式 `user` / `OWNER` 会话。商家、技师、绑定凭证及 local 示例令牌均不可访问。客户端不指定主体、对象键或存储桶。成功上传不代表已关联车辆档案；业务归属关联随 S1 实现。没有公共文件列表、公开桶、直接客户端 PUT 或生产测试验证码。

用户此前确认私有上传环境尚未配置，本步继续在可丢弃 CI 环境验证，不要求用户提供密钥。

## 2. 方案选择

| 方案 | 代价与特点 |
| --- | --- |
| **推荐：后端接收单图片，持久化上传状态** | 复用当前扫描后存储流程；增加独立上传状态与失败清理记录，处理重试、并发和进程中断。适合当前 10 MiB 图片范围。 |
| MinIO 直传隔离区，异步扫描后发布 | 节省后端流量，但需要隔离桶、客户端 PUT、扫描任务及发布协议，当前会扩大交付范围。 |
| 仅加同步 Controller，失败即时删除 | 改动少，但无法可靠处理重复提交和进程中断，不能满足本步验收要求。 |

现有 WriteIntegrityService 在数据库事务内调用业务写入。扫描与 MinIO 操作不能放入该事务；上传采用独立状态协议，复用成功审计和响应结构，而非在既有写事务中调用 PrivateUploadService.upload。

## 3. HTTP 契约

### POST /api/file/upload

- Authorization: Bearer 正式车主访问令牌；Idempotency-Key: UUID，服务端统一小写。
- multipart/form-data，仅一个名为 `file` 的文件，不接收附加业务字段或多文件。
- 文件上限 10 MiB，完整 multipart 请求上限 11 MiB；允许 jpg/jpeg/png/webp，复用扩展名及格式标识校验，不信任客户端 Content-Type。
- HTTP 200，统一 ApiResponse 成功信封，data 为 `file_id`、`content_type`、`size_bytes`。不返回原始文件名、主体、桶、对象键、签名 URL 或扫描详情。
- 同键、同主体、同文件摘要和检测类型：已成功则返回持久化的同一成功响应；重放仍检查当前会话、归属和文件状态。不同正文返回 409；正在处理返回 409 和 Retry-After: 2，不启动另一上传。确定的 503 失败且必要清理完成后，同键同内容可用新随机对象键重试；待核对期间不得重跑，感染拒绝保持原结果。
- 幂等成功记录至少有效 24 小时。期限从成功提交开始，不能在任务执行中仅因期限到达而复用键。到期后的键仅在旧尝试已终止、清理状态明确时允许重新保留；不删除仍需核对的历史对象键。
- 无效格式/字段/文件为 400；超限为 413；感染为 422；未登录为 401；错误角色为 403；限流为 429；配置缺失、扫描异常或依赖异常为 503。

### GET /api/file/{id}/access

- 同一正式车主会话，仅允许读取本人、未删除且 CLEAN 的文件。
- 复用 PrivateFileAccessService，重新检查私有桶与对象大小/MIME，成功返回 data：`url`、`expires_at`。
- 不存在、非本人或已删除统一 404；扫描状态不可读为 409；对象或依赖异常为 503。
- 每次重新签名；不缓存签名 URL。响应使用 Cache-Control: no-store，URL 不进入持久化幂等响应、审计或应用日志。
- 默认 120 秒，配置范围仍为 1–300 秒。签发后撤权不能立即撤回已经签出的 URL；短 TTL 边界需保留在接口说明中。

错误均使用固定安全消息，新增 41300 / 42200；不返回 JDBC、SDK、扫描原文或客户端文件名。

## 4. 处理流程与一致性

1. 在 multipart 解析前验证正式会话、角色、UUID 和入口负载额度，再解析并校验有界文件。会话已经退出或配置缺失时拒绝上传。
2. 计算文件 SHA-256 摘要；摘要与检测类型构成请求指纹，原始文件名不是幂等内容。通过数据库短事务保留主体/路径/键对应的上传记录和预先生成的随机对象键。
3. 同键只有一次有效尝试。扫描和对象写入在事务外执行；存储前后均不暴露临时对象访问能力。
4. 成功前开启短事务，复核并锁定当前车主/会话与上传尝试，原子写入 file_object、成功审计、固定成功响应及 SUCCEEDED 状态。外部对象操作不得进入该事务。
5. 文件元数据、审计或状态提交失败时进入结果核对；只有确认没有成功提交记录且当前尝试已终止，才删除对应随机键。数据库提交结果不明确时不盲删，接口返回 503，同键重试通过记录核对恢复。
6. 上传记录保存 PROCESSING / SUCCEEDED / REJECTED / RECONCILE_REQUIRED；处理尝试包含独立 attempt_id 和截止时间。截止的 PROCESSING 原子转为待核对，旧尝试不得提交成功，也不得借相同对象键再次 PUT。已知失败与不确定结果分开处理。
7. 清理工作先核对成功状态和元数据，再按已登记的专用对象键删除；成功对象不纳入失败清理。旧执行者在终止后产生迟到写入仍需重复核对，不能把单次 DELETE 当作跨存储原子性证明。

现有 PrivateUploadService 的内部接口继续可用。HTTP 上传编排需要抽取可复用的有界校验/扫描/对象处理组件及 JDBC 提交能力，避免调用会独立提交元数据的 saveClean 后再补写幂等响应。重构应保留全部现有测试语义。

## 5. 数据、清理与资源控制

- 新增 V004，不修改 V001–V003：`upload_request` 保存幂等身份、摘要、尝试、对象键、状态、响应、时间和核对信息；`upload_cleanup_task` 保存失败对象清理任务、重试、下次执行和终止状态。唯一索引隔离主体/路径/键及随机对象键。
- 用现有 auth_rate_limit 的独立 scope 实现共享入口计数，不改变既有身份限流语义。上传入口每车主每分钟 10 次，签名入口每分钟 60 次；包含重试及失败请求，返回 Retry-After 到窗口结束。计数不可用时拒绝操作。
- multipart 解析前每实例最多 4 个上传请求占用资源，超过返回 429。配置必须是正数；响应结束/异常/断连均释放。此限额属于单实例保护，不宣称集群全局并发限额。
- Spring multipart 显式设置单文件 10 MiB、总请求 11 MiB 和临时文件阈值；Nginx 上传 location 同步设置 11 MiB 请求限制及有界超时。无 Content-Length 或 chunked 请求仍受实际读取/解析上限约束。超限错误通过后端或代理返回一致的安全 JSON。
- 清理任务通过数据库认领，避免多实例同时执行同一任务；每轮最多 100 条，周期 60 秒，指数退避上限 1 小时。失败继续保留任务，不因次数用尽删除待核对记录。
- PROCESSING 超过 5 分钟可转待核对；扫描/存储各自继续使用现有有界超时。数据库不可用、无权访问桶、对象状态异常时不猜测成功，保留待核对并发出安全事件。
- 清理只针对本次协议登记的随机键；不按全桶扫描删除，不清理已经成功但尚未关联业务的文件。未关联文件生命周期随后续业务契约另行确定。
- 成功审计只包含内部 file_id、主体、检测 MIME、大小和请求 ID，不包含文件字节、原名、摘要、对象键或签名链接。

MySQL、MinIO 不构成分布式事务：进程中断、迟到外部写入及提交结果不明确可能导致暂时不一致。持久化核对降低风险，但不能承诺绝对无孤儿对象；部署需监控待核对与清理积压。

## 6. 验证与交付拆分

### A：后端入口与状态协议（本次实现目标）

- MockMvc：正式会话与角色、绑定/local 凭证拒绝、无数据库/扫描/存储、参数及错误信封、签名响应禁止缓存。
- 实际 HTTP multipart：精确大小边界、超过文件/请求上限、多文件/非法字段、chunked、未登录与并发入口额度。不能只靠 MockMultipartFile 验证容器请求限制。
- MySQL：同键并发、不同指纹、跨主体隔离、24 小时边界、事务回滚、权限/退出复核、仅一次元数据和成功审计、未知提交结果核对及迟到尝试拒绝。
- 真实 MinIO/ClamAV：干净文件上传与签名下载、感染拒绝、匿名访问拒绝、故障补偿、核对重试、对象丢失/篡改/公开策略拒绝；继续注明测试合成病毒签名的边界。
- 迁移脚本和 Compose 初始化追加 V004，重复迁移可执行；现有数据库需要人工补迁移。更新 schema CI、API 草案、接入文档、当前状态与执行记录。
- 六项 CI 通过后交付独立 PR，不把 CI 结果算作真实微信或生产上传验收。

### B：小程序图片操作（后续独立一步）

在车主档案 Tab 增加明确的图片接入验证入口；使用现有内存会话，封装选择图片、uni.uploadFile、同键重试及短时预览。按微信/H5 支持情况处理取消、401、413、429、503 和重复点击。没有真实档案接口时不展示“档案已创建”。页面、离线响应替身及实际模拟器验证分别记录证据。
