# A7.1 核销验码与审计规格

日期：2026-10-09。基线：main `43903c9`，A4–A6 的 PR #35–#44 已全部合并；主分支六项 CI 通过，后端 348 / 小程序 169 项。用户已授权规划后实施及逐阶段上传 GitHub。

## 目标与边界

车主在待核销订单展示已有六位预约码，商家本人输入核销；只有真实成立的接车、车主确认、已接单派工、防护、完整报工与质检签字，以及可信付款记录同时成立，才能从 PENDING_VERIFY 进入不可逆 COMPLETED。历史缺证据订单拒绝自动补齐。

本阶段不执行退款、取消争议订单、第二次异议、超时处理、评价、档案回写、经验卡片或佣金结算。后续分别补充规格实施。真实微信支付尚未接入，正式核销不可借用测试凭据。

## 方案比较与选择

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 在通用 COMPLETE 动作扩展验码 | 少一个接口 | 混合原通用动作与凭据，难隔离核销重放及审计 |
| 独立核销接口与不可修改记录（采用） | 与 A3–A6 专用入口一致；凭据、并发、审计可明确约束 | 增加一张核销记录表 |
| 新发第二个动态核销码 | 与接车码分开 | 需要新增发码、失效及车主交互规则，当前范围无此需求 |

## 服务端契约

- POST `/api/merchant/orders/{id}/redeem`，MERCHANT 会话、本店订单，UUID Idempotency-Key；仅允许 JSON `{code:"六位数字"}`，不得附带查询参数或目标状态。商家读接口不返回正确码。
- GET `/api/merchant/orders/{id}/redemption` 和车主 GET `/api/order/{id}/redemption`：本人/本店授权后返回 `{order_id,redemption:null|{redeemed_at,test_mode}}`，no-store；没有核销记录的历史 COMPLETED 不推定核销。
- 依次锁商家身份/门店→时段→订单→证据/付款；通用 COMPLETE 一律返回 43006，包含目标已完成的重复动作，避免绕过专用入口。
- 复用 A6 证据检查，重新检查未解决争议、接车确认、已接单的同店派工、完整报告及所有关联图片/签字的 CLEAN/未删除状态；不要求完工后技师仍有活跃登录会话。
- 付款必须唯一有效 SUCCEEDED、CNY、金额等于订单快照、非空支付号/渠道交易号/付款时间，且存在同渠道 payment_event outcome=PAID、非空摘要。任何付款异常记录均阻断（不通过软删除规避）。测试渠道只在原隔离 local-payment-test profile + 显式开关 + 合法密钥下开放；直接复用 PaymentChannels 门禁。WECHAT 尚未接入时拒绝；未来正式通道需另行验收，不默认信任数据库状态。
- 每门店每订单共享防猜额度，跨员工/会话共用；固定十分钟窗口最多五次错误，第六次及之后包括正确码返回 429 与 Retry-After。错误计数以独立事务提交，失败业务事务不能回滚计数；格式、权限、状态、证据失败不计验码失败。两次事务之间重新检查全部前置与码。
- 持久核销记录只保存订单、门店、操作员工、付款关联、test_mode、核销时间，不保存码。PENDING_VERIFY→COMPLETED、核销记录、ORDER_COMPLETE 状态迁移、audit_log 与成功幂等响应同事务；任意失败全部回滚。
- 同键同请求重放必须重新授权、检查前置及核销关联；新键对已经完整核销的订单返回当前记录且 changed=false，不新增迁移或成功审计。正确码仍必需；历史已完成但无核销记录拒绝。
- 核销码不写入响应、审计、日志或幂等响应；幂等请求只使用摘要。成功投影 `{order_id,order_status:"COMPLETED",redeemed_at,test_mode,changed}`。

## 页面与生命周期

商家订单详情的待核销入口打开验码页，先展示订单/金额/付款模式，输入六位码并二次确认。测试环境明确“测试核销，未真实扣款，不可作为收款凭据”。提交前后校验身份与订单；断网/503 保留原幂等键重试，429 显示等待，业务拒绝刷新状态；切换账号/隐藏页面清理输入并抑制过期回包。完成页展示核销时间，已完成不能再次执行按钮。

车主订单详情在 PENDING_VERIFY 标明“向商家出示核销码”，完成后不继续展示可用码，可查询核销结果。原 PAID 接车码行为兼容。

## 验收

真实 MySQL：成功/重放/异键重复/竞争只一次、错误码共享限额与窗口恢复、付款缺失/金额/渠道/事件/异常拒绝、证据失效、跨店/撤销会话、通用绕过、三处审计/迁移/缓存故障回滚、码不泄露。HTTP：角色/严格输入/缺库/Retry-After/no-store。小程序：输入、二次确认、失败重试、身份切换、隐藏失效与测试标识；微信/H5 构建。最终运行完整 CI，并用隔离数据库真实 HTTP 串联付款→施工→核销；真机、真实微信收款和测试证书直连图片预览分别标记待验收。

## 规格自审

已对照 Spec F08/F16、来源 §2.3、现有 A3 六位码、A6 证据与支付门禁复核；未新增资金操作或自动恢复。专用入口不可绕过；测试与正式凭据不混用；异常记录不自动解除；原状态矩阵与容量规则沿用。writing-plans 技能未安装，以下实施计划按同等粒度记录任务、验证、阶段上传。
