# S0 私有上传核心设计

> 2026-10-03。用户确认 MinIO 与 ClamAV 尚未配置，先做可离线验证的上传核心。本文待审阅，尚未实施；以 PR #8 的写入完整性分支为基线。

## 需求与方案

原始交付文档 §6.4 指定后缀 jpg/png/jpeg/webp、单文件不超过 10 MB（原文标为假设）、ClamAV 病毒扫描、私有桶与签名 URL；§6.1 指定自建 MinIO。已有 V001 `file_object` 保存主体、对象键、类型、大小和扫描状态。Compose 已有 MinIO，尚无应用上传适配器或 ClamAV 服务。

推荐分两步交付：本步实现不依赖真实服务的上传核心、持久化仓储与存储/扫描接口；下一步接入真实 MinIO、ClamAV、签名访问和 HTTP 接口。这样可以先验证拒绝与失败路径，并明确哪些结果尚未经过真实服务验证。

备选是本步同时完成真实服务适配器、部署和 HTTP 入口，端到端覆盖更完整，但需处理扫描服务启动、私有桶策略、外部签名域名及跨系统重试。另一备选是客户端直传后异步扫描，适合大文件，但需要隔离区、上传凭证和异步恢复；本步图片体积有限，暂不采用。

## 本步范围

- Java 应用服务，接收可信调用方提供的服务端主体、原始文件名及有界输入流；主体只允许现有 `user`/`staff_account` 类型与正数 ID，不从文件内容或客户端字段推导身份。
- 文件校验、病毒扫描接口、私有对象存储接口、JDBC 元数据仓储及测试。
- 复用 `file_object`，不新增迁移，不接入小程序、OCR、施工防护或正式业务附件关系。
- 本步不开放 HTTP 上传或签名 URL 接口，不配置生产替身，也不把接口替身验证计作 MinIO/ClamAV 联调完成。

## 校验与资源约束

采用 10 MiB（10 × 1024 × 1024 字节）作为本步明确上限，读取至上限加一即拒绝；拒绝空文件。扩展名不区分大小写，只允许 jpg/jpeg/png/webp，拒绝路径分隔符、控制字符及缺少扩展名。原文件名不保存到数据库、对象键或日志。

服务根据 JPEG、PNG、WebP 文件标识识别类型，要求扩展名与识别类型一致；不信任客户端 Content-Type。标识校验只确认文件格式入口，不承诺完整图片解码或消除多格式文件风险，病毒扫描仍为必经步骤。对数据的读取、扫描和保存使用同一份受限字节快照，防止验证与存储内容发生变化。单请求内存有上限；HTTP 并发、请求体总上限和用户/IP 限流在入口接入时实施。

## 数据流与失败行为

1. 校验主体、文件名、大小及格式；失败不创建元数据、不调用扫描或存储。
2. 扫描接口返回 `CLEAN`、`INFECTED` 或 `UNAVAILABLE`；只有 `CLEAN` 可以继续。未知或缺失结果按不可用处理，病毒拒绝与扫描故障均不存储，不创建可读文件。
3. 服务生成随机对象键，不接受调用方指定路径；私有存储接口必须确认目标为私有配置，否则拒绝操作。不存在可用的扫描器或私有存储实现时返回服务不可用，不自动使用测试替身。
4. 扫描通过后保存私有对象，再用短数据库事务插入 `file_object`，记录 `owner_type`、`owner_id`、对象键、识别出的 MIME、实际字节数与 `CLEAN`。成功仅返回文件 ID、类型和大小。
5. 对象保存失败不写元数据。数据库插入或提交失败后尝试删除对象；补偿失败以不包含原文件名、内容、凭据或签名的结构化事件记录随机对象键，供后续清理使用，不向调用方返回存储细节。存储接口须明确失败可能留下对象，上传失败时也尝试删除该随机键。跨数据库与对象存储不能承诺原子提交。

扫描与对象存储属于事务外副作用，不放入已有 `WriteIntegrityService` 的事务回调。后续 HTTP 写入口需另行设计幂等上传及孤儿对象清理，不能直接套用 JDBC 原子写服务。

## 私有读取边界

提供内部元数据查询服务，以当前服务端主体检索文件 ID，拒绝跨主体、删除记录及非 `CLEAN` 状态。对象键只供受信任的存储调用方使用，不作为本步公共响应。本步不签发 URL；下一步真实适配器必须在权限复核后产生短时签名 URL，并验证未签名对象访问被拒绝。

本步同步扫描，不产生持久化 `PENDING` 文件。读取检查仍拒绝现有表中的 `PENDING`、`INFECTED`、错误或未知状态。正式车辆/商家附件授权需要业务关系检查，单纯上传主体归属不能替代这些规则。

## 错误、验证与交付

应用错误区分无效文件、病毒拒绝、无权限/不存在、扫描/存储/数据库不可用；不暴露扫描器原始输出或数据库异常。HTTP 状态码、multipart 请求契约与 API 错误映射在后续入口接入时确定，本步不增加 OpenAPI 操作。

离线测试验证四类允许扩展名、扩展名与格式不匹配、非法名称、空文件、精确大小边界、超限读取停止、病毒/未知结果/故障拒绝、私有配置拒绝、服务缺失、存储失败补偿、数据库失败补偿及补偿失败事件。替身记录扫描和存储接收到的字节，确认内容一致；验证扫描未通过时无存储调用。

MySQL Testcontainers 实际验证元数据插入、主体隔离、删除与扫描状态拒绝、数据库失败后补偿。Docker 不可用时测试不得跳过，CI 为本机无法运行后端测试时的验证证据。继续运行已有六项 CI，完成后更新执行记录、当前状态与下一步规划，每步推送 GitHub 独立 PR。

## 后续接入与自检

下一步实现真实 MinIO/ClamAV 适配器、部署配置、私有桶与签名访问验证，随后设计 HTTP 上传入口的幂等、并发/限流和清理策略，再接入具体业务。本步不计作 S0 私有上传全部验收完成。

自检：扫描通过是存储必要条件；主体来自可信调用方；文件大小与读入边界明确；外部副作用未混入 JDBC 原子事务；存储补偿失败与真实服务未验证均有明确处理范围。无需私有凭据即可实施本步测试。
