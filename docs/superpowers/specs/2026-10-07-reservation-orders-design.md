# 商家时段发布、车主预约与本人订单

日期：2026-10-07。基线：main `34e92f5`（PR #23）；合并后 CI `37470310896` 六项成功。用户已确认商家发布时段与名额，并确认本步业务范围。状态：书面规格待用户复核。

## 目标与交付范围

完成 F07/F08 的本机预约与订单子集：商家发布项目时段，车主从在售报价选择本人车辆和可用时段，创建待支付订单；查看本人订单、详情和取消待支付订单。预约保存报价版本与价格快照，名额、幂等响应与成功审计同事务。

曾比较三种路径：商家发布时段可独立管理并验证完整业务链路；人工测试时段可较快验证车主页面但缺少商家管理；仅订单查询无法验证预约创建。用户选择第一种。

支付、优惠券、退款、商家接车/派工与核销后续独立设计。页面明确待支付及支付能力尚未接入，不伪造支付成功或修改为已支付。本步不判定完整 F07/F08 或 S2 验收通过。公网、云托管和真机按用户决定后置。

## 商家时段规则

- 时段属于一个商家及标准项目；商家仅为本店启用、上架且未删除的报价发布。服务端复核有效 MERCHANT 会话、员工及已审核商家。
- 时间输入为带时区 ISO 8601，按 `Asia/Shanghai` 解释日历日期并展示，数据库存 UTC。开始时间必须晚于服务器当前时间，且不晚于当前时间加 30 天；起止时间在北京时间同一天，开始早于结束。精度为分钟，秒和小数秒须为零。
- 容量为整数 1–100。容量属于“本店、项目、时段”，不推断跨项目共享工位或全店总容量；后续若引入工位排班需另行设计。
- 同店同项目未删除时段不得重叠，采用半开区间 `[starts_at, ends_at)`，允许前一段结束时下一段开始。已关闭时段也保留这一约束，避免其已有预约与重新发布的重叠时段重复占用服务安排。
- 发布后时间、项目和容量不可编辑。本步支持关闭时段，关闭仅停止新预约，保留已有订单及历史；不软删除或复开。时间结束后不再作为可预约时段展示。
- 同店发布、关闭与订单占位用商家/时段锁串行，不能通过并发请求发布重叠窗口或超过容量。

## 车主预约与价格确认

- 有效 OWNER 只选择本人未删除车辆、已审核商家、启用标准项目、在售报价，以及匹配该商家/项目的开放且未开始时段。
- 前端提交 `merchant_project_id, quote_version_id, vehicle_id, slot_id`。不接受 user_id、merchant_id、金额、订单状态、券等额外字段。
- `quote_version_id` 必须等于该报价当前版本。包括价格或上下架版本变化均返回可识别的冲突，页面重新加载报价并要求车主重新确认后再提交；服务端不会静默按新价格下单。
- 金额使用版本中的两位小数字符串及 DECIMAL。`amount=pay_amount`，无券折扣；保存项目名称/内容、商家名称/地址、报价 ID/版本 ID/版本号/金额、预约起止时间的下单快照。后续改价或关闭时段不会改写已有快照。
- 创建订单状态为 `PENDING_PAYMENT`，到期时间为“创建后 15 分钟”与“时段开始时间”中较早者。返回订单 ID/编号、应付金额、状态与到期时间，成功后查询订单详情。
- 可预约列表仅显示未开始、开放、未删除且有剩余容量的时段；未来日期查询范围覆盖北京时间今天至未来 30 天。无可用时段显示真实空态。

## 状态、取消与超时

本步状态为 `PENDING_PAYMENT → CLOSED`，关闭原因分别为 `OWNER_CANCELLED` 或 `PAYMENT_EXPIRED`，并记录关闭时间。与现有数据库/S0 字符串状态保持一致；不引入已支付转换。

待支付订单可由本人取消。已关闭订单再次取消返回当前结果，不再次释放容量或记录重复关闭审计；其他状态取消被拒绝，不能代替退款。已过期的待支付订单先按超时关闭，原因不改为主动取消。

后台每 30 秒批量扫描到期订单，在事务中锁定并复核状态和到期时间，关闭订单、释放一次名额并写系统审计。单条失败回滚并留待重试，不影响同批其他订单；多实例/重复执行只允许一次有效关闭。系统审计使用固定系统主体 `actor_type=system, actor_id=0`，无客户端系统身份入口。

剩余名额读取按实际仍占用的订单计算，过期的待支付订单不计入展示名额；创建预约时在已锁定的时段内先处理其到期订单，再校验容量和新增占位。这样后台暂时延迟不会把已释放的展示名额错误判为已满，也不会超卖。关闭时段的既有待支付订单仍按上述规则过期或取消。

## 数据结构与事务

复用 `appointment_slot` 与 `order`，新增 V007 可重复迁移：时段开放状态/关闭时间；订单报价关联/报价版本引用、关闭原因/时间和预约快照，以及查询/到期处理索引。已有订单不回写历史快照、不推断历史支付或关闭原因；旧数据缺失新增字段时详情做明确兼容展示。

模块按职责拆为时段发布与查询、订单创建/查询/取消、超时处理、小程序会话与页面状态。复用现有本人/本店身份校验、统一 ApiResponse、24 小时幂等及成功审计，避免给报价维护类增加订单职责。

人工写操作以当前会话主体隔离幂等键，同键同正文重放创建结果；同键异文为 400。缓存命中复核当前身份及请求主体，不要求历史报价仍在售或历史时段仍开放，不再次占位。创建响应重放为首次响应，当前订单状态由详情接口获取。

创建时事务保存订单、名额占用、快照、成功审计与幂等响应；取消保存订单关闭、释放名额、成功审计与幂等响应；任一步失败整体回滚。发布/关闭时段也接入幂等和审计。

采用一致锁序：身份相关锁在前；业务锁按商家、项目/报价（需要时）、时段、订单顺序。批量到期处理逐条事务，先读取候选关联 ID，再按锁序锁定并重新验证，避免与创建/取消形成锁顺序倒置。读列表与计数使用同一读取事务。

## 接口

| 路由 | 身份与参数 | 结果 |
| --- | --- | --- |
| `GET /api/merchant/slots` | MERCHANT；可选 date，分页 | 本店时段、项目名称、容量/剩余名额、开放状态；默认未结束时段 |
| `POST /api/merchant/slots` | MERCHANT；standard_project_id, starts_at, ends_at, capacity | 新时段 ID 与规范化字段 |
| `POST /api/merchant/slots/{id}/close` | MERCHANT；空对象正文 | 关闭后的时段 |
| `GET /api/order/slots` | OWNER；merchant_id, project_id, date | 匹配项目的可用时段、起止时间、capacity_left |
| `POST /api/order/create` | OWNER；merchant_project_id, quote_version_id, vehicle_id, slot_id | order_id, order_no, amount_due, status, expires_at |
| `GET /api/order/list` | OWNER；分页，可选 status=PENDING_PAYMENT/CLOSED | 本人订单及快照摘要 |
| `GET /api/order/{id}` | OWNER | 本人订单详情、快照、状态/关闭原因、到期时间 |
| `POST /api/order/cancel` | OWNER；order_id | 当前订单关闭状态与原因 |

人工 POST 均要求 UUID Idempotency-Key，严格白名单正文、安全正整数 ID，GET 分页默认 1/20、页大小最大 100、页号上限 1000000；时间返回带时区 ISO 8601。本人订单按创建时间/ID 倒序，时段按开始时间/ID 升序。

统一 no-store：400 参数/幂等键错误；401 身份失效；403 角色无权；404 不属于本人/本店或资源不可用；409 版本改变、时段重叠/关闭/开始或名额竞争等冲突，细分业务码让页面区分重新确认与重新选时段；503 数据库/事务不可用。不能泄露 SQL 或他人订单。

## 小程序

- 商家本店服务入口新增时段管理：选择本店在售项目，填写日期、开始/结束时间与容量，发布并查询服务器结果；确认关闭时段。
- 车主报价条目增加预约入口，携带报价与版本引用；预约页选择本人车辆、日期和可用时段，展示当前报价与期限，确认后创建。
- 版本冲突先清除旧报价确认和待提交正文，重新加载服务器价格；需用户再次确认。名额/时段冲突重新加载时段；不自动选择或自动提交另一个时段。
- “我的”接入订单列表及详情；待支付展示服务端金额、预约时间、到期时间和取消操作，明确支付尚未接入；关闭展示原因。
- 所有页面覆盖无车/无时段/无订单、加载与分页失败重试、身份变化/页面隐藏后的迟到响应隔离；同一正文网络结果不明保留原键，编辑换键，提交中防止重复点击。倒计时只用于显示，状态由服务器复核。
- 项目/店铺文字纯文本显示；隐藏用户敏感身份信息，不输出令牌或车牌原文。
