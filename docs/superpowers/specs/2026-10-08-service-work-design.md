# A6 防护与报工规格

## 范围与依据

依据 DELIVERY_V1 §5.9、§5.10、§8.3、§12.1，延续 A5.6 的本人派工与争议恢复规则。用户已要求开始编码、每阶段同步文档并上传 GitHub。本次采用 brainstorming 的规格复核流程，按已有实施授权继续。

退款、取消争议订单属于 A7；第二次异议、超时自动处理不在 A6。签字后进入 PENDING_VERIFY，不完成核销、不归档、不生成经验卡片。

## 设计选择

选择复用 repair_protection、technician_report，加私有文件关系和报工提交元数据。另建全部业务表会重复既有模型；直接存永久 URL 会失去权限、扫描与关联校验。历史无证据记录一律拒绝修改，不猜测补齐。

1. 商家提交勾选项和一张防护照片；座椅套、方向盘套必选，照片须同时包含两者，由商家实际拍摄确认，服务器不声称识别照片内容。脚垫、翼子板布可选。接车完成、车主确认 1/3、无 OPEN 争议、订单 RECEIVED/IN_SERVICE 才能提交。提交后不可改。
2. 技师使用独立上传接口，沿用图片类型/大小/扫描/限流/24小时幂等。会话、当前 app 的有效工号绑定、员工与商家状态均须复核，不能借用商家上传权限。
3. 报工只允许当前 ACCEPTED 的本人派工且订单 IN_SERVICE。防护记录及关联 CLEAN 图片必须有效。施工照、完工照各 1–9 张；故障件照 0–9 张，no_fault_parts=true 时必须为空且故障分析明确写无故障件，否则至少一张。所有图片 ID 不重复，不接受 URL。
4. 施工内容、故障分析各 1–2000 字。配件最多 20 条，名称/型号/品牌各 1–100 字，数量 1–999；无配件必须显式 no_parts=true 且列表为空。工时为整数分钟 1–1440。工时及配件为实际填报值，不自动推断。
5. 完整报工一次提交后不可改，状态保持 IN_SERVICE。独立质检签字接口必须使用本人 CLEAN PNG 签名图；服务器只验证文件，不声称判定签名真伪。重新核对全部证据后，原子写 signed_at、报工状态 1、service_report_ready_at、订单 PENDING_VERIFY、迁移审计与幂等响应。
6. 商家通用 FINISH_SERVICE 停用（43005），只能本人质检签字送核销，时间戳不能旁路。COMPLETED 仍留待 A7。
7. 每次写入先复核身份、归属、接车确认、争议与文件，再读取幂等缓存。相同键相同请求可重放；新键不能修改既有记录。状态冲突 40905，缺防护 43002，缺报工 43005，未解决争议 43007；跨店/跨技师 404。
8. 文件与记录关联唯一。不可复用接车照片或其他施工证据。图片访问必须由本店商家或本人工单技师经过订单关联授权获得短期签名；不公开对象路径、签名 URL、身份 ID、车牌、VIN、预约码或付款信息。所有业务响应 no-store。
