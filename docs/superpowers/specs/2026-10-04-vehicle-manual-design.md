# S1 本人车辆列表与手动录入

日期：2026-10-04。用户已确认先实施车辆列表、有效车型查询与手动添加，档案录入随后实施。

## 范围与依据

依据 DELIVERY_V1 的 F02、C06、§6.4、§8.3–8.5，交付档案 Tab 的本人车辆列表和 `/pages/vehicle/manual` 手动选择页，配套五个既定 API。品牌→车系→年款→配置选择必须对应数据库中的有效 model。外部授权车型库来源尚未确定；接口查询已有库，空库如实显示，没有生产自动种子或虚构车型。测试种子只用于隔离验证。

推荐先交付这个页面/API/落库流程；仅写后端缺少可操作验收，一次加入档案、OCR、VIN 解码则增加未经明确的依赖。完整 F02、F03、F04 和 M1 不在本步完成范围。

## 契约

- 五个接口都要求正式 user/OWNER、有效 jti、未撤销未过期会话和有效用户；local 演示令牌不能调用。身份来自令牌，正文不接收 user_id。
- `GET /api/vehicle/list`：page 默认1、page_size默认20且最大100；只返回本人未删除车辆，按 id 降序。data 为 list、page、page_size、total。列表显示车型、当前里程及脱敏车牌/VIN，不返回原文。
- `GET /api/brand/list`、`/api/series/list?brand_id=…`、`/api/model/list?series_id=…`：同样分页；只返回有效父子链，稳定 id 排序。车型含 year/config_name。前端支持继续加载，无截断为“全部”。
- `POST /api/vehicle/add`：Idempotency-Key UUID 必填，正文仅允许 add_type=4、model_id（必填正整数）、current_mileage（默认0，非负INT）、plate_no（可选普通/新能源大陆号牌）、vin（可选17位大写、排除I/O/Q）。空可选串归一为缺省。买车日期等未使用字段本步不开放。响应 vehicle_id、model_name、need_archive=true。
- add_type 的4为本步显式约定（原文未定义数值映射）；其余入口不在本接口接受范围。车牌/VIN归一大写并校验，同一车主的未删除车辆不得重复同一非空车牌或VIN；不同车主允许分别登记，不据此推断车主拥有法律所有权。服务端通过用户行锁串行检查与创建。
- 复用 WriteIntegrityService：24小时内同键同规范正文返回原响应；同键异正文400。每次重放先复核有效会话。成功审计仅保存 vehicle/model/里程，不保存原文车牌VIN；业务、响应、审计一起提交。车型父子链在新增事务中锁定复核；重放不依赖车型当前可用，但必须仍为有效车主。
- 缺少数据库返回503；参数400、过期身份401、身份类型403、车型无效404、同车主车辆重复409。前端用固定提示，不展示上游异常、车牌VIN或令牌。

## 页面与生命周期

档案 Tab 登录后提供真实列表、首次空态、加载、失败重试、分页及手动添加入口，保留图片准备卡。手动页级联选择四级车型；上级改变清空下级，年款从已加载车型派生，同年配置选择 model_id。车型页分页未加载完时提供继续加载；空库显示暂无车型，禁用提交。

可选车牌、VIN和里程在用户确认前校验，保存期间禁用编辑和重复提交。首次保存生成UUID；网络/503失败保留原键及正文重试，编辑正文才生成新键。身份切换清除私人列表和表单并忽略旧异步结果；页面隐藏停止接受旧结果，保存成功返回档案Tab重新查询。

## 数据与后续档案

复用 V001 vehicle/brand/series/model 及 V003 会话，不改历史迁移。无新增表。F03 下一步按本人 vehicle_id 查询/创建；类型遵循 vehicle_archive 的1保养、2维修、3保险、4事故、5改装、6违章、7年检；手动 input_type=3。图片必须引用本人CLEAN file_id并记录稳定ID，签名URL不入档案；具体字段与附件关系由下一步设计确认。本步不提前开放 archive 接口。
