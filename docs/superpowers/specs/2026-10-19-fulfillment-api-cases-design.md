# A4d-2b1 预约履约 API 业务验收

## 范围

在已完成车辆/手动档案业务验收之上，验证预约→LOCAL_TEST 支付→接车确认→派工→技师施工/签名→核销→自动归档的真实 HTTP 闭环。车主、另一车主、门店、另一门店、已绑定技师均为全新隔离库中的合成身份。为独立完成这一阶段，券的正向交易及退款回退单列下一阶段 A4d-2b2。

## 方案与约束

复用隔离 Docker/Newman 运行器和生成资产模式；较仅复用 JUnit 旅程增加可交付 Postman 用例与严格执行证据，较一次扩展全部业务域使失败可以定位到履约链。每个纳入接口均有正常、边界、错误和未授权案例。实际方法/路径/查询/身份/断言与声明一致才可通过；匿名回调的授权采用 HMAC 验签，不能以 JWT 代替。重复写请求重放须返回相同结果，数据库关键业务行只能产生一次。

隔离后台仅显式开启 local-payment-test 配置与自动服务归档，不连接真实微信或支付渠道。合成 CLEAN 文件元数据只验证施工材料归属，实际上传/扫描另验。仅发布脱敏汇总，私有环境、JWT、预约码和回调签名原始日志保留忽略目录。

## 验收

当前来源构建 jar，新建数据库执行全部迁移，运行匿名门禁与默认禁发模板，再运行履约集合。检查支付事件、接车、派工、报告、签名、核销、归档任务/记录等业务事实、重复提交不重复入库、他店/他人不可见。源码与迁移稳定，隔离容器/网络回收成功方可 PASS。完整 API 验收仍未完成，性能延迟未达标继续保留。
