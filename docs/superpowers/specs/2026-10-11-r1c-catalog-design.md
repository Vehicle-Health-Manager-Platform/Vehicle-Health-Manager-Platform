# R1c 标准项目、品牌车系车型治理规格

日期：2026-10-11。沿用已批准的三端业务优先路线，仅微信小程序与必要后端。正式身份接入后置。

## 方案与范围

选择扩展既有标准目录表：保留 ID/历史引用，在受限运营入口维护。另建平行目录会引入同步与引用迁移；直接用删除字段表示停用会混淆历史数据，因此采用明确发布状态。

- 四种资源 `projects/brands/series/models`，新增 `sort_order/revision/source_note`，品牌/车系/车型新增 `status`。既有非删除记录默认发布以兼容既有数据；新建默认未发布。无物理删除。
- 独立 `can_catalog` 权限默认关闭，与经验/入驻审核互不交叉；离线运营 CLI 显式授予，撤销同时撤销会话。维护接口开关 `CATALOG_GOVERNANCE_ENABLED` 默认 false。
- 列表分页每页最多50；创建/更新严格 JSON，拒绝未知、重复字段、错误类型。更新携带 revision，过期更新409；写请求UUID幂等，重放仍复核身份权限。
- 所有资源包含 sort_order（0–9999）与 source_note（2–256字符，无控制字符，说明合法数据来源）。品牌 name（2–64）；车系 brand_id/name（2–128）；车型 series_id/year（四位年份1900–2100）/config_name（1–128）/power_type（FUEL/HYBRID/ELECTRIC）；项目 name/category（1–6）/service_content/quality_standard/参考价范围（字符串两位小数，0–999999.99）。
- 上级创建后不允许改挂；发布子项须上级链已发布，停用父级使新选择隐藏子项，但不修改子项自身状态。以父级先锁、子级后锁的固定顺序避免竞态。
- 已被车辆引用的品牌/车系/车型身份字段（名称、年款、配置、动力）禁止修改，仍可调整来源说明、排序、发布状态；避免既有车辆名称随目录改写。项目历史订单依既有快照保留。
- 同父级车系名称、同车系年款配置不能重复，品牌/项目沿用唯一名约束。冲突409，不泄漏SQL。
- 服务/录车新读取仅已发布且上级可用，按 sort_order/id 排序；车主录车提交实时锁定复核整条链。停用项目阻断新报价启用/预约，门店可以下架已有停用标准的报价；历史订单与施工档案不重写。
- 门店不新增标准库权限，选品/定价仍限店长。维护动作、状态/来源与前后投影写审计，不能出现身份密钥。
