# R4a 受限图文/PDF提取内核

承接PR247，用户已授权规划后实施。本轮完成内部提取内核、来源协议、受限运行及实测；R4b再把它接入持久任务/鉴权/页面，不新增无鉴权的公开文件接口，不把本轮内核称为完整车主业务交付。

选择复用既有PDFBox3.0.5和固定PaddleOCR模型。直接在HTTP/JVM请求内解析多页会绕过运行预算；另引入PDF/云OCR供应商增加依赖及外部数据传输。本轮不安装新模型或改变业务图片上传白名单。

输入只含固定媒体类型与文件字节：JPEG/PNG沿现有4MiB/边4096/600万像素与EXIF规范化；PDF沿10MiB静态文件校验，但提取最多4页、总文字4096 UTF16单元、80行/每行500单元。任何超限整次失败，没有截断成功。PDF页有XObject、内联图像、绘图内容或无原生文字时栅格化后OCR；原生文字页保留页号与规范化提取文字的UTF16偏移，OCR保留实际栅格尺寸及实际多边形，不推测日期/金额/里程为业务事实。候选必须人工核对。

Java私有CLI在任务独立临时目录解析/栅格化，单页最长边2048、最多400万像素、PNG不超过4MiB，最多4份栅格。Python内核组合页面与OCR；Paddle实际rec_polys缺失或形状/分数/文字不合法时失败，不伪造位置。EXIF/旋转后的OCR坐标明确相对最终栅格，不把页内文字偏移冒充原PDF像素坐标。

运行器是显式本地验收工具，容器无网络、非root、只读模型/输入/源码、2GiB内存/CPU2/PID限制及受限tmpfs。受控子进程设置父退出、CPU/文件上限和seccomp禁止socket；Java继承限制，超时终止进程组且回收。只处理本轮合成PDF/图片，不读用户材料或取得公开访问URL。生产接入前仍需独立部署、任务授权/撤销/TTL、持久化与真实用户效果验收。

退出：真实原生/空白/扫描/混合/旋转PDF与图片来源验证，损坏/加密/活动内容/超页/预算/超时负向测试，既有上传/里程/行驶证OCR回归，分项证据/操作指南和草稿PR。中文OCR部分或无值须保留真实失败，不将合成Provider当实际模型效果。
