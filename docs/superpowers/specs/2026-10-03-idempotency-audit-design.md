# S0 受保护写请求的幂等与审计设计

> 2026-10-03。承接[下一步规划](../../progress/NEXT_STEPS.md)的可离线推进项。用户已确认开始，核心与 local 示例已实施并通过 CI，证据见[S0 执行记录](../../progress/S0_EXECUTION_LOG.md)。真实微信凭据、已迁移联调数据库、HTTPS 后端与短信通道仍待确认。

## 当前基础与方案选择

后端已有 Spring JDBC 和事务管理器；V001 中的 `idempotency_record` 具有主体、方法、路径、幂等键的唯一索引，并保存请求摘要、成功响应和过期时间。`audit_log` 保存操作者、操作、资源、变更前后状态与请求 ID。现有本地车辆接口只演示归属读取，没有真实业务写入。

采用应用服务加 MySQL 事务：业务变更、成功响应与审计记录在同一事务中提交，可直接复用现有表，并验证并发和失败回滚。

备选方案是 HTTP 过滤器自动覆盖全部写接口，优点是接入代码较少，但难以保证控制器业务与缓存同一事务，并会干扰一次性授权 code、刷新和退出；另一方案是 Redis 去重锁，协调速度快，但本步业务仍在 MySQL 中，跨存储提交需要额外故障恢复。推荐第一种方案。

## 本步交付范围

实现可供后续业务调用的事务服务，并在仅 `local` profile 生效的 `POST /api/demo/vehicles/{id}/mileage` 中首次接入。示例更新测试数据库 `vehicle.current_mileage`，审计只记录里程数字及内部资源 ID；不自动创建或覆盖测试车辆，也不接入小程序页面。测试用例创建可丢弃的测试数据，人工复现仅在明确的本地测试库执行。

该示例是 S0 写请求验证入口，不能计入 S1 车辆录入、正式里程报工或完整审计交付。生产 profile 不暴露 demo 写接口；认证、手机号 code、员工码绑定、刷新、退出与渠道回调不通过本业务幂等服务。此步不需要修改 V001 或增加表；如实现发现原表约束不足，必须新增迁移，不能修改已发布基线。

## 请求契约和权限

- 使用服务端验证后的 JWT，要求车主角色；主体与车辆归属来自服务端，拒绝客户端提交的操作者和车主 ID。本地示例可使用现有 local-only 测试令牌，正常业务调用不得放宽身份验证。
- `Idempotency-Key` 必须是 UUID，统一为小写标准形式；缺失或格式错误返回 HTTP 400、`40001`。作用域是服务端主体类型、主体 ID、HTTP 方法与标准化资源路径；不以会话 token 为键，换 token 后同主体仍可重放。
- 请求正文仅允许 `current_mileage`，为非负整数。首执行不能降低已存里程；未知字段、无效正文或状态冲突返回 HTTP 400、`40001`。主体无权限返回 403、`40300`，车辆不存在返回 404、`40400`；未配置数据库返回 503、`50300`。
- 请求摘要为验证后规范 JSON 的 SHA-256。同一作用域及键，24 小时内相同摘要返回已保存的成功响应，包括原 `request_id`；不同摘要返回 HTTP 400、`40001`，不改车辆或新增成功审计。该示例成功状态固定为 HTTP 200。

## 事务与并发规则

每次请求均先验证当前身份与资源归属，再查看缓存；已失效身份、已删除或改归属资源不得通过重放访问历史成功响应。授权和执行检查在事务中完成，执行过程中锁定车辆行；所有调用保持相同锁定顺序。

幂等键的唯一索引及行锁用于跨实例串行化同一作用域的请求。事务服务取得记录锁后，检查数据库 UTC 时间与有效期：有效成功记录按摘要返回或拒绝；不存在或已过期记录执行一次业务操作。执行成功后，生成统一响应，写入审计和响应缓存，并设置自成功完成起 24 小时的有效期，最后提交事务。提交前不会向客户端返回成功。

业务、审计写入、响应序列化或幂等缓存保存任一失败，全部回滚。失败响应不缓存；修复后可用同键重试。进程在提交前中断由数据库回滚；提交成功但客户端未收到响应时，同键重试取得已保存响应。同键并发等待前一事务完成，不能出现两次成功变更。锁超时、死锁或数据库不可用返回安全的服务不可用提示，客户端可以同键重试。

过期键在行锁保护下重新用于一次操作；并发的过期键请求仍只能执行一次。此步不增加删除历史审计的任务；幂等历史批量清理与审计保留策略另行实施。

## 审计边界

本步保证成功示例写操作有且只有一条审计，保存服务端主体、动作 `VEHICLE_MILEAGE_UPDATE`、车辆 ID、前后里程、原始请求 ID 与时间。成功重放不新增审计。密码、验证码、访问或刷新令牌、手机号、车牌、VIN、原始请求和错误堆栈不写入该记录或业务日志。

本步审计覆盖成功变更；权限拒绝、认证失败、审核、退款、上下线和改价的完整审计应在相应业务实现时接入，不能因已有审计表和本地示例而标记为全部完成。
