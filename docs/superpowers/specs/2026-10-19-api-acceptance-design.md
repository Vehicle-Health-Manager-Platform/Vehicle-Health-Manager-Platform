# A4d-1 全API验收资产与匿名门禁

用户已授权规划后直接实施和阶段上传。沿用brainstorming梳理边界、planning-with-files记录执行，不重复已经完成的A4c-2及视觉刷新。

现状：352项OpenAPI契约，其中338项受保护、14项公开；全部API的Postman/Newman正常/边界/错误/未授权验收仍有差距。选择从源契约生成验收资产，并先完成可独立执行的匿名门禁；相比手工复制352项不会漂移，相比直接补全所有正向状态夹具，本阶段范围明确且无需外部服务。

交付三个生成资产：338项匿名401检查集合；352项默认禁发的业务请求准备集合；逐API正常/边界/错误/未授权状态清单（初始NOT_RUN，公开接口另审，不自动标通过）。缺少operationId时生成确定性ID，不修改原契约。身份/文件/业务写入由后续场景配置，禁止虚构有效载荷。

复用已验证的性能阶段隔离容器封装，新建网络/MySQL/当前后端jar，执行全部迁移；Newman6.2.1实际运行338项请求，检查401、code40100、no-store，并验证确实访问预期方法/路径、无缺失/跳过、前后表行数一致。每次检查容器归属并清理，不接受外部服务地址或真实账号。仅匿名集合自动运行；业务集合必须显式开启和配置预期结果、身份及请求变量。

完成标准：真实Newman证据、必要生成器/证据门禁测试、CI一致性/执行步骤、中文复跑及剩余案例说明、整阶段上传。匿名401不证明控制器已实现，也不证明角色、归属或全部业务案例已验收。性能延迟仍保持未达标事实，正式身份、资金、识别仍留B段。
