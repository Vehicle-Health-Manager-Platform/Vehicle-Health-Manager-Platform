# R4a4 本人读数历史与修正履历

2026-10-12。承接 R4a3；用户要求规划并开始实施，仅微信小程序与必要后端，所有 README 等用户另行要求。

## 方案与范围

采用不可变追加事件表。仅覆盖当前值会丢失修正前数据；完整事件重建会增加现有六类读数接口的复杂度。因此保留当前值表并在同一事务追加历史，提供分页表格。本阶段不做健康评分、曲线、供应商数据或私有历史删除。

新增测量 RECORD（省略 operation 时兼容旧客户端）；CORRECT 只允许修正同一有效来源的当前非空读数，并以 expected_revision 指明被修正的版本；空 measurement 表示 CLEAR，只允许省略 operation 或显式 CLEAR。来源替换必须明确 replace_source；修正不能换来源。新测量可填写过去日期，当前值由最后成功写入决定，不代表最近测量日期。

修正保存完整六字段，追加新版本及 supersedes_revision；原行不覆盖。多次修正形成链，只可修正当前版本。清空保留历史、档案与照片，后续新增不会恢复旧当前值。重复清空拒绝；修正缺失/失效/已清空版本拒绝。

## 存储与迁移

V031 新增历史表，唯一键本人/车辆/指标/版本。迁移把已有每个当前槽位保存一次 MIGRATED_SNAPSHOT（包括空槽位），明确仅是迁移时状态，不制造此前测量或修正链。重复迁移不重复插入。应用新增、修正、清空的事件与当前更新、通用审计及幂等回执原子提交；审计和回执不复制私人测量值。

## 读取与权限

GET /api/vehicle/health-observation-history，vehicle_id、metric、before_revision（可选）、limit（默认20，1..50）。按版本倒序，用最后返回版本作为下一页游标；取 limit+1 判断 has_more。每页鉴权本人有效会话、当前车辆所有权，并逐条验证原档案仍属于车辆、类型正确、录入类型1/3且未删除。来源失效时隐藏档案ID、日期、measurement；车辆转移后新车主不能继承原车主历史。历史还显示原值是否被修正；清空事件没有数值。

比较仅在来源档案、名称、单位、方法、本人来源均相同时有意义；界面逐行显示来源、日期及方法，不连线、不计算差值或分数。分页不是完整趋势；迁移快照不声称是一次新的测量。

## 小程序与验收

六类读数每类均可进入历史（包括未知或来源失效）；历史分页、刷新、登录恢复，隐藏/注销/切换账号清除内存读数并忽略迟到响应。编辑页独立新增测量/修正当前按钮与修正确认；弱网重试保持同内容UUID，操作变化更换UUID。

验收：迁移重放；新测量/修正链/清空；幂等/并发/审计失败回滚；权限/源删除/转移；游标边界；响应字段、分页重试和生命周期；微信原生构建、全套测试、最新六项CI。真实设备验收仍单列。
