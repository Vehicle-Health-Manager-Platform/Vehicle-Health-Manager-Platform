# S0 幂等与成功变更审计

事务服务 `WriteIntegrityService` 复用 V001 的 `idempotency_record` 和 `audit_log`。调用方提供服务端主体、标准化方法/路径、经验证的正文、资源授权锁定回调和业务变更回调。服务拥有独立事务；回调必须使用同一数据源，不能发送短信、支付或进行其他事务外副作用，也不能在外层先持有它将访问的行锁。

先锁定并校验资源，再锁定幂等记录。24 小时内，同主体类型/ID、方法、路径、UUID 键及规范正文摘要返回原成功响应（包括 `request_id`）；同键不同正文返回 40001。对象属性顺序不影响摘要，数组顺序保留。数据库 UTC 时间决定有效期，过期键可以重新执行一次。

业务变更、白名单前后状态审计与响应缓存一起提交。失败全部回滚，失败响应不缓存；客户端可在故障恢复后使用原键重试。成功重放不会重复写审计，且再次验证当前资源权限。调用方负责让响应和审计快照只含允许保存的字段；本示例只保存里程数字和内部 ID。该服务不覆盖认证、微信一次性 code、会话轮换、退出及第三方回调。

## 本地示例

`POST /api/demo/vehicles/{id}/mileage` 仅在 `local` profile 存在，必须配置已初始化的可丢弃测试数据库。接口不会创建或覆盖测试车辆；需自行在测试库准备属于测试车主的 `vehicle` 数据。现有 local-only `/api/dev/token` 可给固定测试车主 1001/2001 签发验证令牌，不能在生产启用该入口。

- 请求头：`Authorization: Bearer <测试访问令牌>`、`Idempotency-Key: <UUID>`。
- 正文：`{"current_mileage":20}`，只接受非负 32 位整数，不允许未知字段，首次执行不可降低已存里程。
- 成功：统一响应，`data` 含车辆 `id` 和 `current_mileage`。重复相同请求保留原 `request_id`，数据库只有一次成功变更审计。
- 失败：400/40001 为无效键、正文、同键冲突或里程降低；401 为未登录；403 为非车主或跨车主访问；404 为车辆不存在；503 为数据库未配置或事务失败。错误不返回数据库细节。

此入口是 S0 技术验证示例，不表示正式车辆录入、里程报工或完整平台审计交付。认证失败、权限拒绝、审核、退款、上下线和改价审计，以及记录清理和审计保留策略，随后续业务接入。

## 验证

`JdbcWriteIntegrityTest` 在 MySQL 8 容器执行真实事务、并发、过期、归属变化和触发器故障回滚检查；容器不可用时该类必须失败，不能跳过。`LocalMileageTest` 等 MockMvc 用例验证请求、角色、无数据库及非 local profile 边界。CI 的后端作业运行这些检查。
