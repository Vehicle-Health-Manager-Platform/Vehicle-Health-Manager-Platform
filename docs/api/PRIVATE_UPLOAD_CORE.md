# S0 私有上传核心

`PrivateUploadService` 是内部应用服务，没有 HTTP 路由、签名 URL 或小程序入口。调用方传入服务端 `FileMetadataRepository.Actor`，主体允许 `user`/`staff_account` 与正数 ID；业务附件授权随后续接口接入，不能由上传主体归属替代车辆/商家关系检查。

## 上传与读取

- `upload(actor, filename, input)`：输入流由调用方管理。最多消费 10 MiB + 1 字节，超限或空文件拒绝；后缀只接受 jpg/jpeg/png/webp，大小写不敏感。拒绝路径分隔符、控制字符和超过 255 字符的名称，不保存原始名称。
- 根据 JPEG/PNG/WebP 标识校验扩展名与 MIME，不信任客户端 Content-Type。只检查格式标识，不进行完整图片解码，不承诺消除多格式文件风险。
- 扫描器必须明确返回 `CLEAN`；病毒、不可用、空结果和异常均阻止存储。传给扫描器的是快照副本，防止扫描器修改待存储字节。
- 存储目标必须通过适配器的私有性检查。对象键由服务生成，成功仅返回 ID、MIME 与实际大小。
- `readable(actor, id)` 为受信任的内部调用返回元数据与对象键；检查主体类型/ID、删除和 `CLEAN` 状态。它不下载文件或产生 URL，禁止直接作为公共 API 响应。

`UploadException` 的原因是 `INVALID_FILE`、`INFECTED`、`NOT_FOUND`、`NOT_READABLE`、`UNAVAILABLE`；错误消息不包含底层异常，跨主体访问与不存在合并为 `NOT_FOUND`，不透露文件归属。未来 HTTP 适配器负责状态码和统一响应映射。

## 接入与事务边界

配置类总是提供应用服务；仅配置 `MYSQL_HOST` 时创建 JDBC 元数据仓储。没有 `VirusScanner`、`PrivateObjectStore` 或仓储时拒绝上传，不自动启用替身。后续新增的[真实 MinIO/ClamAV 适配器](UPLOAD_ADAPTERS.md)通过显式开关和完整私有配置启用；默认不启用，真实部署仍待验收。

扫描器和存储适配器需限制网络等待时间、输出大小，验证私有桶策略，并提供幂等删除。外部操作不进入 JDBC 事务；上传拒绝在调用方已有事务中执行，避免跨系统调用持有外层数据库锁。元数据仓储独立短事务提交后才返回，复用 V001 `file_object`，不新增迁移。

对象保存或数据库提交失败时尝试删除该随机键。删除失败输出结构化 `upload_cleanup_failed` 事件，只含服务生成的对象键，不记录文件、原名称、凭据、签名或原始异常；自定义事件接收器异常时使用默认日志回退。

该补偿没有跨系统原子性：进程在保存对象后退出可能留下孤儿对象；数据库提交的网络结果不明确时，也可能存在元数据与对象不一致。失败前提交测试只证明已知回滚路径。下一步需实施定期清理/状态核对与幂等 HTTP 上传流程，不能把应用失败等同于“数据库确定未提交”。

## 验证与尚未交付范围

`PrivateUploadTest` 使用记录调用与字节的替身验证类型、大小边界、拒绝顺序、缺少服务、扫描修改隔离、存储/仓储/清理事件故障及错误脱敏。`JdbcPrivateUploadTest` 必须在 MySQL 8 Testcontainers 中执行，覆盖实际插入、主体类型/ID 隔离、删除/扫描状态限制、触发器拒绝插入补偿，以及已知提交前故障回滚。无 Docker 时不能静默跳过。

替身测试不能证明 MinIO 私有策略、ClamAV 病毒检测、签名访问或真实网络行为。本步不增加 OpenAPI 操作。HTTP multipart 契约、用户/IP 限流、总请求体限制、上传幂等、对象清理、业务附件关系、完整图片解码及真实服务联调随下一步接入。
