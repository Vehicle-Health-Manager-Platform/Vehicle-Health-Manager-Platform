# 商家账号身份核心（S0-7.1f-2）

商家入口使用已由受信任流程创建的 `staff_account`，`role=MERCHANT`，关联审核通过的 `merchant`，并配置中国大陆手机号及 BCrypt `password_hash`。技师微信身份和车主身份不能通过商家入口取得商家权限。

1. `POST /api/auth/merchant/code`：请求 `{"account":"...","password":"..."}`。验证账号、密码、员工和商家状态后生成六位随机短信码；只存 BCrypt 摘要，五分钟失效。同一账号再次请求使旧码失效。成功仅返回 `sent=true` 和 `expires_in=300`，不返回手机号或验证码。
2. `POST /api/auth/merchant/login`：请求 `{"account":"...","password":"...","sms_code":"123456"}`。再次校验账号、密码和状态，并在数据库事务中消费一次性短信码。成功返回与车主、技师一致的访问和刷新凭证，以及 `user.role=merchant`、主体 ID、商家 ID。
3. 两个入口同时按请求来源 IP 和账号使用共享数据库限流。失败统一返回 401；频繁请求返回 429。访问 JWT 和刷新时重新校验员工、商家状态及商家 ID；退出撤销会话。前端传入的商家 ID 不参与授权。

短信发送通过 `MerchantSmsSender` 接口接入私有服务商。当前尚未确定服务商，因此生产环境没有发送实现；获取验证码返回 503，无法完成真实商家登录。接入服务商时须确保发送异常会使验证码写入事务回滚，不得把验证码、密码或短信凭据写入响应或日志。短信码按员工 ID 隔离，即使两个员工共用手机号也不能互用。

现有 `sms_code`、`staff_account` 和 `auth_session` 表已满足此阶段结构；无新数据库迁移。已有数据库仍须先应用 V002、V003。商家账号的可信创建、密码重置、短信服务商配置和真机联调仍需后续交付。
