# R3a1 微信录车与本人车牌匹配

POST /api/vehicle/match-plate，application/json，Bearer有效user/OWNER会话。正文仅 `{"plate_no":" 粤b12345 "}`，首尾空格/大写规范化，复用既有普通/新能源大陆形状校验，最长32；拒绝未知/重复字段/尾随JSON/空值，拒绝全部query。只读无需幂等键，不把标识写URL。

成功data只有matches（0–20项）；每项vehicle_id、model_id（旧车无车型可0）、model_name、current_mileage、plate_no_masked、vin_masked。只匹配当前车主未删除记录；同牌其他用户存在与否均不透露，已停用车型的旧车辆仍可显示。超过20条409需核对。查询无数据库写入；Cache-Control:no-store。400输入、401会话、403身份、503缺配置或数据库异常。不能据此证明车辆所有权。

微信新增四入口页：手动、本人车牌匹配、行驶证、VIN。用户确认OCR/VIN来源尚未开通：行驶证不上传证件，提供手填回退；VIN只校验17位再带入手动，不猜车型。所有创建继续POST /api/vehicle/add、add_type=4，用户选择发布车型并确认里程后保存；原幂等/重复/停用目录行为保留。

带入标识存内存，令牌绑定、60秒到期、一次消费，身份变化立即清空；URL和本地缓存不含车牌/VIN。匹配响应严格字段/脱敏/本次车牌绑定，修改输入/切换方式/身份/隐藏丢弃旧响应。用户选择匹配车辆后进入本人档案，不重复创建。

真实OCR/VIN适配及识别效果仍未实现，R3a2继续；本阶段无私有证件上传适配，无新增迁移（仍66表），原生新增页面/真机未验收，正式身份资金R9。仅微信与必要后端，不建设PC。
