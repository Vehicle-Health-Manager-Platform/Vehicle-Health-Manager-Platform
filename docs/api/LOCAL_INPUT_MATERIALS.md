# 本机录音与辅助材料边界（R9-A2a）

> **A2b变更**：此文件保留A2a当时的本机边界；当前共享组件新增音频/PDF单份显式上传，新增2个独立接口和V062。仍不自动附加至AI/档案正文，原图片白名单未放宽。[当前契约](CONTROLLED_INPUT_MATERIALS.md)。

AI与档案录入增加本机辅助材料采集，无新增HTTP接口或数据库迁移。录音管理器、音频播放、图片/PDF选择通过 `api-runtime` 的原生方法调用，不经过云托管请求或任何服务端。

材料最多3份；图片/PDF每份≤10MiB；MP3录音1–60秒、≤3MiB，采样16000Hz、单声道、48000bps。文件大小缺失时读取本机文件信息；PDF只接受正常名称及PDF扩展名，不能把本机检查视作服务器文件安全校验。

候选仅保存内存字段 `id/kind/path/size/label/durationMs`。组件只向父页发材料数量和选择器状态，不发送文件路径、文件名、音频或内容。切号、换车、换档案类型、卸载会使旧回调失效。音频隐藏即停止并丢弃本段；文件选择器返回可在同一上下文恢复候选。

既有 `POST /api/ai/chat` 仍只接收原文本请求，不接收这些附件或音频；附有本机材料时按钮提示“仅发送文字”。既有 `POST /api/archive/add` 仍只保存手填字段和通过原图片流程上传的file_ids；辅助材料不转换为input_type=2，不自动产生档案、OCR结果、健康值或积分。

后续A2b独立定义媒体上传的用途、类型、内容签名、大小/时长、病毒扫描、归属、幂等和访问控制；现有 `FileValidator` 的图片白名单未放宽。后续识别结果必须经用户核对确认后才能进入原业务写入。

本阶段不新增OpenAPI操作或SQL，生成文件保持350操作/130表的原基线。真机录音、文件选择器、识别供应商和实际上传另行验收。
