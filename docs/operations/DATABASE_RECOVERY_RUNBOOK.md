# 数据库备份恢复与升级回退演练

本入口用于合成数据的隔离验收。正式生产备份、PITR、私有文件恢复与发布回退仍需部署环境另行验证。

## 一条命令

在项目根目录运行，要求 Python 3.11+、Docker Engine，以及可用的 `mysql:8.0` 镜像：

```powershell
python scripts/run_database_recovery.py
```

不需要本机安装MySQL、Java或第三方Python库，也不需要任何业务库凭据。脚本没有已有容器、远程数据库或业务库地址选项。仅新建本轮唯一标签的两个MySQL实例，无主机端口映射；每次SQL/转储/恢复/清理都检查完整容器ID、随机本轮标签、角色和名称。

退出码0且本次 `report.json` 中 `passed=true` 才算通过；出现失败时按日志给出的**本次目录**查看，不能拿之前成功目录代替。

输出位于 `.cache/database-recovery-随机编号/`：

- `pre-upgrade.sql`：V001–V061升级前备份。
- `current.sql`：V001–V062当前版完整逻辑备份。
- `report.json`：版本、迁移/转储/实现输入哈希、每表行数与结构/数据摘要、检查结果、耗时、两实例server_uuid和清理结果；不含口令、会话令牌或数据行值。

`.cache` 已被Git忽略。SQL仅含合成数据，但仍只留本机；CI artifact仅上传report.json，14天保留期。报告中的备份哈希可用于核验本机文件，执行恢复时脚本也会先校验哈希。

## 实际验证内容

1. 源实例执行V001–V061（130表），加入合成用户/车辆/中文JSON档案、LOCAL_TEST付款/事件、会话，以及专用触发器、过程和禁用事件。该SQL夹具没有真实身份、资金或扫描效果。
2. 使用mysqldump的single-transaction/routines/triggers/events/hex-blob导出。全部表必须为InnoDB；整个演练不并发写入或执行DDL。
3. V062创建input_material之后主动SIGNAL失败，确认DDL确实已提交；不把SQL ROLLBACK误当成迁移降级。从升级前备份导入**新建数据库**，与130表的升级前结构/数据/对象摘要一致。
4. 重试V062并加入合成辅助材料，导出131表。启动第二台独立MySQL，要求server_uuid不同；恢复至新库后全量比较表结构、全部列数据、触发器/过程/事件定义。
5. 主动修改合成车辆里程并删除合成档案，确认数据摘要变化；将完整备份恢复至新库，对比恢复结果。对该库再次执行V001–V062，检查结构、数据和对象均无非预期变化。
6. 恢复实例验证重复主键拒绝、input_material CHECK拒绝、演练里程触发器拒绝回退、存储过程可调用、事件仍DISABLED。
7. 清理仅停止经过归属检查的本轮容器；`--rm`负责删除其匿名数据卷，脚本再确认容器不存在。不会调用全局prune或删除已有Compose卷。

摘要使用每列HEX编码并区分NULL，将每表行排序后计算SHA256，所以中文、JSON、换行、空串、二进制及重复行不会被简单行数比较掩盖。SHOW CREATE TABLE覆盖索引/检查约束和AUTO_INCREMENT；对象定义比较只标准化本轮库的限定名称，触发器恢复时生成的Created时间戳不参与逻辑定义比较。

## 升级和回退边界

- 本轮边界明确为V061→V062，迁移清单必须恰为62个连续版本；未来增加版本时需先调整演练边界，不能静默只测旧版本。
- MySQL DDL有隐式提交。失败后的安全回退路径是**先保存当前状态，再把升级前备份恢复至另一新库并核验**。本入口不会原地删除新增表，也不自动切换应用连接。
- 备份回退只恢复到备份时点。备份后的新材料/订单等写入不会自动出现在旧备份中；正式回退必须暂停写入、保全后续数据并制定兼容/补偿策略。本合成演练不是零数据损失承诺。
- 本轮是同一Docker主机上的两台独立MySQL实例，验证跨实例逻辑恢复；不证明跨机房容灾、binlog/PITR、每日备份排程/长期留存、对象存储/密钥恢复、MySQL账号授权或旧应用版本兼容性。性能与500并发另在A4c-2。

## CI与失败处理

独立 `database-recovery` job执行同一入口，15分钟超时；`schema-and-ocr`执行隔离/哈希/失败结果测试。它们不代替现有schema-mysql与完整后端回归。

失败报告保留active_step和安全错误描述；不会打印SQL正文、容器口令或转储。失败也会尝试归属检查后的清理；如果cleanup=false，先查看本轮容器状态，确认标签/ID后再处理，不对其他容器执行清理。迁移或摘要比较失败时保留本次失败事实，修复后用全新实例重跑。
