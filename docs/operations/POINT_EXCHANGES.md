# 已核验积分兑换运维

本步为 R8a3b 本地事务/API及收支兼容；车主目录确认和独立兑换恢复已在[R8a3c](OWNER_POINT_EXCHANGES.md)接入。整R8完成后统一上传全部代码/迁移/测试/文档，当前不push/改PR/发布。

## 配置与迁移

- `POINTS_EXCHANGE_ENABLED=false` 默认关闭，兑换开关独立于获分。新兑换仍须服务器同app已核验会话，客户端无法声明。已有成功回执和本人历史在关闭后仍可读取，须当前账号有效。
- 已有卷备份后，按V001–V051后执行 `V052__atomic_point_exchange.sql`；新增一张永久成功兑换事实表，累计111表。已有收入账本原子DDL改为有符号双来源，券发行凭证原子DDL允许POINTS且加唯一兑换引用；迁移可重放，不能编辑旧V042/V050替代升级。
- 不预置价格、余额、兑换或券，不导入旧积分。保留原公共领券一次索引、邀请事件凭证和所有原收入。禁止删兑换事实/扣分流水来“恢复”额度；同模板终身累计限额不能靠换目录清零。

## 失败和恢复

1. 断线/503不能判断成功时，保留原目录ID/修订、UUID和正文，重新登录核对本人成功历史与统一收支流水；同键同正文重试，不换键、目录或价格。正式车主交互在下一步提供。
2. 成功有永久首次结果，通用24小时回执过期或服务重启也不会重复扣分/发券；旧结果中的余额是当次快照，overview才是当前余额。
3. 409须重新读取余额、限额/来源/库存和有效期后，明确确认新操作；404核对真实门店/项目/券及目录；401重新登录。不存在自动补券或异步补扣积分流程。
4. 任一库存事件/审计/序列化或数据库失败必须回滚全部兑换。排查用最小兑换编号和审计，不把内部SQL异常回给用户。检查点为record、负流水、账户余额、POINTS issue、本人券及库存事件是否为同一事务提交。

## 退款与期限

成功不自助返分。金额券支付/佣金沿用R5的正现金实付规则，服务券不创建支付。全额退款仅返原券，POINTS凭证、原发行版本、到期时间保留；到期仍显示过期，余额不回增。目录停用或精选撤回只阻止新兑换，不伪造已发行券的延期。

## 后续门禁

R8a3c接车主实际可兑目录/报价确认/账号隔离原请求恢复和券入口，之后R8b/c及全R8门禁。实际Compose、正式微信/资金、真机/发布不由本次配置解析或合成测试替代。
