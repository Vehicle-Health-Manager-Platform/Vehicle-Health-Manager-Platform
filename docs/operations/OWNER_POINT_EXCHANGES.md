# 车主兑换与原请求恢复

R8a3c接本人页面及目录快照，没有新增迁移；仍为V001–V052、111表。所有R8代码、测试和文档保留本地，整R8完成后统一上传，不在子阶段push/更新PR。

## 使用

1. 现有独立积分运营先按[目录流程](POINT_EXCHANGE_CATALOG.md)配置并发布真实精选服务券/金额券，不使用示例积分价。
2. 车主由“我的积分”进入兑换页，刷新本人已核验余额和目录。历史积分待核对不导入，PENDING任务不能支付；顶部兑换资格独立于获分，默认开关仍关闭。
3. 可兑换条目确认券种、门店/项目、积分、终身累计次数、来源、兑换窗口和原券期限。来源/库存/限额/积分等不满足时展示原因，不提供改价或替代请求。
4. 提交成功后在本人成功记录核对原冻结条款，进入“我的券与有效期”查看实际券及核销入口。金额券仍须现金正实付，服务券独立核销；退款仅返原券、不返积分、不延长原到期时间。

## 断线或设备存储异常

- 网络/503未知：保留原目录ID/修订和UUID，不换键。刷新本人目录和成功记录后“重试原兑换请求”；目录停止、过期或不再显示时也不自动选新目录/新价格。服务端永久回执决定是否已成功。
- 401：重新登录同一车主，先核对服务器再恢复。切号不会清除另一账号的本机请求，也不会显示其迟到响应。
- 存储失败：未保存原请求前阻止网络写。已确认成功但清理失败时仍原键重试，避免重新发券。数据损坏须重新核对服务器并明确清理本机请求，不删除任何服务器兑换事实或撤销已发券。
- 多页：本机已存在不同原请求时禁止覆盖；清理比较读取标记，如另一页修改则重新核对。未决请求处理前不能发起另一笔新兑换。
- 409/404等明确拒绝：重新读来源、积分、库存和成功历史，需再次确认新操作。页面不会自动更换价格或重新发券。

本机存储键为 `autocare:point-exchange:v1:<ownerId>`，与签到 `autocare:point-checkin:v1:<ownerId>` 和运营目录隔离，不保存token/档案。隐藏/卸载页面丢弃内存数据，服务端成功历史为准。静态登录回跳拒绝额外用户参数，服务端始终按JWT和当前会话限定本人。

## 验证边界

读取目录是同一只读事务的状态快照；库存/时间可随后变化，实际提交必须继续通过原子接口的全部复核。正式微信身份、资金、真机/发布仍R9，不由本地合成测试或配置解析替代。
