# 积分任务规则操作（R8a1）

> R8a2已接可信任务/账本及本人页，见[积分操作](POINT_LEDGER.md)。下方保留R8a1配置范围，配置动作本身仍不发积分。

仅本地，整R8完成后才统一上传。协议见[API](../api/POINT_TASK_POLICIES.md)，分步设计见[设计](../progress/R8A1_POINTS_POLICY_DESIGN.md)。

## 数据库与权限

V049在V048后显式迁移；新库Compose已挂载，已有卷先备份再执行迁移，不能靠重新启动自动升级。新增一表point_task_policy，累计105表；can_points默认0，无任务分值/积分发放种子，不改变user.point_balance及point_flow/point_exchange。

离线operator-admin、无HTTP：设置`operator.action=points-permission`、`operator.id`及`OPERATOR_CAN_POINTS=true`或false；只接受显式小写布尔，沿用既有数据库/离线管理启动方法，密码和连接配置通过环境输入。变更、审计和撤销旧会话同事务。创建账号不自动授予积分权限；已有邀请/诊断/券账号不能借权。

## 小程序流程

有权限的运营工作区显示“积分任务规则”；仅积分权限账号登录落点为该页。选择三任务之一，填写真实来源、正整数积分、北京时间生效/截止，保存草稿后确认发布冻结；到期或需要换版先停止原政策。没有规则的任务未知，页面不提供积分获发或兑换按钮。

每次创建/修订/发布/停止均明确确认，本机先保存不可变原正文和键；未知结果只重试原请求。重进页面先服务器核对权限再恢复，按运营账号隔离。存储失败阻止发送；401保留至同账号重新认证，明确失权清理对应范围。数据损坏可先读取服务器并明确核对后只清理本机记录，比较原记录避免误删其他页面新请求。未决请求未确认前不能新建其他正文；本机不存凭据。

配置创建有永久服务器意图，不受通用回执24h到期影响；后续修改/发布/停止仍需期望版本。原键恢复首次草稿结果后重新读当前列表。共享设备操作完成后可清理本机未决恢复记录，但这不会删除服务器政策。

后续R8a2才定义/校验服务器获分证据和记账，R8a3兑换。正式身份/渠道、真机及发布仍R9；配置成功不是正式积分或资金验收。
