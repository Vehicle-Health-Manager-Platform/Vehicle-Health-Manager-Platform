# 门店账号、员工与员工码运维

日期 2026-10-11，对应 R1b（V021）。接口与错误码见[门店员工接口](../api/MERCHANT_STAFF.md)，规格见[门店员工规格](../superpowers/specs/2026-10-11-r1b-staff-store-design.md)。**本单元尚未真实容器联调**，以下步骤中的"已验证"仅指离线测试与 MockMvc/真实 MySQL 用例。

## 开关与灰度顺序

`MERCHANT_STAFF_ENABLED` 默认 `false`。开关关闭时全部门店员工/资料接口（含本店列表与本人资料查询）返回 `50300`，页面提示"功能尚未开启或暂不可用"。

灰度顺序固定为：**先迁移 V021 → 再升级小程序 → 最后显式开启**。反过来做会让已开启的客户端打到还没有列的服务上。V021 只给 `staff_account` 加 `display_name`、`created_by` 两列，带 `information_schema` 守卫可重复执行，累计仍 63 表。

## 账号体系与首次发放

| 身份 | 账号 | 登录方式 |
| --- | --- | --- |
| 店长 `MERCHANT` | `m{merchant_id}`，R1a 入驻开店时创建 | 账号 + 密码 + 短信验证码 |
| 店员 `STAFF` | `s{merchant_id}-{seq}`，店长在小程序内创建 | 账号 + 密码 + 短信验证码（同一入口） |
| 技师 `TECHNICIAN` | `t{merchant_id}-{seq}`，店长在小程序内创建 | 微信绑定一次性员工码 |

账号由系统生成，不接受自由文本；`seq` 在该门店同角色内自 1 递增，生成在商家行锁内并对唯一冲突顺延，并发建号不会串号。

店长账号本身**不能**经这套接口创建、停用或修改——它是入驻审核的结果。R1a 之后的店长账号是 `PENDING_ACTIVATION`，**账号激活与正式短信属 R9**；在此之前店长无法自助登录，联调只能用隔离合成会话。

明文密码只在创建请求里出现一次，响应、审计与幂等记录都不含密码。店长创建后请通过可信渠道当面/单线转达，不要发在群里。

## 员工码：签发、轮换与撤销

- 入口：小程序「本店员工与员工码」页，仅店长可见（能否看到由服务端 `can_edit`/权限判定，前端不自行判断角色）。
- **签发即轮换**：每次点击"签发员工码"都会生成新码并让旧码与已有绑定在库内失效，明文码只在页面上显示这一次。技师绑定成功后该码立即失效，离开页面即不再显示（明文只存在内存，不落盘）。
- **撤销**：清空员工码哈希并撤销该技师全部有效微信绑定。
- 库中只存 `employee_code_hash`（`AuthTokens.sha256`），**明文码不落库、不写审计、不写幂等记录**。这两个接口刻意没有 `Idempotency-Key`：重放返回旧码与"旧码立即失效"直接冲突，一次性密钥进幂等记录就是磁盘上的明文泄露。
- 目标必须是本店 `status='ACTIVE'` 的技师：非技师或跨店返回 `40400`，已停用返回 `40900`，店员调用返回 `40300`。

离线 CLI（`StaffCodeCli`，profile `staff-admin`）保留为运维兜底，语义与锁序不变，仅在受控服务器上使用；日常签发走小程序。

## 停用与启用

停用在单事务内完成，锁序 **商家 → 员工 → 微信绑定**：

1. 复核会话、员工行与门店同时有效；
2. `status='DISABLED'` 且清空员工码哈希；
3. 撤销该员工全部 `auth_session`；
4. 技师另外撤销其全部有效微信绑定。

第 3 步不可省：JWT 校验器每次请求实时复核 `status='ACTIVE'`，旧访问令牌立刻失效；但刷新端点只验会话行，不撤销会话就仍能用 refresh 换出新令牌。两者一起才构成"停用立即生效"。

启用只把状态置回 `ACTIVE`，**不恢复**已撤销的微信绑定——技师必须重新用员工码绑定。停用不影响历史工单、派工与接车单快照。

## 故障处置对照

| 现象 | 先看什么 |
| --- | --- |
| 页面提示"门店员工功能尚未开启或暂不可用" | `MERCHANT_STAFF_ENABLED` 是否为 `true`；开关改动必须重建容器，`docker restart` 不重读环境变量 |
| 店员登录后看不到新增/启停/员工码入口 | 属预期：管理面限店长。列表与门店资料对店员可读 |
| 店员调用管理面得到 `40300` | 属预期，不是故障 |
| 技师提示"账号可能已被店长停用，或微信绑定已被撤销" | 向店长索取新员工码后重新绑定；不要只重试登录 |
| 技师操作返回 `40100` 且重登录无效 | 同上——绑定已被撤销，重登录不会恢复绑定 |
| 员工"不存在或不属于本店"（`40400`） | 目标不属于调用者门店。跨店一律按不存在处理，不泄露其他门店是否存在该员工 |
| 签发员工码返回 `40900` | 员工已停用，或本店该角色账号序号用尽 |
| 写请求返回 `50300` | 用**原幂等键与原载荷**重试；换键会产生重复写入 |
