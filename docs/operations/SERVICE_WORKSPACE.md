# R7b 使用与运维

## 使用

1. 门店/技师首页进入“当前任务工作台”，按真实分类数量选择任务，进入既有订单详情办理。来源需核对时先检查派工/确认数据；工作台本身不改变订单状态。
2. 车主在本人订单详情进入“历史档案授权”，先核对记录和图片，再逐条授权。仅可选择保养/维修/故障；证件、保险、违章不在共享范围。正文/照片可能含车主自行录入的信息，确认前应检查。
3. 门店在有效服务阶段订单详情进入“本单必要资料与已授权档案”；技师须已接受本单。未授权仅车型、本单项目和接车里程。
4. 修改已授权记录后显示“来源失效/需重新确认”，车主重新确认本版本。撤销后拒绝新读取；已发图片链接最多300秒到期。
5. 网络失败显示原操作重试时使用该按钮；版本冲突则刷新重新确认。当前R7b未决操作保留同账号同订单页面隐藏期间的内存，关闭页面后重新读取实际授权状态，不假称已持久化重试。

## 运维

- 按序执行V044；Compose已挂载。无默认授权/回填，数据库总96表；唯一键uk_order_archive_grant防重复。回滚应用前先停入口，保留授权及审计事实，不通过删除授权数据撤回审计。
- 撤销/关闭/异议/转派/解绑/账号停用/车辆转移均重新核对，禁止使用车主令牌代门店或技师读取。
- 文件不可用先核对扫描/删除/原上传者，再核对档案关联与源指纹。自动归档需DONE任务和原签字报工来源；不得把历史URL填入新文件来源。
- 503排查数据库、对象存储、审计写入；不要以跳过审计、降低身份校验或延长URL有效期解决失败。
- 站内消息和持久草稿恢复接续R7c；正式微信/短信/资金/真机发布仍R9。整个R7完成前代码、测试、迁移及文档均只保留本地。
