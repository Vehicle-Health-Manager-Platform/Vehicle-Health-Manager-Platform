## 2. 运行只读入口预检

在可访问测试后端的终端，使用 Python 3.11 或更新版本：

```sh
python scripts/check_auth_readiness.py --base-url https://api.example.test
```

将示例域名替换为真实测试域名。地址必须是 HTTPS 原点，可带端口或单个尾随 `/`，不可带路径、查询、片段或用户名密码。脚本只发两次匿名 GET：`/actuator/health` 应为 HTTP 200 且 JSON `status=UP`；`/api/vehicle/list` 应为 HTTP 401 且 JSON `code=40100`。两项通过时退出码 0，检查失败为 1，地址格式错误为 2。重定向、证书/网络/超时错误及非 JSON 都判失败。输出仅含检查项和分类原因。

失败时先核对域名、证书、入口路由、后端健康状态和部署版本；不要通过关闭证书验证或发送真实令牌绕过预检。脚本运行机器通过不代表小程序真机能访问；后续须在真机验证合法域名和网络。

## 4. 真实环境验收

在私有测试环境中用小程序真机完成操作；需要观察 HTTP 状态时使用受控的测试日志或 API 客户端，不将秘密复制到共享记录。每项填“通过 / 失败 / 阻塞 / 未执行”、验证人、日期、环境版本及脱敏证据编号。失败记录阶段、HTTP 状态/业务码和关联的脱敏追踪 ID，不记录请求体和响应体。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| O1 | 新微信测试身份从车主入口 `wx.login` 首次登录 | `POST /api/auth/wx-login` 成功；创建一个车主主体，返回 OWNER 会话，未授权手机号时 `phone_bound=false` |
| O2 | 同一微信身份退出后重新取得**新**登录 code，再从车主入口登录 | 复用同一车主主体，无重复账号；旧一次性 code 不可重放 |
| O3 | 车主点击微信手机号授权按钮，使用其独立 code 调用 `/api/auth/phone/bind` | 获得 `phone_bound=true` 及脱敏号码；非车主会话被拒，号码不以明文进入共享证据 |
| T1 | 未绑定技师从技师入口登录 | 返回 `BIND_REQUIRED` 和短时绑定凭证；该凭证访问业务 GET 被拒绝 |
| T2 | 用有效且未占用的员工码调用 `/api/auth/technician/bind`，再用新 code 登录 | 绑定成功并得到 TECHNICIAN 会话；重复登录复用该员工，不新建员工 |
| T3 | 在测试环境禁用员工或商家，或按受信任流程回收员工码，再访问受保护接口 | 旧技师访问被拒；恢复后按业务要求重新绑定，不把旧会话视为有效 |
| S1 | 分别用 OWNER、TECHNICIAN、MERCHANT 会话访问非本角色受保护资源 | 服务端按实际身份拒绝，不能通过修改客户端入口、角色参数或归属 ID 提权 |
| S2 | 使用有效刷新凭证调用 `/api/auth/refresh`，再重放旧刷新凭证 | 首次获得新访问/刷新凭证；旧刷新凭证立即被拒，新的凭证可用 |
| S3 | 调用 `/api/auth/logout` 后用该会话旧访问与刷新凭证访问/刷新 | 旧会话均被拒；重新登录须使用新微信 code 或商家新验证码 |
| M1 | 有效商家账号请求 `/api/auth/merchant/code`，查看测试接收设备 | 验证码送达，仅返回 `sent=true` 与有效期；当前无生产短信发送器时记录“阻塞”，不得使用测试发送器代替 |
| M2 | 用正确密码和短信码调用 `/api/auth/merchant/login`，随后重复使用同一码 | 首次得到 MERCHANT 会话；重复消费失败，码五分钟过期后失败 |
| M3 | 用错误账号/密码/验证码请求商家登录，并在受控测试中触发限流 | 错误身份统一 401；达到限流阈值为 429；不在共享日志中记录凭据或短信码 |

对于 S1，使用该角色确有权限的测试接口与明确的跨角色接口；若某角色业务 API 尚未交付，记录“阻塞”和缺失接口，不把未覆盖项写为通过。O3、M1–M3 受微信主体能力或短信发送器条件约束，条件不具备时保留阻塞。限流验证使用专用测试账号和可恢复环境，避免干扰其他测试人员。
