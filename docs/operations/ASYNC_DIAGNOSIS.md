# R7c2 诊断使用与运维

## 配置与人员

1. 先按序执行V046，后端与客户端同批升级。102表；diagnosis_control唯一结构控制行不是默认受理政策，全部诊断权限默认关闭，无历史回填。
2. 经授权的账号管理员沿既有无HTTP的operator-admin流程，分别以显式环境OPERATOR_CAN_DIAGNOSE_MANAGE=true|false配合`--operator.action=diagnose-manage-permission --operator.id=...`、OPERATOR_CAN_DIAGNOSE=true|false配合`--operator.action=diagnose-permission --operator.id=...`独立授予/撤销；变更与审计/撤销原会话同事务。邀请、目录、券池或审核权限不能代替。管理人员只能配政策/看最小队列/分配；正文处理人必须获派。正式运营短信身份仍依原接入计划R9验收。
3. 在受限运营入口进入“诊断受理配置”，填写面向车主的来源、北京时间有效期和三态，保存草稿后发布。可受理/离线留言均非实时；暂停拒绝新留言。需先有有效处理人员才能发布接收版本；切换已发布模式时停止旧版本、另发新版本。
4. 邀请条件仍由独立can_invite维护。R6资格和受理配置是两项条件；任何一项未知/到期/停止/人数不足均不能提交或追加。

## 车主及处理

- 车主从AI页邀请条件组件进入“人工诊断与本人留言”，选择本人车辆、输入本次问题并确认文字/车型用途，再确认提交。历史档案及图片不会默认发送；请核对主动文字内容。
- 车主在诊断详情查看答复、追加文字或关闭。追加需重验当前资格，跨月/暂停后仍可查看既有本人答复；关闭不可重开。
- 管理人员从“管理分配队列”明确选择当前有效处理人，确认分配/转派；队列无正文。处理人从“分配给我”进入正文，PROCESSING时可答复；REPLIED后等待车主追加或关闭。
- 转派/撤权/停用后原处理人失去读取和回复。待处理状态表示异步安排，不承诺即时响应。

## 恢复与排障

- 版本冲突或来源变化时刷新后重新确认；网络结果未知只重试原请求，按钮会保留不可变正文/键，禁止在未决期间另起变更。创建意图在数据库永久去重，即使通用24小时回执过期也不会因重试创建第二条。
- R7c3第一步已接入文字和关闭请求的本机持久恢复，先保存原请求再发送。重新进入或登录后须服务器权限读取成功，才能恢复原键；不会自动提交。401保留本机未知意图、隐藏内容直至重新认证；403/404清理失权业务。
- 草稿需主动保存，最长七天，恢复后重新勾选用途同意并核对本人车辆；共享设备请用“清除本机草稿”。不自动保存草稿，不持久化令牌或服务器图片。未决请求期间不可覆盖原正文或另建变更，清理设备数据前先核对服务器记录。
- 本机存储失败会阻止新提交；服务器已确认但清理失败时，只能重试原操作完成清理。损坏本机数据拒绝发送，先核对服务器本人记录后在设备清理应用存储；不能通过构造本机内容绕过服务端权限或版本。见[恢复执行与限制](../progress/R7C3_RECOVERY_EXECUTION.md)。
- 排查受理失败依次核对资格政策、北京月份、当前新客状态、受理配置/版本/时窗、处理人员权限及本人车辆归属。不能把缓存的ELIGIBLE或历史奖励回执当当前授权。
- 503检查数据库、迁移/控制行、审计及事件约束；不跳过事件/审计，不修改会话版本绕过冲突。文字存受限消息表，审计和事件仅最小元数据，禁止把正文/证件/对象URL写入普通日志或订单通知。
- 控制锁只在短数据库事务中持有，禁止接外部AI/短信/存储网络调用。管理/处理权限撤销由当前数据库会话复核生效。
