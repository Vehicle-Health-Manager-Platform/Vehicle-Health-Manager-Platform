# 兑换目录配置与恢复

> 当前已补[R8a3b事务与V052](POINT_EXCHANGES.md)；下方为R8a3a配置流程，目录操作本身不扣分发券。

R8a3a 仅本地配置，未开放车主兑换。整个 R8 完成后才统一上传代码/迁移/测试/文档。正式身份、资金和真机仍 R9，原有获分等开关默认关闭。

## 升级

备份后，在 V001–V050 现有库顺序执行 `V051__point_exchange_catalog.sql`，可重放。新增一张 `point_exchange_catalog`，累计 110 张业务表。初始化挂载只用于新卷，不代替已有卷升级。无默认兑换目录/积分价格/限额，不清理历史余额，不发券。降级应用前先停止相关目录并保留表和回执，不能删表来重置限额或恢复意图。

## 配置流程

1. 用现有离线 `points-permission` 授予独立 can_points；券人员先发布真实服务券/金额券并选入精选池，积分人员不获得券管理权限。
2. 运营工作区→积分兑换目录，读取来源及库存、发行/精选池版本；选择真实来源，填写积分价、本人同模板终身限额、依据说明和北京时间窗口。目录时间须在原券有效期内。
3. 保存草稿，确认服务器列表；发布前再次核对来源/版本、价和限额。发布后条款冻结；替换先停止再创建新目录，同模板限额后续按全部成功兑换累计。
4. 来源停用、下架、取消精选或过期时不能新发布；取消精选再选回也必须刷新池版本。已失效来源不妨碍停止目录。列表支持提前配置未来券/零库存券，不能当作成功发券证据。

## 网络与身份

本机原请求用 `autocare:points-exchange-catalog:v1:<operatorId>`，与积分任务、签到隔离。确认后保存原正文和 UUID，断线/503 保留；刷新服务器列表后重试原请求，不生成新键。创建即使越过通用回执期仍返回首次草稿回执。

本机存储失败阻止写入。损坏数据须重新读取服务器并明确清理本机原请求，多页面比较标记防覆盖。切号、隐藏页面和退出丢弃旧页面数据及迟到响应，原请求仍按原账号保存。401 重新登录后先核对，403 不得借券权限绕过。CAS/来源冲突重新读取并重新确认业务内容。
