# R6a 本地邀请验收

## 实际验证口径

使用真实 MySQL 8.0 Testcontainers，合成车主/店员和官方适配结果仅用于隔离测试。HTTP 使用 Spring MockMvc 和显式替身，与真实数据库事务测试分列；不宣称真实微信新客、真机扫码/分享或奖励到账。

阶段共有 **66 个不同后端用例通过**（去掉重跑重复）：最后完整定向65/65，新增会话撤销修复定向33/33（20个邀请真实库、6个登录HTTP、7个原登录），均零失败/错误/跳过。前端 **553/553**，微信/H5 最终构建、原生公共样式、正式包无测试身份桥通过。全 V001–V040 重放及 V040 重复执行 **91 表**通过；三表无生产资格回填/种子，五项唯一索引通过。

## 后端覆盖

- GET 不创建、UUID 同键重放、换键与 24h 过期仍为同一稳定码、审计不写推广码。
- 新 openid 注册与固定归因、已有账号/重复登录/换码不改变来源、无代码/无效代码正常注册但不产生资格。
- UNKNOWN/TEST 无论绑定手机都不升格；客户端证明标志不能到达换码适配器；官方端点与服务端开关共同判断。
- 当前推广者失效/员工转店/门店失效检查，资格拒绝原因独立保存，原始归因不改。
- 已见手机号即使解绑仍不能成为新客；不验证或 app 不符不计数；同手机号/账号并发与唯一约束不重复产生事件。
- 同 openid 并发只有一个不可变来源；同人并发手机绑定只有一次资格审计；注册/资格审计失败全部回滚。
- 资格时间北京时间跨月，按绑定资格发生月；月初进度重新计算、历史保留；多轮 1/3/6/10 节点与剩余目标复算；时钟倒退拒绝并回滚。
- 读写当前会话重验，包括生成码同键回放与手机号外部换码后会话撤销。员工只读本人的冻结门店来源，记录不含用户/手机/openid；跨角色和身份覆盖查询拒绝。
- 严格正文/重复字段/尾随 JSON、空创建正文、UUID、固定每页20/分页上限/no-store；原登录、云托管开关和券库存兼容。

## 前端覆盖

四档循环、UTC/北京时间一致性、严格状态和角色来源、隐私多余字段拒绝、页面分页匹配与 UUID 去重；显式邀请携码和云托管正文、登录首次尝试冻结来源、结果提示协议；未知生成结果同键重试；隐藏/账号切换丢弃迟到响应；读取失败清理旧码/旧进度/旧记录。三条新增页面及原启动入口保持可核对。

## 环境修复

本机 Docker daemon 与 Testcontainers 默认 API 不兼容，采用 `DOCKER_API_VERSION=1.44` 与 `JAVA_TOOL_OPTIONS=-Dapi.version=1.44` 后执行真实库测试。首轮测试 fixture 的 MerchantActor 参数顺序与 merchant.address 必填项已修正，未放宽数据库规则。上述 66 个不同用例为修复后的成功结果，失败/跳过的尝试不计验收。

首轮远程完整 CI 38569849756 的券交易测试在 @BeforeAll 因旧总表数88与实际91不符退出。该类加载全部迁移，断言已同步到当前91表并完整35/35通过；与前述66项共101个不同后端用例通过。四项非后端检查成功，失败运行不算完整验收。未登录“我的”增加公开邀请码落地入口，私有内容仍须登录。最终六项结果在 PR152 正文记录。
