# 真机相机拍照验收清单

更新日期：2026-10-07。适用于车主端「档案拍照录入」：真机拍摄 → 上传 → 归档的完整链路。
相机无法在开发者工具中验收（模拟器没有摄像头），因此本清单必须在真实手机上执行。

## 为什么需要这份清单

拍照链路的代码一直存在（档案页「拍照录入」→ 微信相机 → `/api/file/upload` → 归档），
但从未在真实相机上验收。准备验收时发现它**实际跑不通**：小程序统一传输层改造时，
`runtime` 从 `uni` 换成了只暴露 `{ initCloud, request, login }` 的 `apiRuntime`，
而图片服务调用的 `chooseImage` / `uploadFile` / `previewImage` 没有一并透传。

后果比"报错"更糟：`uploadFile` 的失败被上层 catch 成
**「无法连接图片服务，请检查网络后重试」**，把排查方向直接带偏——看起来像网络问题，
实际是方法不存在。该问题已修复，并补了「用真实装配」的契约测试防止再次发生
（`apps/miniapp/test/api-runtime.test.js`）。

## 本次修复后的取图行为

| 场景 | 行为 |
| --- | --- |
| 真机 · 拍照录入 | 使用 `wx.chooseMedia`，`sourceType: ['camera']`、`camera: 'back'`，直接调起后置相机 |
| 真机 · 手动录入选图 | `sourceType: ['album', 'camera']`，相册与拍摄均可 |
| 旧基础库（不支持 `chooseMedia`） | 自动回退 `wx.chooseImage` |
| 开发者工具 | **没有摄像头**，退回相册选择，并在页面上明确提示，不假装拍到了 |
| 用户取消 | 静默处理，保留原有图片，不报错 |
| 权限被拒 | 单独提示「未获得相机或相册权限」，并给出「去开启相机权限」按钮 |
| 原生未回报 size | 经 `getFileSystemInfo` 补齐，避免被误判成"无法读取图片" |

## 前置条件

1. 后端在本机可达：`http://127.0.0.1:18080/actuator/health` 返回 `UP`，
   容器镜像必须是 `vehicle-auth/backend:ai-chat`（旧标签不含 AI 代码）。
2. 手机与电脑同一张网；若为校园网/公共 WiFi，改用电脑移动热点（客户端隔离常见）。
3. 后端发布到局域网、产物指向局域网地址：

   ```bash
   node scripts/miniapp_lan_helper.cjs --apply --build
   ```

4. 开发者工具导入 `apps/miniapp/dist/build/mp-weixin`，点「预览」，手机扫码。
5. 手机预览后，右上角「…」→「打开调试」（跳过域名校验的官方做法，仅测试号阶段）。

## 验收步骤

| 步骤 | 操作 | 预期结果 | 记录 |
| --- | --- | --- | --- |
| R1 | 手机浏览器打开 `http://<电脑局域网IP>:18080/actuator/health` | 返回 `UP`。**不通过就别继续**，先解决网络 | |
| R2 | 小程序选「车主」并登录 | 真实 `wx.login` 换到 openid，进入车主首页 | |
| R3 | 档案页 → 选择车辆 → 点「拍照录入」 | 页面提示「拍摄至少一张图片，再填写真实的档案内容」，按钮为「拍照并上传」 | |
| R4 | 点「拍照并上传」 | **调起后置相机**（真机专属证据，工具里不可能出现） | |
| R5 | 拍一张照片 | 返回后显示「图片已上传，保存档案后才会归档」，出现「预览」按钮 | |
| R6 | 点「预览」 | 打开刚拍的原图 | |
| R7 | 保存档案前，先删掉已上传图片 | 「保存档案」按钮变为不可点（拍照录入要求至少一张图） | |
| R8 | 重新拍一张并保存 | 保存成功；列表显示该记录来源为「拍照录入」 | |
| R9 | 再次点「拍照并上传」，在相机界面按返回/取消 | 提示已取消，**原有图片保留**，不出现错误 | |
| R10（建议） | 系统设置里关闭本小程序相机权限后重试 | 提示「未获得相机或相册权限」，并出现「去开启相机权限」按钮；点击后进入设置页 | |

R4 通过即证明真实拍照可用；R5–R8 通过即证明拍摄→上传→归档闭环；R9/R10 验证边界。

## 收尾

```bash
node scripts/miniapp_lan_helper.cjs --restore     # 产物切回回环并重新构建
```

容器端口发布按需改回回环（见[真机登录清单](../operations/LAN_DEVICE_LOGIN_RUNBOOK.md)）。

## 边界

- 本清单只覆盖**真实相机拍照**。上传后的安全检查（ClamAV 扫描结果）、签名到期重试等后端行为
  已有独立证据，见[私有图片联调](LOCAL_PRIVATE_IMAGE_ACCEPTANCE.md)。
- 开发者工具下无法验收相机、弱网与真实设备能力，只能验通上传与归档流程。
- 在模拟器里看到「开发者工具没有摄像头，已从相册选择」是**预期提示**，不是故障。
