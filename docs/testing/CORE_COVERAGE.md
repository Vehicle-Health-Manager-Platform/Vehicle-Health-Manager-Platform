# A4a核心业务覆盖率门禁

## 口径与范围

固定清单为 `scripts/core_coverage_scope.json`。六组共33个业务根类及其全部内部类，不按单个方法剔除失败路径；JaCoCo同时输出整个模块报告，但门禁只统计清单中的核心业务。

- 券：库存/发布/领取、交易券抵扣与服务券、幂等、释放/过期恢复及输入。
- 邀请：登记与证据、奖励批次/政策、资格与诊断政策、输入。
- 考核：政策、事实快照、计算、汇总与角色视图。
- 里程/车辆：本人手动车辆登记与校验，以及仅local环境开放的测试里程更新。后者不算生产里程接口已开放，权限边界继续由既有测试验证。
- 订单状态：预约时段/创建/到期、接车、施工、核销、异步归档及对应输入。
- 写入完整性：幂等、鉴权回放、审计与事务回滚。

依据[原文核心业务方法测试项](../reference/DELIVERY_V1.md)，要求**每组及总体LINE与METHOD均≥70%**；使用整数分数比较，不依据四舍五入结果放行。清单可提高阈值，两个阈值均不允许降到70%以下。BRANCH同时披露但不作为本次70%的度量。不宣称整个平台或未纳入的身份、社区、上传、支付供应商、知识检索等模块均达到70%；本阶段也不代表这些外部效果通过。

清单根类缺源文件/未编译进入报告、无可执行行、重复归组、非法/重复计数、缺必跑测试、失败/错误/跳过测试、缺XML均拒绝通过。内部类逐一计入分母，名称相近的未声明类不混入分子。单个低覆盖类保留在报告可见，行/方法门禁阈值为组和总体，并非每个类单独70%。

## 本机复跑

从仓库根目录运行：

```powershell
python -m unittest discover -s scripts -p test_core_coverage.py -v
python scripts/run_core_coverage.py --docker
```

Docker模式使用现有Maven/Java17镜像和缓存卷，Testcontainers创建临时MySQL，运行固定19个核心套件；无生产容器/数据库名称或生产连接参数。当前Windows Docker Desktop使用Java Docker API 1.44和host.docker.internal。其他主机有Maven/Java17及Docker时可不加`--docker`；不支持此宿主配置时先修正测试连接条件，不能跳过数据库测试冒充成功。

运行器首先移除前次这三份结果文件并执行Maven clean verify，防止旧绿色报告残留；不清理用户数据或其他容器。失败仍记录退出码/环境/命令，若存在失败/跳过测试则不放行。源文件在测试期间变化也拒绝结果。完整套件可加`--full`，其真实上传镜像/扫描与网络准备仍需满足既有测试条件。

产物均在忽略的 `backend/target`：

- `site/core-coverage/index.html`：JaCoCo逐行/分支报告。
- `site/core-coverage/jacoco.xml`、`jacoco.csv`：原始机器计数。
- `core-coverage-summary.json`：六组、逐根类、整体、测试数量、阈值与文件摘要。
- `core-coverage-run.json`：本机开始提交、源摘要、精确命令、测试结果、耗时、宿主环境；本机选定套件和CI全量需区分。

只检查已生成的报告：`python scripts/check_core_coverage.py`。该命令不执行测试；前提必须是本次干净运行生成的XML与JUnit，不可拿旧报告替代复验。

## CI

原backend全量步骤改用core-coverage profile、clean verify，再检查门禁；不额外复制一次全量测试。失败时仍上传覆盖率与JUnit证据，artifact名 `core-coverage-and-tests`、保留14天。schema-and-ocr任务先运行门禁自身测试。后端测试、门禁或构建任一失败，都不得将该head记为通过。
