## 实际环境与结果

真实后端镜像 vehicle-auth/backend:r1c-catalog，独立 sidecar vehicle-r1c-catalog-backend，端口只绑定 127.0.0.1:18081。JAR SHA 与本次 Maven package 一致，网络为既有隔离测试网络，MySQL 应用 V022 两次。原 R1b 后端未替换，未操作生产环境。

JWT/会话只在隔离库为合成运营、车主、店长创建；不发送短信，不调用真实微信身份登录，不代表正式身份验收。脚本核对镜像/网络/端口/开关/JAR 后才写入，并拒绝固定测试 ID 碰撞。配置与令牌不输出、不入仓。

最终 **42/42 通过**；复跑通过。运行报告及日志仅在忽略目录 .cache/r1c-catalog-acceptance.json、.cache/r1c-http-acceptance.log，报告不含令牌。

| 验收链路 | 实际结果 |
| --- | --- |
| 未登录、车主、店长维护目录 | 401/403；未知资源及重复参数 400 |
| 新建四类目录 | 默认未发布、revision=1，单层信封 |
| 品牌→车系→车型发布 | 未发布父级阻断子级；整链发布后可录车 |
| 已引用品牌改名 | 409；禁止重写车辆身份 |
| 停用车型 | 既有车辆可回显，新增目录隐藏，新录车 404 |
| 发布标准项目→店长报价→时段→预约 | 真正通过 HTTP 写入报价及订单 |
| 幂等、版本冲突 | 重放内容一致且单层信封；旧 revision 409 |
| 停用标准项目 | 新下单 404，旧订单仍可查且快照不变；允许下架原报价 |
| 权限撤销 | 即时 403，连已缓存的幂等写重放也拒绝 |

首轮失败为脚本按 JSON 序列化字符串比较字段顺序；已改为 JSON 深比较并保证断言失败进程非零退出，复跑全部通过。相关后端测试还覆盖并发、输入白名单、引用保护、事务失败回滚；这些属于真实 MySQL JUnit 证据，未冒充本 HTTP 脚本场景。
