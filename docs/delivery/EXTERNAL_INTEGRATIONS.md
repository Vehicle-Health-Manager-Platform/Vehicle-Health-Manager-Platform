# 外部接入待办及验收标准

本阶段不办理账号、资质、采购、云环境开通或真实资金操作。以下是后续负责人可执行的接入清单；验收结果目前均不能记为真实服务通过。此文件依据当前仓库接口/运维实现整理，供应商控制台规则须办理时核实。

## 微信身份、手机号及云环境

责任角色：小程序主体管理员、云环境管理员、后端负责人。

资料：主体/管理员权限、正确AppID、服务器私有凭据、已获准测试账号、手机号能力权限及额度、所选可信云环境/服务、域名证书或云通道访问配置。

步骤：

1. 按[云部署准备](../../deploy/cloudrun/README.md)创建环境并记录区域、服务和网络。现有Java/MySQL不能直接替换为云开发文档数据库；先完成MySQL迁移和私有附件方案。
2. 在私有配置设置AppID/AppSecret/JWT及数据库参数。云身份启用前关闭公网身份入口，只接受平台注入的可信头；直连方式使用既有微信code交换。
3. 小程序成对配置环境ID和服务名，或配置合法HTTPS API原点；运行[身份预检](../operations/AUTH_INTEGRATION_RUNBOOK.md)。
4. 分别走车主首次/重复登录、手机号授权/拒绝、技师未绑定/合法绑定、刷新/退出与停用。商家/运营继续走自己的二次验证，不能借云车主身份绕过。

验收：真实获准账号在iOS/Android完成；code重放、绑定凭证访问业务、伪造可信头、过期/撤销令牌、停用员工、跨用户/店/技师均拒绝；刷新凭证轮换一次有效。记录版本、状态、脱敏请求ID，不公开openid/手机号/凭证。

## 短信与商家激活

责任角色：运营主体、短信服务管理员、后端身份负责人。

资料：服务商账号、签名/模板审批、用途说明、限额与费用预算、私有访问凭据、受控测试接收号码及商家资料。

步骤：实现现有 `MerchantSmsSender`、`OperatorSmsSender` 的真实适配并配置到所选环境；完善待激活账号的初始凭据设置/交付和身份核实流程；接入商家/运营各自的验证码请求与核验；配置频率、有效期、尝试次数、发送失败处理和告警。当前 `SMS_PROVIDER` 模板占位本身不会发送短信。

验收：真实发送/失败回执可核查；正确验证码一次性生效，错误/过期/重复/超次数/跨账号拒绝；发送失败不激活账号、不签发登录会话；旧密码或明文验证码不进入日志/数据库。审批开店不等于激活完成，待激活账号必须保持拒绝。

## 微信支付、退款与渠道账单

责任角色：商户财务、微信支付管理员、后端资金负责人。

资料：小程序与商户关联、API证书/密钥与轮换记录、验签材料、回调域名、获准测试资金账户、退款权限和账单样本。

步骤：实现当前WECHAT渠道拒绝式占位的创建/查询/退款和回调；复用已有金额快照、幂等事务、异常事件与恢复任务；校验签名、时间窗、事件去重和金额/币种/商户匹配；接入真实账单、差额/手续费/结算规则。不得把LOCAL_TEST回调路径当正式回调。

验收：正常/重复/乱序/延迟/坏签名/金额不符/查询超时恢复均有证据；同一业务不重复扣款、退款、返券或冲销佣金；渠道和数据库事实一致。真实交易必须另行授权。现有本地资金记录和3%佣金不等于实际结算对账。

## 车型、行驶证、语音、图文及AI资料

责任角色：产品/数据授权负责人、算法与后端负责人。

资料：合法车型/VIN/车牌数据来源、获授权行驶证/仪表样本、ASR/文档提取能力、语料使用许可、模型凭据与评估集。

步骤：先定义图片/材料归属、订单或车辆用途和明确同意；接行驶证识别、VIN解码与新车牌车型来源；接车OCR本轮已完成接线，后续补真实模型/授权仪表/手机验收；语音/照片/PDF提取仅生成候选，本人确认后原保存；知识向量检索须记录来源、版本、许可和撤回。

验收：成功、无匹配、低置信、多候选、超时/取消/迟到、跨归属均覆盖；无同意不调用，识别不自动落库。KEYWORD检索不得标为向量；上传回执或手工填表不得标为机器理解。独立开发缺口不能仅因等待资质就从清单删除。

## 微信通知、邀请与原生分享

资料：获准订阅模板、用户同意、官方码权限、真实新客与分享测试账号。

步骤：把既有站内/outbox事件接到微信订阅消息，实现官方小程序码/原生分享与来源归因；保留同意、拒绝、失败和重试状态。

验收：站内生成、供应商受理和实际送达分别记录；重复事件不重复奖励，拒绝订阅仍可完成核心业务；不得把本地海报或站内通知当成官方消息成功。

## 发布与移交

正式负责人完成HTTPS/合法域名、云服务及MySQL/存储权限、生产扫描/OCR、监控告警、备份恢复、性能和iOS/Android验收后，按[交接入口](LOCAL_HANDOVER.md)的部署顺序发布。每个待办交付负责人、环境版本、完成日期、脱敏证据和回滚方式；没有证据保持“待验”。

## VIN来源补充（R2a）
VIN车主网关及候选页面已接通，仍需获授权VIN/实车对照、来源条款与数据传输用途确认、HTTPS出口和覆盖/错误预算；NHTSA以美国市场登记为主，不能替代国内精确车型来源。真实接入步骤/验收见[接口与接入](../api/VIN_OWNER_GATEWAY.md)。合成HTTP测试不等于真实供应商验收。

## 行驶证识别正式验收（R2b）

软件新增本地受限OCR车牌/VIN场景、当前OWNER新车网关和人工确认入口，默认关闭。负责人需准备授权证件/实车字段对照、用途同意、私有存储/扫描、图片保留及本人删除政策、固定模型/依赖摘要。按清晰/模糊/部分/多值/无值/旋转/超限/失败与人工修正、跨账号/撤销/扫描变化/取消迟到验证，再核对手动车型保存和无证件自动关联；替身、合成图、真实证件和手机证据分开。具体[配置/步骤/验收标准](../api/LICENSE_RECOGNITION.md)。

## ASR资源与正式验收（R3）

负责人准备经许可的多语small模型精确revision/来源/全文件SHA-256、完整transitive离线wheel/hash锁、Linux受限镜像、私有服务网络/token及获授权声音样本。现有requirements.in仅直接依赖faster-whisper1.2.1，不代表资源已经安装或验收。按[离线资源步骤](../../services/asr/README.md)核验，再按[任务接口](../api/ASR_JOBS.md)验收本人/跨用途、撤销/转移、取消/未知创建、TTL/旧租约、静音/噪声/方言/时长边界、人工修正与原表单保存。真实效果、模型进程安全与手机分别记录，不用替身返回source标签冒充真实模型。
