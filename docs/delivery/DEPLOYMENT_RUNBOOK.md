按顺序执行缺少的迁移，每步保存版本、校验值、退出码及结构核对结果。不要根据134张表的数量直接推断所有约束已正确；核对V065索引任务/块外键与现行识别任务字段。旧数据不得被自动补成已授权嵌入资料。

MySQL DDL可能已在失败前提交，SQL ROLLBACK不能保证降级。按[恢复手册](../operations/DATABASE_RECOVERY_RUNBOOK.md)先保全失败状态，再恢复到另一个新库并比较完整结构/数据/对象摘要，核实后再切换连接。不能覆盖失败库或丢弃备份后的业务写入。

## 启动与上线验收

本地Compose的配置静态检查可用下列命令；静态检查不启动服务或证明凭据有效：

```powershell
docker compose --env-file .env -f deploy/compose/compose.yml config --quiet
```

目标环境按数据库→私有依赖→后端→访问入口→小程序的顺序启动。检查健康、数据库连接、UTC持久时间和显式北京时间业务日；暴露给终端的地址/证书需从实际设备验证。监控端口及 `/actuator/prometheus` 只向受控监控网络开放，不作为公共业务入口。

上线前分别记录：

- 匿名业务401、过期/撤销会话拒绝、跨用户/门店/技师拒绝、运营细分权限，以及错误请求的安全响应。
- 三角色录车/预约/接车/施工/签字/核销/归档/评价和取消/退款异常路径；正式渠道需本次真实或获准测试回执，不能导入LOCAL_TEST记录冒充。
- 真实私有上传、扫描、签名读取、超限/非法文件拒绝、扫描不可用和对象丢失处理；候选取消/TTL与原文件删除分别验证。

微信/短信/支付/订阅所需资料、步骤及验收在[外部接入](EXTERNAL_INTEGRATIONS.md)。未满足条件的能力保持关闭并记录责任人，不能用环境变量占位表示服务已开通。

## 观察、告警与回退

当前基础采集配置在 `deploy/monitoring/prometheus.yml`。目标环境需实际核验采集UP、健康、5xx、延迟、连接池、扫描不可用、模型/索引失败及积压、备份失败、磁盘和容器重启；由部署负责人配置接收渠道、阈值、值班人和演练记录。配置文件存在或本地服务健康不等于生产告警已投递。

出现异常先暂停受影响写入/调度，保存请求ID、原幂等键、版本与安全状态，关闭相关功能开关；不要公开正文、令牌或模型诊断。资金状态未知时先查询渠道和数据库事实，不重新造一笔请求。

应用回退前核实旧版对现行schema的兼容性。数据库若需回退，使用已核验的新库恢复和受控连接切换，保全升级后数据并制定补偿；不能直接反向删除新表。向量跨profile清理需先停止所有索引实例再按维护指南执行。回退后重验健康、鉴权、只读事实、关键写入和后台任务，记录最终版本及遗留问题。

本轮只证明报告内的本地恢复检查；生产PITR、跨机房容灾、长期稳定性、对象存储与密钥恢复及真实告警送达保持待验。交接时填写环境版本、执行人、日期、脱敏证据和回退结果，再办理提审发布。
