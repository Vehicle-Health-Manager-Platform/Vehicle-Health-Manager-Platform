## 2026-10-02：单测试号三角色工程与团队边界

用户确认测试阶段在一个微信小程序测试号内预览车主、商家和技师三种角色。本仓库新增一个 uni-app 小程序工程，角色页面和后续业务模块分开；测试入口仅用于预览，业务身份由服务端校验。原始交付文档的正式三端目标暂不改动；正式 AppID 的数量、主体与发布权限仍待确认。PC 运营后台交由其他团队负责，本团队维护小程序及其共用 API/数据契约，不新增 PC 后台业务页面。具体边界见[单测试号设计](superpowers/specs/2026-10-02-single-test-miniapp-design.md)。

单一 `user.openid` 仅维持当前原文与测试号基线；正式拆成多个 AppID 前须新增 `(app_id, openid)` 身份映射，并通过已验证的绑定流程关联平台用户。AppSecret 仅服务端持有，不进入仓库与客户端。

## 2026-10-02：恢复原始交付文档的终端方案

用户决定重新按提供的原始 v1.0 交付文档开发；仓库根目录的交付文档已按该文件原样恢复。车主端为微信小程序主端、H5 兜底，商家端和技师端为微信小程序，运营后台为 PC 网页。车主以微信 code 换 openid 并绑定手机号，技师以微信授权登录并首次绑定商家工号；来源核心接口恢复为 `POST /api/auth/wx-login`。原始 `user.openid` 与可空 `phone` 重新成为数据基线。支付、测试、构建、审核发布和外部资源清单均以原始文档的小程序要求为准。

下方 2026-09-29 的四端网页决定已被本决定取代。此前交付的 Vue3/Vite 车主、商家、技师网页仅是过渡期原型及 CI 验证资产，**不能计为小程序工程、微信登录、H5 兜底或 M0 终端验收通过**。运营 PC 网页、Java 后端、数据库与基础设施可在核对后沿用；小程序工程、真实微信接口和相关验收尚待实施。

## 2026-09-29：四端改为网页（历史记录，已被 2026-10-02 决定取代）

用户明确要求车主、商家、技师和运营四端均以网页交付，并同步修改文档中的小程序要求。S0 按 Vue3 + Vite 构建四端响应式网页；车主、商家、技师优先适配手机浏览器，运营端优先适配桌面浏览器。网页登录改为手机号验证码（运营端保留账号密码与二次校验）；原 `/api/auth/wx-login` 改为 `/api/auth/login`。支付渠道须选择支持浏览器网页的方案，具体服务商与回调契约仍待 S0 确认。原文中扫码进入订单可由浏览器打开二维码链接实现。此变更影响 F01、C01、认证接口、用户表、前端构建、兼容性测试和发布流程。
